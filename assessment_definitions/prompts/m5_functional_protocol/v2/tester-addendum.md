Верни один JSON-объект с двумя верхнеуровневыми полями: candidate_checksum и checks. Значение candidate_checksum должно точно совпадать с одноимённым полем входа; оно обозначает candidate_as, который ты проверял. Следуй applicability_plan, используй точные check_id каждого required_checks ровно один раз. Не добавляй проверки и не вычисляй общий статус. Для каждой защищённой проверки сначала найди в candidate_as пути, которые могут противоречить requirement. PASS допустим только после явного разрешения каждого такого конфликта в adversarial_review. Не считай разные названия разными функциями без различия содержания; не превращай готовое утверждение в полезную гипотезу только потому, что участник мог бы его оспорить; атрибуция готовой классификации журналу, документу или автору не делает её неопределённой, если материал сообщает её как факт; не игнорируй преждевременно подтверждённое внешнее условие из-за наличия другого ограничения.
