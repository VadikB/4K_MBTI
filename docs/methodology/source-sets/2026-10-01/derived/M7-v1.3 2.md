M7.1 Назначение и структура Assessment Cycle

M7.1.1 Назначение и единицы организации

M7 определяет организацию одного среза оценки человека: цель и план, принадлежность сессий, подбор Cases, покрытие конструкта, время, допустимые уточнения и условия завершения.

Assessment Cycle — один срез оценки одного человека, включающий одну или несколько Assessment Sessions. Целевой состав, совокупное покрытие и итоговая достаточность определяются для Cycle. Закрытие Cycle завершает сбор ответов для этого среза, но не означает полноты результата.

Assessment Session — отдельный организованный эпизод прохождения одной или нескольких Assessment Situations внутри конкретного Cycle. Session сохраняет собственные начало и завершение, маршрут, время и обстоятельства прохождения.

Assessment Situation (AS) — персонализированная реализация одного Case. Dialogue фиксирует взаимодействие в её пределах. Evidence Bundle (EB) и итоговый Indicator Assessment (IA) относятся к одному IndicatorID в одной AS; Cycle не создаёт общей ситуации или общего Dialogue.

В методологии 1.1 штатно завершённая Session закрывает Cycle сразу, в том числе при неполном покрытии. Дополнительная Session допускается только для продолжения незавершённого прохождения в ещё открытом Cycle по M7.8. Учитываемый бюджет прохождения и предельная календарная длительность сбора задаются параметрами плана по M7.2 и M7.5. Их значения по умолчанию — 60 минут для экспресс-оценки и 72 часа для окна Cycle.

M7.1.2 Границы ответственности

Блок | Содержание и связь с M7
M1 | Закрепляет понятия и связи Cycle, Session, Assessment Situation и результатов.
M2 | Определяет Skills, Components, Indicators и дескрипторы L0–L3. M7 использует их для целевого состава и покрытия.
M3 и M4 | Определяют RoleProfile и зафиксированный PersonalizedProfile для всего Cycle.
M5 | Определяет Cases, ролевые реализации, сценарии Dialogue и Indicator Observability конкретных Assessment Situations.
M6 | Формирует Evidence и Indicator Assessments, проверяет их основания и сопоставимость, агрегирует допустимые оценки внутри Cycle.
M7 | Задаёт Cycle и состав его Sessions, планирует получение наблюдений, проверяет покрытие, управляет временем, продолжением и закрытием.
M8 | Формирует представление Results одного закрытого Cycle; определяет допустимое сопоставление отдельных Cycles и динамику.



M7 использует выводы M6 о достаточности и допустимости оценок для проверки плана Cycle. M7 не меняет Indicators и дескрипторы, не присваивает уровни вместо M6 и не восполняет отсутствующие Evidence.

M7.1.3 Входные основания

Для Cycle фиксируются человек, цель, целевой состав конструкта, PersonalizedProfile с RoleProfile, версии методических оснований, требования к наблюдениям, два параметра времени с источниками их значений и условия завершения. Используются допустимый пул Cases, сведения об их применимости, времени и ограничениях повторного использования.

Для каждой Session до её начала определяются принадлежность к Cycle, назначение и маршрут. При подготовке Assessment Situations проверяется Indicator Observability; при адаптации используются выводы M6 о полученном материале и ограничениях.

M7.1.4 Содержание и результат Cycle

С Cycle связываются исходный план, фиксированный контекст и версии, все входящие Sessions, их последовательность и основания назначения, совокупное покрытие, учитываемое время, календарное окно, причина и момент закрытия.

Для каждой Session сохраняются предъявленные Assessment Situations, Dialogue, изменения маршрута, время и обстоятельства завершения. Происхождение материала восстанавливается от Cycle через Session и Assessment Situation к Indicator Assessment и его Evidence Bundle. Связи с Evidence и исходными Turns сохраняются, когда такой материал фактически существует; пустой Evidence Bundle не заполняется вымышленными основаниями.

По закрытому Cycle M6 формирует Skill Results с полным или частным SkillScore, отдельными обоснованными результатами без допустимого SkillScore либо фиксирует отсутствие Skill Result по M6.7.4. Для каждого исхода сохраняются покрытие и ограничения. M8 связывает с Cycle один Results и представление фактически полученного профиля. Несколько Sessions одного Cycle не создают самостоятельных итоговых профилей для последующего усреднения. Разные Cycles имеют отдельные Results.

M7.1.5 Общие принципы

Целевой состав и требования к наблюдениям задаются до прохождения и сохраняются для всего Cycle. Ответы не служат основанием для последующего сокращения плана или перегруппировки Sessions.

Все Sessions одного Cycle относятся к одному человеку, одному фиксированному PersonalizedProfile, одной оценочной задаче и целевому составу. Применяются одинаковые либо явно обоснованно совместимые версии конструкта и правил оценивания. Изменения источников контекста не меняют использованный профиль автоматически.

Совпадения человека, Skills или близости дат недостаточно для объединения Sessions. Принадлежность к Cycle устанавливается при назначении каждой Session, до получения её ответов. Уже закрытый Cycle не открывается для дополнительного сбора.

Плановое покрытие, фактическая возможность наблюдения и достаточность Evidence различаются. Принадлежность к одному Cycle не гарантирует сопоставимости всех Indicator Assessments: её отдельно проверяет M6.7.

M7.2 Цель и план оценки

M7.2.1 Цель Cycle

До начала Cycle определяется требуемая область оценки: все четыре компетенции, одна компетенция либо выбранные Skills. Повторная оценка состояния человека представляет собой самостоятельную задачу и новый Cycle, в том числе после программы развития.

Цель определяет организацию среза, но не предопределяет уровни пользователя и не изменяет правила M6. Дополнительная Session внутри открытого Cycle продолжает первоначальную незавершённую оценку и не получает отдельной самостоятельной цели.

M7.2.2 Целевой состав

Целевой состав раскрывается последовательно: Skills → Components → Indicators применяемой версии M2. Для каждого целевого Skill сохраняются полный обязательный состав M2 и состав плана Cycle, необходимые для проверки полноты по M6.7.3–M6.7.4.

Сокращённый состав внутри Component или Skill допускается при предварительном методологическом обосновании и явном ограничении результата. Полнота такого плана отличается от полноты конструкта M2. Выполнение сокращённого плана не превращает частный ComponentScore или SkillScore в полный. Настройки времени не уменьшают обязательный состав задним числом.

M7.2.3 Контекст и методические основания

План Cycle связывается с человеком, зафиксированным PersonalizedProfile, содержащимся в нём RoleProfile и версиями применяемых методических оснований. Условия использования контекста определяются M4. По M4.4 профиль фиксируется до первого использования при подборе или формировании кейсов конкретной оценки, даже если ответы ещё не начались.

Сведения PersonalizedProfile служат подготовке и пониманию условий AS. Опыт, должность и заявления в UserContext сами по себе не являются Evidence уровня. Наличие материала в профиле или в полном Case не означает его предъявления пользователю. Фактически доступные сведения и момент их появления восстанавливаются по AS, материалам и Turns Dialogue; непредъявленные материалы и невозникшие ветви не считаются доступными в соответствующий момент — M6.2.2.

Обновление исходных сведений после фиксации не переписывает использованный PersonalizedProfile автоматически, в том числе до первого ответа. ФИО и контакты не передаются для формирования кейсов и содержательного оценивания; связь с человеком сохраняется отдельно. Применяются правила M4.3–M4.6 без введения нового snapshot или обязательных полей UserContext. Границы уточнения контекста и оценочного уточнения установлены в M7.6.1 и показаны на схеме Б.6.

При дополнительной Session используются тот же профиль, целевой состав и совместимые методические основания. Любые известные изменения условий между Sessions фиксируются и передаются M6 для проверки допустимости оценок. Сам факт изменения не служит основанием для перегруппировки уже проведённых Sessions.

Для повторной оценки формируется план нового Cycle; связь с предыдущим срезом и предполагаемое сопоставление указываются отдельно по M7.8.

Значения параметров времени определяются отдельно по следующему порядку: методическое значение по умолчанию → значение организации → переопределение для конкретной программы или запуска оценки. При отсутствии переопределения используется значение предыдущего уровня. Настройки организации и программы могут задавать оба параметра; само наличие программы не вводит новую сущность методологии.

Административные настройки организации задают значения по умолчанию для её оценок. Настройки конкретной программы или запуска позволяют выбрать другие значения до начала прохождения. M7 определяет смысл параметров и правила их применения; интерфейс и полномочия изменения относятся к продуктовой реализации.

До старта первой Session в плане Cycle фиксируются оба эффективных значения, единицы измерения и источник каждого значения: методический сценарий, настройки организации либо конкретная программа или запуск с их идентификатором и версией или датой фиксации. Изменения плана до старта сохраняются в истории. Начавшийся Cycle использует зафиксированные значения; последующее изменение настроек не меняет его бюджет и крайний срок.

Дополнительную Session назначают только после установления незавершённости прохождения. Её принадлежность фиксируется до начала; она использует остаток бюджета и тот же крайний срок Cycle.

M7.2.5 Сохранение исходного плана

При прохождении сохраняются исходный целевой состав, требования и зафиксированные параметры времени. Изменение предстоящего маршрута допускается по M7.6 с указанием основания; полученные наблюдения и оценки сохраняются.

Невыполненные цели отражаются в фактическом покрытии и ограничениях. Они не удаляются из исходного плана после получения ответов.

Полное покрытие за 60 минут в базовой экспресс-оценке является проектным требованием, достижимость которого проверяется в M7.9. Другие настройки времени не подтверждают покрытие и пригодность маршрута автоматически.

M7.3 Покрытие и достаточность наблюдений

M7.3.1 Целевое покрытие

Покрытие определяется для всего Cycle по структуре Skills → Components → Indicators. Для базовой экспресс-оценки обязательны все Skills четырёх компетенций и полный обязательный состав входящих в них Components и Indicators по M2 и M6.

Для оценки одной компетенции или выбранных Skills используется соответствующая часть конструкта. Полный результат по Skill требует выполнения требований по его обязательному составу.

Покрытие Cycle учитывает допустимые наблюдения из всех его Sessions. Повторное наблюдение одного IndicatorID может дополнять основания и выполнять требование повторности, но не считается покрытием нового целевого Indicator. Доли покрытия отдельных Sessions не суммируются.

M7.3.2 Плановые и фактические основания

Предусмотренная возможность наблюдения, фактически возникшие условия, обоснованный Indicator Assessment и допуск его сводного вклада к расчёту различаются. M6 проверяет основания и допустимость; M7 сверяет полученные сведения с исходным планом Cycle.

Наличие Indicator Observability до прохождения не гарантирует получения Evidence. Если условная ветвь не возникла, включение ситуации в маршрут не закрывает соответствующую цель. M6 определяет L0–L3, INSUFFICIENT_EVIDENCE либо обоснованное отсутствие IA по M6.6.3. Пока AS открыта, доступен промежуточный разбор, а итогового IA ещё нет.

По M6.7.4 покрытие сохраняется в следующих разрезах:

Счётчик | Числитель | Знаменатель
Фактическая возможность | Уникальные IndicatorIDs, для которых возможность возникла хотя бы в одной AS. | Обязательные IndicatorIDs выбранного состава.
Обоснованные IA | Уникальные IndicatorIDs с хотя бы одним обоснованным итоговым IA L0–L3. | Тот же обязательный состав Indicators.
Допустимые вклады | Уникальные IndicatorIDs с допустимым сводным вкладом после проверок M6.7.1–M6.7.2. | Тот же обязательный состав Indicators.
Components со Score | Components с рассчитанным полным или частным ComponentScore. | Обязательные Components данного Skill.
Полные Components | Components с полным ComponentScore. | Тот же обязательный состав Components.



Для каждого счётчика фиксируются числитель, знаменатель, включённые и отсутствующие IDs и версия состава. На уровне Skill сохраняются покрытие Indicators и покрытие Components. При различии плана и полного состава M2 показатели рассчитываются и показываются отдельно для каждого состава. Для состава, в котором элемент не предусмотрен, он не считается пропуском плана, но остаётся видимым в покрытии полного конструкта. Пустой знаменатель не преобразуется в 100 процентов покрытия.

Повторы одного IndicatorID не увеличивают числители; доли Sessions не суммируются. После исключения IA или сводного вклада M6 пересматривает затронутые расчёты и покрытие, M7 повторно проверяет требования плана. Удаление вклада из среднего не удаляет Indicator из обязательного состава и знаменателя покрытия. Наличие IA и допустимость общего вклада не подменяют друг друга.

M7.3.3 Единица наблюдения для плана

Единица Indicator Assessment — один IndicatorID в одной Assessment Situation. Несколько Turns и уточняющих ответов в её Dialogue могут дополнять один Evidence Bundle и одно итоговое оценочное основание.

Количество сообщений, Fragments или промежуточных выводов не подменяет количество оценок в разных Assessment Situations. Повторная обработка того же Dialogue не создаёт нового наблюдения.

Одна ситуация может поддерживать несколько целей, если для каждого IndicatorID имеются самостоятельные содержательные основания.

M7.3.4 Минимум для полного результата экспресс оценки

Для полного результата базовой экспресс-оценки требуется как минимум один обоснованный итоговый IA L0–L3 по каждому обязательному IndicatorID внутри Cycle. Это необходимое условие полноты, а не запрет на получение частного результата при пробелах.

Наличие одного IA ещё не подтверждает достаточность сводного вклада. M6.7.1–M6.7.2 проверяют всю совокупность оснований, сопоставимость, противоречия и требования плана к числу и условиям наблюдений. Универсальное требование двух Assessment Situations на каждый Indicator не устанавливается. Если план требует повторности, одного наблюдения для соответствующего вклада недостаточно.

INSUFFICIENT_EVIDENCE и отсутствие IA не заменяют обоснованную уровневую оценку. При реальной возможности действовать обоснованный L0 является полноценным результатом и сам по себе не требует дополнительной попытки. Частный Score допускается только по тем вкладам, для которых выполнены требования M6; сам по себе низкий процент покрытия не вводит нового числового порога допустимости.

Дополнение материала по M7.6 возможно до завершения прохождения и в оставшемся бюджете. Невыполнение минимума после штатно завершённой Session ограничивает результат закрытого Cycle; отдельная Session только ради устранения этого пробела в методологии 1.1 не назначается.

M7.3.5 Совокупность оценок и порядок агрегации

В каждой завершённой Assessment Situation M6 формирует итоговые IA по всему EB. Допустимые итоговые оценки всех Sessions одного Cycle группируются по IndicatorID. M6.7.1–M6.7.2 проверяют обоснованность, сопоставимость, достаточность и различия; по допущенным IA формируется один сводный вклад Indicator.

По M6.7.3 ComponentScore рассчитывается как среднее доступных допустимых сводных вкладов обязательных Indicators, а SkillScore — как среднее доступных полных или частных ComponentScores обязательных Components. Каждый включённый Indicator имеет равный вес внутри Component, каждый включённый Component — равный вес внутри Skill. Отсутствие всех допустимых вкладов означает отсутствие соответствующего Score. M7 использует расчёт M6 и не вводит собственную формулу.

ComponentScore полный, когда включены все обязательные вклады M2 и выполнены требования к ним; иначе допустимый Score частный. SkillScore полный, только если все обязательные Components имеют полный ComponentScore и выполнены требования M7 к результату Cycle. Частный ComponentScore или отсутствующий обязательный Component сохраняют частный характер SkillScore. Выполнение сокращённого плана не меняет эту квалификацию.

INSUFFICIENT_EVIDENCE, отсутствующие и недопущенные вклады исключаются из числового знаменателя, но остаются в покрытии. Обоснованный L0 включается как 0. Покрытие и Confidence не умножаются на Score. Число AS одного Indicator не увеличивает его вес; готовые результаты Sessions не усредняются, все Indicators Skill не сводятся в одно плоское среднее.

EB разных Assessment Situations не объединяются. Общий итоговый IA на Cycle не создаётся. Промежуточные разборы и повторная обработка того же Dialogue не увеличивают число наблюдений. Все исходные IA, допуск, исключения, причины, число AS и разброс сохраняются. Различие обоснованных сопоставимых IA может быть вариативностью по M6.8.2; оно не требует автоматического исключения или дополнительной попытки.

Принадлежность к одному Cycle сама по себе не делает оценку допустимой для совместного расчёта. Закрытые Cycles не объединяются для увеличения покрытия или получения общего Skill Result.

M7.3.6 Проверка достаточности и ограничения

M6 устанавливает обоснованность отдельных IA, допустимость сводных вкладов, Scores и вид результата по M6.7. M7 проверяет исходные требования Cycle: целевой состав, количество и условия наблюдений, фактическое покрытие и ограничения. Проверка охватывает Indicators, Components и Skills; наличие числового Score само по себе не означает выполненного плана.

Отдельно фиксируются закрытие Cycle, выполнение плана и полнота результата относительно M2. Прохождение всех Cases, штатное завершение Session и 100 процентов сокращённого плана не гарантируют полного Score конструкта.

При пробелах допустимы частные ComponentScore и SkillScore по M6.7.3. Если отдельные IA обоснованы, но совместный расчёт недопустим, сохраняется Skill Result без SkillScore. Если нет ни одного обоснованного и допустимого для содержательной интерпретации IA L0–L3, Skill Result не формируется. Все четыре исхода и состав передачи определены в M7.7.4–M7.7.5.

Качественные основания Confidence, существенные противоречия и решения M6 учитываются как ограничения вывода. Confidence не является порогом покрытия или числовым весом; Reliability относится к версии механизма, а не к компетентности человека. Числовая «достоверность» в M7 не вводится.

M7 решает вопрос продолжения по M7.7–M7.8. После штатного завершения Session недостаточность, отсутствие полного Score или позднее исключение вклада не являются основаниями оставить Cycle открытым, возобновить его или назначить дополнительную Session. Целевой состав не сокращается задним числом.

M7.4 Подбор и последовательность кейсов

M7.4.1 Назначение

M7 подбирает Cases и организует последовательность Assessment Situations так, чтобы обеспечить целевой состав оценки по M7.2 и требования к наблюдениям по M7.3.

Для экспресс-оценки маршрут должен предусматривать оценку всех Skills четырёх компетенций в пределах зафиксированного бюджета Cycle, по умолчанию 60 минут. Количество кейсов определяется их содержанием, покрытием и продолжительностью. При другом бюджете пригодность маршрута проверяется для этих условий; целевой состав не сокращается автоматически.

M7.4.2 Основания для включения кейса

Основание | Что проверяется
Допуск по M5 | Конкретная версия Case и используемая ролевая реализация прошли необходимые проверки и допустимы для данного применения.
Релевантность роли и контекста | Задача, полномочия, информация и действия пользователя соответствуют зафиксированному PersonalizedProfile.
Вклад в целевое покрытие | Case применим к нужным Skills и Components и содержит точные IndicatorIDs с версией M2. После персонализации подтверждены условия Indicator Observability этих Indicators.
Условия самостоятельного проявления | Сценарий позволяет пользователю самостоятельно действовать; предъявление и реакции системы сохраняют условия оценивания.
Продолжительность | Плановое время позволяет включить ситуацию в маршрут с учётом остальных целей сессии.
История предъявления | Учитываются известные предыдущие прохождения этого кейса и ограничения его повторного использования.



Подбор начинается с Applicability Case на уровне Skills и Components и его точных IndicatorIDs по M5. В Assessment Situation до предъявления конкретизируются и проверяются условия наблюдения этих Indicators. Их состав не выбирается заново по уже полученным ответам.

M7.4.3 Сборка маршрута

При сборке маршрута для каждого обязательного Indicator определяется, в какой Assessment Situation и при каких условиях может возникнуть необходимое наблюдение.

Приоритет получают ситуации, которые обеспечивают ещё не обеспеченные цели плана. Одна ситуация может поддерживать несколько целей, если для каждой предусмотрена содержательная возможность самостоятельного проявления.

Повторное наблюдение того же IndicatorID включается, когда оно необходимо по требованиям M7.3 или для уточнения результата. Оно учитывается отдельно от покрытия других Indicators.

Для базовой реализации предусматриваются:

Основной маршрут — начальный набор и порядок ситуаций, рассчитанный на выполнение плана.

Резервные варианты — заранее допустимые кейсы для конкретных замен или дополнительных наблюдений.

Резервные варианты включаются по необходимости в пределах оставшегося временного бюджета. Для каждого указывается, какие цели он может обеспечить и на каком основании применяется. План может предусматривать резерв времени на уточнения и изменение маршрута внутри общего бюджета Cycle; обязательная единая доля такого резерва не устанавливается.

Если покрытие зависит от условной ветви Dialogue, эта зависимость отмечается в плане. Предусматривается способ получить необходимое наблюдение, если ветвь не возникнет. При отсутствии такого способа сохраняется известное ограничение плана.

M7.4.4 Правила последовательности

Порядок Assessment Situations определяется следующими требованиями:

Учитываются содержательные зависимости. Пользователь получает необходимые вводные и сведения до того, как они потребуются для действий.

Обеспечивается распределение наблюдений по целевым Skills. Для экспресс-оценки маршрут по возможности позволяет начать сбор материала по всем навыкам до углублённого повторного оценивания отдельных из них.

Сохраняется самостоятельность ответов. Прохождение предыдущей ситуации и обратная связь между ситуациями не должны раскрывать способ действия, который предстоит оценивать.

Учитываются время и сложность. Последовательность должна оставлять возможность пройти запланированный состав без произвольного сокращения сценариев.

Сохраняется сопоставимость вариантов. Разные маршруты одного стандартного сценария проверяются на соответствие общим целям и требованиям к условиям наблюдения.

Обязательная последовательность K1 → K2 → K3 → K4 не устанавливается. Кейсы могут одновременно затрагивать несколько компетенций.

M7.4.5 Изменение маршрута

До завершения прохождения замена или добавление ситуации допускается по заранее установленным основаниям: потеря возможности наблюдения, недостаточность материала, необходимость уточнения, невозможность прохождения или иное предусмотренное планом условие.

При изменении маршрута:

сохраняются исходный план и причина изменения;

проверяется пригодность новой Assessment Situation до предъявления;

учитываются её вклад в покрытие Cycle, оставшийся бюджет и крайний срок сбора;

сохраняются все уже полученные наблюдения и оценки.

Обоснованный низкий уровень сам по себе не является основанием для замены кейса или повторного предъявления.

M7 управляет выбором следующей ситуации. Основное сценарное развитие текущего Dialogue выполняется по M5; оценочные уточнения и решения о дополнительной оценке определяются в M7.6.

M7.4.6 Результат подбора

Результат подбора — маршрут с указанием Cases и их версий, подготовленных Assessment Situations, целей покрытия, условий возникновения наблюдений, порядка и планового времени.

Для фактического прохождения дополнительно сохраняется история изменений маршрута. По ней должно быть понятно, почему каждая ситуация была предъявлена и какую задачу оценки она решала.

M7.5 Проведение сессии и управление временем

M7.5.1 Подготовка и начало

До начала должны быть подготовлены план Cycle с эффективными значениями обоих параметров времени, зафиксированный PersonalizedProfile и допустимый начальный маршрут. При назначении Session фиксируются её идентификатор, Cycle и цель прохождения. Эту принадлежность нельзя определять по уже полученным ответам.

Пользователь получает короткую инструкцию: что оценивается, в какой роли он действует, как отвечать и запрашивать сведения, какие средства разрешены, как учитываются время и паузы и как остановить прохождение. Инструкция не раскрывает оцениваемый способ решения.

Сбор и согласование контекста завершаются до запуска оценки. Фактический запуск первой Session, включая общую инструкцию, фиксирует начало календарного окна Cycle. Предварительное назначение Session окно не запускает.

Для последующей Session проверяются незавершённость исходного прохождения, открытое состояние Cycle, остаток бюджета, срок и условия M7.8.

M7.5.2 Прохождение Assessment Situation

Пользователю предъявляются исходные сведения, задача и роль. Далее Dialogue развивается по правилам соответствующего Case из M5.

Система обеспечивает предусмотренные сценарием реакции, выдачу информации и изменения ситуации. Допускается техническая помощь, необходимая для взаимодействия с интерфейсом. Содержательные пояснения предоставляются в границах сценария.

Во время оценочного прохождения система не сообщает правильное решение и не обучает способу действия, который предстоит оценивать. Обратная связь о качестве выполнения предоставляется в предусмотренный планом момент с учётом оставшихся оценочных задач.

После завершения основного сценария при необходимости проводятся оценочные уточнения по M7.6 в том же Dialogue. Переход к следующей Assessment Situation происходит после завершения текущей ситуации, включая допустимые уточнения, либо по предусмотренному основанию остановки. Сценарное завершение и достаточность Evidence учитываются отдельно.

M7.5.3 Учёт времени и предельное окно Cycle

В плане каждого Cycle до первой Session фиксируются два самостоятельных параметра. Они ограничивают разные виды времени и применяются одновременно.

Параметр | Значение по умолчанию | Правило применения
Бюджет учитываемого времени прохождения | 60 минут для экспресс-оценки 4К | Общий бюджет всех Sessions Cycle. В других сценариях задаётся планом; продолжение не создаёт нового бюджета.
Максимальная календарная длительность сбора | 72 последовательных часа | Непрерывное окно от фактического старта первой Session до крайнего срока. Включает паузы, ожидание и промежутки между Sessions.



60 минут и 72 часа являются значениями по умолчанию, а не неизменными константами методологии. Их переопределение и фиксация регулируются M7.2.4. Оба параметра задаются как определённые положительные длительности; для начавшегося Cycle они не изменяются.

Учитываемое время складывается из времени всех Sessions одного Cycle. Сценарные вопросы M5 и оценочные уточнения M7 не имеют отдельного дополнительного бюджета.

Вид времени | Правило учёта
Общая инструкция после запуска, чтение вводной, обдумывание и содержательные переходы | Входят в общий учитываемый бюджет.
Вопросы и ответы в основном сценарии M5, в том числе запросы пользователя и уточнения реплик | Время чтения, обдумывания и ответа входит в тот же бюджет.
Оценочные вопросы M7 после основного сценария и ответы на них | Входят в тот же бюджет; отдельное добавочное время не выделяется.
Дополнительные Assessment Situations и продолжение в другой Session | Используют остаток того же бюджета Cycle.
Блокирующее ожидание системы или AI, включая генерацию, анализ M6 и подготовку вопроса M7 | Исключается из учитываемого времени только на период, когда пользователь не может продолжать прохождение; фиксируется отдельно.
Разрешённая пауза и промежуток между завершённой прерванной Session и допустимым продолжением | Не входят в учитываемое время; календарное окно продолжается.
Итоговый анализ M6 и подготовка отчёта M8 после прекращения сбора | Не входят во время прохождения и могут завершиться позже закрытия Cycle.



Фоновая работа системы не останавливает учитываемое время, если пользователь может продолжать читать доступную часть задания, обдумывать решение или отвечать. Исключение ожидания требует зафиксированного блокирующего состояния с началом и концом; сам факт работы AI или отсутствия сообщений пользователя недостаточен. Пересекающиеся интервалы ожидания и пауз не вычитаются дважды.

Крайний срок сбора равен моменту фактического начала первой Session плюс зафиксированная максимальная календарная длительность. Начало включает общую инструкцию после запуска; предварительное назначение Session окно не запускает. При значении по умолчанию это 72 последовательных часа, а не три календарные даты. Начало и крайний срок сохраняются с часовым поясом либо однозначными временными отметками.

Паузы, технические задержки и промежутки между Sessions не продлевают календарное окно. По достижении крайнего срока сбор прекращается, открытые Assessment Situations и Sessions окончательно завершаются, Cycle закрывается по M7.7. Нельзя начать Session до срока и продолжить сбор за его пределами.

Окно задаёт максимально допустимую длительность сбора, а не обязательное ожидание. Штатное завершение Session закрывает Cycle раньше; исчерпание учитываемого бюджета также прекращает сбор. Первое наступившее основание завершения применяется независимо от остатка по другому параметру.

Сохраняются эффективные параметры, учитываемое время каждой Session и всего Cycle, календарные начало и конец, блокирующее ожидание, паузы и причины остановки. Молчание пользователя само по себе не считается паузой: он может читать, обдумывать задачу или готовить ответ.

M7.5.4 Управление временным бюджетом

Пользователю доступны оставшийся учитываемый бюджет и крайний срок Cycle. Состояние разрешённой паузы или блокирующего ожидания должно быть различимо. Предупреждения о завершении даются нейтрально и не содержат оценочных подсказок; при продолжении показывается остаток общего бюджета.

Плановое время Case используется для организации маршрута. Обязательный жёсткий таймер на каждый ответ не вводится; ограничение внутри ситуации применяется, если оно предусмотрено и методически обосновано в M5. Настройка общего бюджета Cycle сама по себе не изменяет сценарий Case или его условия давления времени.

Перед следующим предъявлением учитываются остаток бюджета, календарное окно и плановая продолжительность ситуации. При недостатке времени выбирается допустимая альтернатива либо прохождение завершается.

При исчерпании учитываемого бюджета сбор прекращается, текущая Assessment Situation и Session завершаются, Cycle закрывается. Непройденный остаток маршрута и недостаточное покрытие не превращают исчерпание бюджета в прерывание, допускающее дополнительную Session.

Текущая Assessment Situation сохраняется в фактически достигнутом состоянии с причиной окончательного прекращения. M6 оценивает доступный материал; незавершённый сценарий сам по себе не означает L0. Ответы и оценочные уточнения после закрытия в этот Cycle не добавляются.

M7.5.5 Паузы прерывания и возобновление

Разрешённая пауза с предусмотренным возобновлением не завершает Session и Cycle. Для базового сценария плановые паузы допускаются между Assessment Situations. Условия пауз сообщаются до начала.

При прерывании внутри Assessment Situation сохраняются вводная, фактически раскрытые сведения, все состоявшиеся Turns, состояние сценария, использованное время и известная причина. Пока ситуация только приостановлена, итоговый Indicator Assessment не формируется по M6.6.9. При возобновлении той же ситуации новые Turns дополняют тот же Dialogue и Evidence Bundles; история не очищается.

Если прерванная Session завершается с решением продолжить незавершённое прохождение в другой Session, её незакрытая Assessment Situation окончательно прекращается и оценивается по сохранённому материалу. Дополнительная Session использует новые Assessment Situations по M5; происхождение прежних наблюдений сохраняется. Это не повторение уже штатно завершённого прохождения.

Продолжение допускается только в открытом Cycle, при сохранности необходимых данных, допустимых условиях, остатке исходного бюджета и до зафиксированного крайнего срока Cycle. Если прерывание нарушило условие сценария, включая обоснованное давление времени, ограничение передаётся M6. При окончательном отказе или невозможности продолжить Cycle закрывается.

Штатное завершение по плану или бюджету не является прерыванием. Прерывание не определяется задним числом по недостаточности Evidence и само по себе не устанавливает уровень навыка.

M7.5.6 Сохранение и передача материала

По каждой Assessment Situation сохраняется полный фактический Dialogue: начальная вводная, сообщения системы и участников, ответы пользователя и сценарные изменения. Фиксируются время, состояние взаимодействия и обстоятельства паузы, завершения или окончательного прекращения.

При передаче M6 сохраняются авторство, точные пользовательские Turns, фактически предъявленные материалы и момент их доступности. По M6.2 один Fragment находится в одном пользовательском Turn, каждый Behavioral Signal опирается на один Fragment; ссылки на другие Turns сохраняют контекст. Слова системы и персонажа не приписываются пользователю. Доказанное невыполнение действия адресуется к существующему Dialogue и условиям по M6.6.3; вымышленные Turns, Fragments или BS для него не создаются.

На уровне Session сохраняются её принадлежность к Cycle, маршрут, изменения, учитываемое время и причина завершения. На уровне Cycle сохраняются все Sessions, совокупное покрытие и ограничения, эффективные значения обоих параметров времени с источниками, фактически использованное время, непрерывное окно и основание закрытия. Для исключённых из учитываемого времени интервалов сохраняются границы и основания.

M6 получает материал с происхождением и условиями для формирования итоговых Indicator Assessments по завершённым Assessment Situations и допустимой агрегации внутри Cycle. Завершение сбора не требует одновременного окончания расчётов и подготовки отчёта.

M7.6 Дополнение оценки и адаптивные решения

M7.6.1 Назначение и распределение ответственности

Дополнение оценки применяется до завершения прохождения для получения недостающих оснований и разрешения ограничений, препятствующих результату Cycle. Оно ограничено остатком исходного бюджета и зафиксированным календарным окном Cycle; после штатного завершения Session отдельное дополнение в том же Cycle не проводится.

Адаптация осуществляется на двух уровнях:

внутри текущей Assessment Situation — через уточняющие оценочные вопросы после основной сценарной части;

между Assessment Situations — через изменение порядка, замену или добавление допустимых ситуаций.

Ответственность распределяется следующим образом:

Блок | Ответственность
M5 | Определяет основной сценарий, условия его завершения и границы допустимых уточнений для конкретного Case.
M6 | Проверяет полученные Evidence по дескрипторам M2, определяет конкретную неопределённость по IndicatorID и интерпретирует дополнительные ответы.
M7 | Решает, требуется ли уточнение, выбирает его назначение, формулировку и порядок; управляет временем и дальнейшим маршрутом.



Уточняющий оценочный вопрос назначается по правилам M7 на основании вывода M6 и в пределах допустимости, установленных M5.

Для выбора процедуры различаются три назначения уточнения:

Назначение | Основание и владелец | Правило в M7
Исходные сведения контекста | Ошибка, неполнота или конфликт источников профиля; M4.3–M4.5 и владелец соответствующего источника. | Передать на уточнение источника. Сохранить использованный профиль и фактические условия AS; оценочное влияние передать M6.
Сценарная реплика | Нужно понять ответ для продолжения основного взаимодействия; допустимые правила Dialogue в M5. | Продолжить сценарий в его пределах, без скрытой коррекции способа действия по предполагаемому уровню.
Оценочное основание | После основной сценарной части осталась конкретная неопределённость по IndicatorID × AS; запрос M6.6.6. | M7 определяет необходимость и допустимость вопроса, формулировку, порядок и остановку; M6 интерпретирует весь EB по M7.6.3–M7.6.4.



Если конфликт выявлен при подготовке оценки, действуют ограничения запуска по M4.5. Если ошибка исходных сведений обнаружена при прохождении, сохраняются фактически предъявленные условия и её влияние; исправление источника не заменяет их задним числом. Ответ на оценочное уточнение не обновляет фиксированный профиль автоматически. Необязательное незаполненное поле UserContext, конфликт контекста или сам факт вопроса не означают L0, INSUFFICIENT_EVIDENCE либо Red Flag. M6 проверяет фактическую возможность и доступные основания: при отсутствии возможности и других оснований IA не формируется, а причина остаётся пробелом покрытия. При невозможности допустимого продолжения M7 применяет правила завершения M7.7.

Порядок оценочного уточнения показан на схеме Б.3, разграничение трёх назначений — на схеме Б.6.

M7.6.2 Основания для дополнения

Основаниями могут быть:

неоднозначный смысл ответа, существенный для интерпретации Indicator;

недостаточность оснований для Indicator Assessment при возникшей возможности наблюдения;

неразрешённое противоречие в полученном материале;

отсутствие необходимой возможности наблюдения;

невыполненное требование плана к составу или повторности наблюдений;

нарушение условий прохождения, ограничивающее пригодность полученных оснований.

M6 устанавливает характер пробела. Уточнение смысла уже полученного ответа и получение нового наблюдаемого действия требуют разных решений. Запрос M6 по M6.6.6 содержит AS, IndicatorID, версию M2, EB, последний учтённый Turn, подтверждённые признаки и фактические связи, конкретную неопределённость и её влияние, потребность в объяснении либо новом действии и ограничения M2/M5. Запрос не является готовым вопросом пользователю или указанием продолжать Session.

Различие уровней одного IndicatorID в разных Assessment Situations само по себе не требует дополнения. До сводного вклада M6.7.1–M6.7.2 и M6.8.2 различают допустимую вариативность, несопоставимость условий и неясность основания отдельного IA. M7 получает конкретный пробел и его влияние; универсальный числовой порог расхождения уровней не вводится.

Обоснованный низкий уровень не является основанием для дополнительной попытки. Отсутствие признаков более высокого уровня не означает недостаточности Evidence.

M7.6.3 Уточнение внутри Assessment Situation

Базовый порядок предусматривает завершение основного сценария M5, включая все применимые сценарные ветви, затем проверку необходимости оценочных уточнений. M7 управляет прохождением с самого начала; оценочный вопрос после сценария относится к M7, а его интерпретация — к M6.

Завершение основного сценария не закрывает весь Dialogue. При необходимости уточняющие вопросы и ответы продолжают тот же Dialogue в пределах той же Assessment Situation.

Порядок уточнения:

M6 проверяет накопленный материал на последний учтённый Turn и передаёт запрос по M6.6.6. Для затронутых IndicatorIDs определяет подтверждённые признаки, существенные противоречия и конкретные недостающие основания. Будущие ответы не используются для обоснования более раннего запроса.

M7 определяет допустимость вопроса. Проверяет, может ли уточнение разрешить эту неопределённость без подсказки оцениваемого способа, изменения задачи или нарушения условий Case.

M7 учитывает время. Уточнение проводится в открытой Assessment Situation до завершения Session и Cycle, в оставшемся общем бюджете и календарном окне с учётом остальных целей Cycle. Чтение вопроса, обдумывание и ответ учитываются по M7.5.3; блокирующее ожидание анализа M6 или подготовки вопроса фиксируется отдельно.

Пользователю задаётся вопрос. Его назначение — прояснить конкретный ответ, основание решения или противоречие. Оценочное уточнение должно быть различимо с реакцией персонажа в основном сценарии.

M6 рассматривает дополнительный ответ вместе с прежним материалом. Сам факт ответа не означает устранения пробела. При отсутствии ответа это обстоятельство фиксируется без создания вымышленного пользовательского Turn или Evidence.

Один вопрос может относиться к нескольким IndicatorIDs только при самостоятельном основании для каждого; EB и итоговые IA остаются отдельными. При сохраняющейся неопределённости допускается следующее обоснованное уточнение. Вопросы прекращаются, когда неопределённость разрешена, допустимое уточнение больше не может дать новые оценочно значимые основания, требуется новое самостоятельное сценарное действие, пользователь отказался продолжать либо исчерпаны бюджет или окно Cycle. Затем Assessment Situation закрывается; M6 формирует итоговые оценки по доступному материалу. Отсутствие ответа не задаёт уровень автоматически.

Во время основного сценария допускаются предусмотренные M5 уточнения, необходимые для понимания реплики и продолжения взаимодействия. Они не должны превращаться в скрытую коррекцию поведения на основании предполагаемого уровня пользователя.

M7.6.4 Границы уточняющих вопросов

Вопрос должен сохранять условия самостоятельного проявления. Он не должен сообщать требуемый способ действия, готовые критерии, последовательность шагов или правильное решение.

Краткость ответа сама по себе не означает недостаточности. Требование объяснять способ действия применяется только там, где такое объяснение содержательно необходимо для соответствующего Indicator.

M6 учитывает, что проявилось до вопроса и что возникло после него. Действие, выполненное после прямого запроса, нельзя задним числом интерпретировать как самостоятельную инициативу пользователя. Универсальный штраф за любое уточнение не устанавливается.

Объяснение после основного сценария может раскрыть смысл ответа или основание решения и дать Evidence по Indicator, допускающему такую форму проявления. Оно не подтверждает само по себе совершение ранее не наблюдавшегося действия. Поздний ответ сохраняет условия своего появления и не заменяет ранний материал автоматически.

Если необходимой возможности проявления не было, ретроспективный вопрос не создаёт её задним числом. Когда после завершения основного сценария требуется новое самостоятельное сценарное действие, M7 рассматривает другую Assessment Situation. Применимые ветви текущего Case выполняются до завершения его сценарной части; под видом уточнения этот сценарий не открывается заново.

Уточнения не изменяют исходную задачу, полномочия пользователя, целевой состав оценки и правила M6.

M7.6.5 Изменение маршрута и завершение дополнения

Если уточнения внутри ситуации неприменимы или не устранили пробел, M7 определяет необходимость дальнейших наблюдений. Возможность добавить AS не тождественна возможности назначить дополнительную Session:

Ситуация | Допустимое решение
Прохождение Session продолжается; Cycle открыт | До штатного завершения допускается другая AS по правилам изменения маршрута, если она необходима, допустима по M5 и укладывается в остаток бюджета и календарный срок.
Прохождение прервано и остаётся незавершённым | Возобновить ту же Session либо назначить Additional Session по M7.8. В другой Session используются новые AS; прежняя незакрытая AS окончательно прекращается и оценивается по M7.5.5.
Session штатно завершена либо Cycle закрыт по иному основанию | Зафиксировать фактическое покрытие и ограничения. Новую AS или Session для дозаполнения закрытого Cycle не назначать. Самостоятельная повторная оценка — новый Cycle.



Эта граница применяется и тогда, когда пробел обнаружен только при окончательных расчётах M6 после закрытия. Схемы Б.2 и Б.4 показывают разные решения для продолжающегося маршрута и незавершённого прохождения.

Перед заменой или добавлением Assessment Situation необходимо:

Указать затронутые IndicatorIDs и невыполненное требование.

Проверить, предусмотрено ли нужное наблюдение оставшимся маршрутом.

Определить, какие новые основания должна дать дополнительная ситуация.

Выбрать допустимый Case и до предъявления проверить ролевую пригодность, Indicator Observability и ограничения повторного использования.

Проверить оставшийся бюджет, срок Cycle и влияние изменения на остальные цели оценки.

После прохождения повторно проверить выполнение требования.

Сохраняются зафиксированный PersonalizedProfile, исходный целевой состав оценки, правила M6, временной бюджет и весь ранее полученный материал.

При ограниченном времени приоритет определяется вкладом ситуации в обязательные требования плана. Для базовой экспресс-оценки сохраняется задача охвата всех Skills.

Все уточнения, вопросы в ходе Case, ответы и дополнительные предъявления используют единый учитываемый бюджет Cycle, по умолчанию 60 минут для экспресс-оценки. Запланированный резерв на уточнения является частью этого бюджета. Ни вопрос, ни новая Assessment Situation, ни дополнительная Session не увеличивают зафиксированный бюджет; правила исключения блокирующего ожидания едины для M5, M6 и M7.

Дополнение прекращается при выполнении требований либо невозможности продолжения в допустимых условиях и оставшемся времени. Сохранившиеся пробелы отражаются в ограничениях результата. Штатное завершение Session закрывает Cycle с сохранившимися ограничениями. Дополнительная Session по M7.8 допустима только для продолжения прерванного незавершённого прохождения, а не для устранения пробелов после штатного завершения.

M7.6.6 Обоснование решений и учёт результатов

Для каждого оценочного уточнения или изменения маршрута должно быть восстановимо:

какое невыполненное требование или неопределённость послужили основанием;

почему выбран конкретный вопрос или Assessment Situation;

какие основания предполагалось получить;

что фактически получено;

какие ограничения сохранились;

сколько учитываемого времени использовано и какие интервалы блокирующего ожидания исключены по M7.5.3.

Вопросы и ответы сохраняются в полном Dialogue с возможностью различить основную сценарную часть и последующие оценочные уточнения.

Дополнительные ответы внутри одной Assessment Situation пополняют Evidence Bundle соответствующего IndicatorID. После завершения взаимодействия M6 формирует итоговый Indicator Assessment с учётом всего материала и влияния заданных вопросов на условия проявления.

Промежуточные выводы после отдельных Turns не считаются самостоятельными наблюдениями для усреднения. Несколько уточнений внутри одной Assessment Situation не заменяют требование плана к наблюдениям в разных Assessment Situations.

Противоречия разбирает M6 при подготовке EB, в промежуточном разборе и после уточнений, перед итоговым IA после закрытия AS, а затем перед сводным вкладом на уровне Cycle. M7 принимает решение об уточнении или новой AS только пока сбор открыт. После исключений пересматриваются расчёты и покрытие; закрытый Cycle не открывается заново.

На уровне Cycle применяется порядок M6.7 и M7.3.5: допустимые оценки одного IndicatorID, затем полные или частные ComponentScore и SkillScore. Недостающие основания и INSUFFICIENT_EVIDENCE числовым значением не заменяются. Качественный Confidence отдельных IA не усредняется.

M7.7 Завершение Session и закрытие Cycle

M7.7.1 Назначение и различение состояний

M7 фиксирует завершение операционного эпизода Session и закрытие сбора для всего Cycle. Отдельно устанавливаются причина завершения, выполнение требований плана и состав результатов, которые может обосновать M6.

В методологии 1.1 штатное завершение Session по плану, включая завершение по временному бюджету, закрывает Cycle сразу. Это правило применяется при любых зафиксированных значениях параметров времени. Получение полного покрытия не является обязательным условием закрытия.

Cycle остаётся открытым после прерванной Session только при зафиксированном решении продолжить то же незавершённое прохождение в допустимых условиях и сроке. Ожидание расчётов M6 или отчёта M8 не является продолжением сбора и не удерживает Cycle открытым.

M7.7.2 Основания завершения и закрытия

Событие | Решение по Session и Cycle
Штатное завершение по плану | Session завершается, Cycle закрывается с фактическим покрытием, в том числе неполным.
Требования выполнены до исчерпания бюджета | Прохождение можно завершить досрочно; Session и Cycle закрываются.
Учитываемый бюджет исчерпан | Сбор прекращается, Session и Cycle закрываются. Пробелы не дают дополнительного бюджета.
Разрешённая пауза | Session и Cycle остаются открытыми; календарное окно продолжается.
Прерывание с допустимым продолжением | Сохраняется состояние; допускается возобновление той же Session либо дополнительная Session по M7.8. Cycle остаётся открытым в пределах срока.
Окончательный отказ или невозможность продолжения | Открытое взаимодействие окончательно прекращается, Session и Cycle закрываются с причиной и ограничениями.
Достигнут зафиксированный крайний срок Cycle | Сбор прекращается независимо от пауз и назначенного продолжения; открытые Session и Cycle закрываются.



При закрытии фиксируются момент, основание и состояние незавершённых Assessment Situations. Их Dialogue окончательно закрываются для новых ответов; M6 оценивает сохранённый материал по M6.6.9.

Если пользователь остановился, фиксируется характер решения: разрешённая пауза, прерывание с продолжением либо окончательный отказ. Нельзя оставлять Cycle открытым без определённого основания или после крайнего срока. Недостаточность, L0 и различия оценок сами по себе не являются основаниями продолжения после штатного завершения.

M7.7.3 Проверка выполнения плана

После прекращения сбора M7 сопоставляет исходный план Cycle и полный состав M2 с материалом всех входящих Sessions и итоговыми выводами M6. Проверяется:

Какие IndicatorIDs получили фактическую возможность наблюдения и какие имеют обоснованный итоговый IA L0–L3.

По каким IndicatorIDs допустим сводный вклад после проверок M6.7.1–M6.7.2, выполнены ли требования к числу и условиям наблюдений и почему другие вклады отсутствуют.

Какие обязательные Components имеют Score, какие из этих Scores полные и какие частные; по каким Components Score отсутствует.

Какой из четырёх исходов M6.7.4 получен для каждого целевого Skill; сохранены ли покрытие Indicators, покрытие Components и границы вывода.

Какие требования плана выполнены, какие ограничения остались и отличается ли покрытие плана от покрытия полного состава M2.

Каждая доля покрытия сохраняет числитель, знаменатель, включённые и отсутствующие IDs и версию состава по M7.3.2. После исключений M6 выполняется повторная сверка. Повторы одного IndicatorID не увеличивают покрытие; плановая наблюдаемость и факт предъявления Cases не подтверждают достаточность автоматически.

Проверка и расчёты могут завершиться после закрытия Cycle. Выявленные тогда пробелы отражаются в результате и не открывают новый сбор в закрытом Cycle.

M7.7.4 Формирование результата при полном и неполном покрытии

Итоговые IA и расчёты формирует M6 по материалу одного закрытого Cycle. Основание Skill Result — хотя бы один обоснованный итоговый IA L0–L3 по относящемуся к Skill Indicator, допустимый для содержательной интерпретации. Допустимость SkillScore проверяется отдельно. M7 принимает следующие исходы M6.7.4:

Исход | Условия и передаваемый результат
Skill Result с полным SkillScore | Все обязательные Components M2 имеют полный ComponentScore, выполнены требования M7. Передаются Score, состав, покрытие, исходные IA и ограничения.
Skill Result с частным SkillScore | Есть допустимый агрегат по M6.7.3, но полный состав или требования полного результата не обеспечены. Каждый Score помечен полным либо частным; отсутствующие элементы и причины видимы.
Skill Result без допустимого SkillScore | Есть обоснованные IA, допустимые для содержательной интерпретации, но общий числовой расчёт недопустим. Передаются отдельные результаты, доступные основания, причины и ограничения.
Отсутствие Skill Result | Нет ни одного обоснованного и допустимого для интерпретации IA L0–L3. Передаются имеющиеся IA с INSUFFICIENT_EVIDENCE, сведения об отсутствии IA, покрытие и причины; пустой Skill Result не создаётся.



Отдельный обоснованный IA сохраняется, даже если его нельзя усреднить с другими IA. Несопоставимость не разрешает выбрать удобный результат ради Score. Незатронутые обоснованные результаты других Components и Skills сохраняются.

L0 включается в допустимый расчёт как 0; частный Score 0 отличается от отсутствующего Score. INSUFFICIENT_EVIDENCE и отсутствие IA не кодируются числом. При отсутствии всех допустимых вкладов соответствующий Score не рассчитывается. Частный Score описывает только включённый состав и не подтверждает результат отсутствующих элементов.

Числовые ComponentScore и SkillScore автоматически не преобразуются в L0–L3. Skill Level требует отдельного обоснованного и проверенного правила M6; M7 не выводит его округлением Score. Наличие полного SkillScore само по себе этого правила не создаёт.

Любой из четырёх исходов совместим с закрытием Cycle. Частный Score, Skill Result без Score и отсутствие Skill Result не запускают дополнительную Session после штатного завершения. Разные Cycles имеют отдельные результаты.

M7.7.5 Выходные данные и передача между блоками

M7 передаёт M6 принадлежность материала к Cycle и Sessions, исходный план и требования, зафиксированный профиль, эффективные параметры и фактические условия времени, прочие условия прохождения и решение о прекращении сбора. Неизвестная принадлежность Session к Cycle не восстанавливается по уровням или ответам; до её уточнения M6 не включает материал в выбранный Cycle по предположению.

После закрытия Cycle и завершения расчётов M6 в M8 передаётся согласованный состав:

Состав | Содержание и источник
Идентичность и план | M7: Cycle, внутренний идентификатор человека, цель, полный состав M2 и план Cycle, требования, фиксированный профиль и версии. Идентифицирующие и контактные сведения не направляются в содержательную оценку M6.
Sessions и прохождение | M7: идентификаторы и принадлежность Sessions, основания назначения, порядок, начало и завершение; Cases и версии, AS, полные Dialogue, изменения условий и маршрута, паузы и прерывания.
Время и закрытие | M7: оба эффективных параметра и их источники; учитываемое время Sessions и Cycle; границы и причины исключённых интервалов; начало окна, крайний срок, момент и причина закрытия.
Результаты и расчёт | M6: исходные IA, допуск и исключения, сводные вклады, ComponentScore и SkillScore при допустимости, признак полного или частного состава каждого Score; четыре исхода M6.7.4, число AS и разброс.
Покрытие и требования | M6 и сверка M7: все счётчики M7.3.2 с числителями, знаменателями, IDs и версиями состава; полный состав M2 отдельно от плана при их различии; причины пробелов, выполненные и невыполненные требования.
Обоснованность и противоречия | M6: качественные основания Confidence, существенные противоречия, решения по ним и ограничения исходных IA и агрегатов. Confidence не усредняется и не превращается в вес Score.
Проверка механизма | M6: использованная версия механизма, применимый протокол Reliability и область проверки либо явное отсутствие проверки или сведений. Проверка другой версии не приписывается использованной.



Значения и происхождение могут передаваться восстанавливаемыми ссылками. Связь IA → EB сохраняется и при пустом EB. Evidence, BS, Fragments и пользовательские Turns адресуются только при фактическом наличии; вместо отсутствующих записей сохраняются исходный Dialogue, условия и обоснование M6. Покрытие и причины передаются также при отсутствии Score или Skill Result.

Каждому закрытому Cycle соответствует один Results. M8 определяет Report и представление получателям; его контракт должен поддерживать частные Scores и существенные ограничения. M7 не создаёт числовой показатель достоверности и не представляет Reliability как качество навыка человека. Изменение длительности не меняет требований к достаточности и не подтверждает сопоставимость автоматически.

Пока Cycle открыт, расчёты и покрытие используются M7 как текущие сведения. Закрытие сбора и завершение расчётов — разные события; окончательный Results выпускается после обоих. Разные закрытые Cycles сохраняют отдельные Results и происхождение.

M7.7.6 Фиксация незакрытых требований

При неполном покрытии фиксируются затронутые IndicatorIDs, зависимые Components и Skills, характер недостающих оснований и границы допустимого вывода.

После штатного завершения Session эти сведения описывают ограничения закрытого Cycle. В методологии 1.1 они не являются заданием на дополнительную Session того же Cycle.

Если впоследствии назначается самостоятельная оценка состояния человека, для неё создаётся новый Cycle по M7.8. Прежние ограничения сохраняются; новые наблюдения не переносятся назад для их устранения. Низкий результат сам по себе не требует повторной оценки.

M7.8 Продолжение прохождения и повторная оценка

M7.8.1 Назначение и виды

Назначение следующей Session определяется до её начала.

Вид | Основание | Принадлежность
Дополнительная Session | Продолжение прерванного незавершённого прохождения в оставшемся бюджете и сроке. | Тот же открытый Cycle.
Повторная оценка | Самостоятельный новый срез состояния человека, например после программы развития. | Новый Cycle со своим планом и Results.



В методологии 1.1 отдельная Session только ради получения недостающих Evidence после штатно завершённой Session не предусмотрена. Если Session завершилась штатно, Cycle закрыт независимо от покрытия.

Первая Session, прерванная до окончания прохождения, и дополнительная Session, которая его завершила, могут составлять один Cycle. Оценка до обучения и отдельно назначенная оценка после него относятся к разным Cycles. Совпадение человека, Skills и близость дат не меняют этого разграничения.

Повторная интерпретация уже полученных Dialogue без новых ответов относится к M6 и сама по себе не является новой Session или основанием переопределить состав Cycle.

M7.8.2 Условия дополнительной Session

Перед назначением необходимо установить все следующие условия:

Исходное прохождение прервано и не завершено штатно; Cycle остаётся открытым с зафиксированным намерением продолжить.

Сохраняются тот же человек, оценочная задача, целевой состав и фиксированный PersonalizedProfile; совместимость методических версий обоснована.

Есть остаток исходного учитываемого бюджета и времени до зафиксированного крайнего срока Cycle.

Продолжение возможно в допустимых условиях с сохранением предшествующего материала и влияния уже раскрытых сведений.

При назначении фиксируются идентификатор Cycle, причина продолжения, невыполненная часть маршрута, доступное время и план новой Session.

Дополнительная Session не получает нового полного бюджета. Допустимо изменить предстоящий маршрут по M7.4 и M7.6, сохранив исходную цель и требования Cycle. Недостаточность уже полученных Evidence может учитываться при таком планировании, но не является самостоятельным основанием дополнительной Session.

Если условия продолжения не выполнены, текущий Cycle закрывается с фактическим материалом и ограничениями. Любая впоследствии назначенная самостоятельная оценка оформляется новым Cycle до получения ответов.

M7.8.3 Кейсы и изменения условий между Sessions

При подборе учитываются ранее предъявленные Cases и версии, раскрытые сведения, сценарные события, обратная связь и известное обучение или тренировка. Предпочтительны другие допустимые Cases, позволяющие получить необходимые наблюдения без воспроизведения запомнившегося решения.

Повтор Case допускается по правилам M5 с учётом цели. Замена имён, чисел или терминологии сама по себе не устраняет знакомство с задачей. Case сохраняет содержательную целостность: его нельзя свести к отдельным вопросам, если исчезают условия самостоятельного проявления.

Известные изменения роли, полномочий, деятельности, обучение и иные существенные изменения между Sessions фиксируются вместе с их временем. В методологии 1.1 сам факт такого изменения не вводится как отдельное автоматическое основание закрыть Cycle или создать новый. Фиксированный профиль и принадлежность уже назначенных Sessions не переписываются; M6 отдельно проверяет влияние изменений на допустимость и сопоставимость оценок.

Если дальнейшее прохождение невозможно в допустимых условиях, применяется закрытие по M7.7. Если назначена новая самостоятельная оценочная задача, создаётся новый Cycle. Для продолжения внутри Cycle сохраняются исходный бюджет и неизменный крайний срок, рассчитанный по зафиксированной календарной длительности. Единого обязательного интервала между самостоятельными Cycles M7 не устанавливает; учитываются цель и ограничения Cases.

M7.8.4 Использование материала дополнительной Session

Все Dialogue, Evidence Bundles и итоговые Indicator Assessments сохраняют принадлежность к своим Assessment Situations и Sessions. Дополнительная Session продолжает сбор для того же среза; она не создаёт отдельный итог, который затем объединяется с результатом ранее закрытого Cycle.

M6.7 проверяет допустимость совместного использования оценок: конструкт и версии, содержание оцениваемого действия, условия роли и сценария, доступные сведения, полномочия, ограничения, вопросы и самостоятельность. Один Cycle, одинаковый IndicatorID или близкие даты не заменяют эту проверку.

В итоговый расчёт Cycle включаются допущенные M6 оценки. Evidence Bundles разных Assessment Situations не объединяются; готовые результаты Sessions не усредняются. Лучшее или последнее значение не выбирается автоматически; исключения требуют основания и сохраняются в происхождении результата.

Повторное наблюдение того же Indicator дополняет его основания, но не добавляет новый пункт целевого покрытия. Несопоставимые оценки сохраняются с ограничениями; ради удобного итога Sessions не переносятся между Cycles.

M7.8.5 Использование результатов повторной оценки

Повторная оценка формирует самостоятельный результат по материалу нового Cycle. Прежние Indicator Assessments и Skill Results не добавляются в его расчёт для увеличения покрытия или изменения значения.

M7 фиксирует новый план, профиль, версии, эффективные значения обоих параметров времени с их источниками, календарное окно и связь с прежним Cycle. M6 агрегирует материал только внутри нового Cycle. M8 определяет допустимое сопоставление отдельных Results и продольный анализ.

Сопоставление требует проверки конструкта, правил оценивания, включённых IndicatorIDs и Components, полноты каждого Score и условий прохождения. Равные Scores при разном составе не доказывают равенство навыка; разница чисел сама по себе не доказывает развитие или снижение. Учитываются знакомство с Cases, обратная связь, обучение и другие ограничения.

При неподтверждённой сопоставимости сохраняются самостоятельные результаты с описанием условий. M7 не объединяет закрытые Cycles и не рассчитывает динамику вместо M8.

M7.8.6 Завершение продолжения и выходные данные

Штатное завершение дополнительной Session закрывает Cycle по тем же правилам, что и завершение первой Session. Если продолжение снова прервано, возможность следующей Session проверяется заново по M7.8.2 в пределах того же остатка бюджета и неизменного крайнего срока.

При закрытии фиксируются состав Sessions, какие части исходного прохождения завершены, совокупное покрытие, ограничения и допустимые результаты M6. Неустранённые пробелы не продлевают Cycle.

Время Sessions учитывается отдельно и суммарно. Результат описывается через зафиксированный бюджет и фактически использованное время всего Cycle. Формулировка о прохождении в пределах 60 минут применима лишь при фактическом соблюдении этого предела; другая настройка не представляется как проверка часового сценария. Число Sessions, паузы, исключённое ожидание и календарная длительность сохраняются; возобновлённое прохождение не представляется как одна непрерывная Session.

Повторная оценка закрывается как отдельный Cycle и передаёт в M8 отдельный Results. Связь с предыдущей оценкой не изменяет происхождение её материала.

M7.9 QA и пилотная проверка

M7.9.1 Назначение и границы

QA M7 проверяет, позволяет ли организация Cycle и его Sessions выполнить план, сохранить допустимые условия наблюдения и получить обоснованный результат. Проверяются принадлежность сессий, подбор ситуаций, покрытие, уточнения, время, продолжение и закрытие.

M5 проверяет пригодность Cases и Assessment Situations; M6 — Evidence, Indicator Assessments и расчёты; M7 — организацию Cycle и согласованное применение правил; M8 — представление Results и допустимое сопоставление Cycles.

Проверка включает документную сверку, сценарные прогоны и эмпирический пилот. Каждый этап подтверждает только фактически проверенные свойства.

M7.9.2 Документная проверка

Область | Что проверяется
Цель и принадлежность | Cycle, человек, фиксированный профиль, целевой состав; назначение Session в Cycle до её ответов.
Кейсы и покрытие | Пригодность Cases, условия наблюдения обязательных Indicators, отсутствие повторного счёта покрытия.
Уточнения | Основной сценарий завершён до оценочных вопросов; согласованы M5, M6 и решения M7.
Расчёт | IA относится к одной завершённой AS; расчёт внутри Cycle различает полный и частный Score, результат без Score и отсутствие Skill Result. Пропуски сохранены в покрытии, равные веса M6 не изменены.
Время | Значения обоих параметров определены по уровням настроек и зафиксированы до старта; вопросы входят в общий бюджет, блокирующее ожидание исключено по факту; календарное окно непрерывно, продолжение не меняет лимиты.

Результат и повторная оценка | Один закрытый Cycle связан с одним Results; передаются состав, все разрезы покрытия, качественные основания Confidence и применимость проверки Reliability. Новый Cycle даёт отдельный срез; сравнение относится к M8.



Проверяются содержательные связи и версии блоков. Наличие задачи в бэклоге не означает закрытия зависимости. Известные изменения условий отражаются без автоматической перегруппировки Sessions; сопоставимость проверяется M6.7.

M7.9.3 Сценарные прогоны

Сквозные проверки оценки опираются на Golden Cases (GC) по M6.9. Для утверждённого GC фиксируются входные AS и Dialogue, методические версии, ожидаемые результаты M6, решения M7 и допустимая передача M8. Case из M5 и отдельная операционная траектория сами по себе не являются GC. До независимого экспертного утверждения материал остаётся кандидатом в GC.

Проверяются как минимум следующие траектории и ожидаемые решения:

Штатное завершение с полным покрытием: Session и Cycle закрыты.

Штатное завершение с неполным покрытием, включая исчерпание зафиксированного бюджета (60 минут при настройке по умолчанию): Cycle закрыт с ограничениями; дополнительная Session ради Evidence не назначается.

Прерывание до завершения: допустимое возобновление либо дополнительная Session в том же Cycle, с сохранением материала и остатка бюджета.

Пауза внутри Assessment Situation: до окончательного завершения нет итогового Indicator Assessment; после прекращения оценивается доступный материал.

Достижение зафиксированного крайнего срока во время паузы, ожидания или дополнительной Session: сбор прекращается, Cycle закрывается; расчёты и отчёт могут завершиться позже.

Неоднозначный ответ: допустимый вопрос после всех применимых ветвей основного сценария; один итоговый Indicator Assessment по всей ситуации.

Уточнение не дало новых оснований, ответа нет или требуется новое самостоятельное действие: вопросы прекращаются; новое действие рассматривается в другой Assessment Situation при доступном времени.

Обоснованный низкий уровень или невозникшая условная ветвь: отсутствует автоматическое назначение дополнительной попытки или L0.

Несколько оценок одного IndicatorID: нет нового целевого покрытия и автоматического выбора лучшей оценки; совместимость проверяется M6.

Известное изменение условий между Sessions: факт и ограничения зафиксированы, профиль и принадлежность не переписаны, оценки проверены M6.7.

Новая оценка после закрытия или после программы развития: новый Cycle и отдельный Results; прежние оценки не добавляются в расчёт.

Попытка перегруппировать Sessions после ответов либо собрать ответы после закрытия: состав закрытого Cycle и границы сбора сохраняются.

Настройки организации и программы: каждый параметр наследуется или переопределяется независимо; перед стартом сохранены эффективные значения и их источники. Проверяются значения по умолчанию и отличные от них значения без скрытого возврата к 60 минутам или 72 часам.

Изменение административных настроек после старта: бюджет и крайний срок начавшегося Cycle остаются прежними, новые настройки применимы к ещё не начавшимся оценкам после фиксации их плана.

Вопрос внутри Case, последующее оценочное уточнение и новая Assessment Situation: учитываемое время списывается из одного бюджета, продолжение в следующей Session использует только остаток. Резерв не создаёт дополнительных минут.

Генерация или анализ M6 блокируют продолжение: интервал исключается из учитываемого времени, календарный срок продолжает идти. Если пользователь может продолжать, время учитывается; отсутствие сообщений само по себе таймер не останавливает.

Неполный состав: допустимы частные ComponentScore и SkillScore; пропуски исключены из числового знаменателя и сохранены в покрытии. Наличие числа по всем Components при одном частном Component не делает SkillScore полным.

Четыре исхода M6.7.4: полный Score, частный Score, отдельные обоснованные результаты без допустимого Score, отсутствие Skill Result. Все исходы сохраняют основания и ограничения и не возобновляют закрытый Cycle.

После исключения IA: повторно проверены достаточность вклада, расчёты и покрытие. Обоснованный IA без допустимого общего вклада не объявлен покрытием вклада; L0, INSUFFICIENT_EVIDENCE и отсутствие IA различены.

Разные IA одного Indicator: допустимая вариативность сохраняет разброс; несопоставимость ограничивает вклад; противоречие внутри IA проверяется по его EB. Поздний ответ не имеет автоматического приоритета.

Передача результата: сохранены все счётчики покрытия, состав и версия механизма, качественные основания Confidence и существенные противоречия. Для Reliability передан применимый протокол и область либо явное отсутствие проверки или сведений.

Сокращённый план и результаты разных Cycles: выполнение плана не объявлено полнотой M2; различия или совпадения частных Scores при разном составе не превращены автоматически в динамику или равенство навыка.

Сведение или материал есть в профиле либо полном Case, но не предъявлены в AS: доступность к конкретному Turn не предполагается; заявленный опыт пользователя не становится Evidence уровня.

Отсутствует необязательное поле UserContext или выявлен конфликт источников: это не автоматические L0, INSUFFICIENT_EVIDENCE или Red Flag. Отдельно проверяются возможность наблюдения и влияние на вывод M6; контекст исправляется по M4.

Источник изменился после подготовки кейса до первого ответа либо после оценочного уточнения: использованный PersonalizedProfile не переписан автоматически, прежние условия восстановимы.

Один и тот же пробел обнаружен до штатного завершения и после закрытия: в первом случае допустимость другой AS проверяется по M7.6.5; во втором сохраняется ограничение без нового сбора. Additional Session не назначается только из-за пробела.

Повторная обработка того же Dialogue и уточняющие Turns не создают независимых наблюдений. На IndicatorID × завершённую AS сохраняется не более одного итогового IA; при повторном разборе обновляются основания, а не количество наблюдений.

Проявления из разных пользовательских Turns и слова системы: Fragments локализованы в своих Turns, BS имеет один исходный Fragment, авторство сохранено. Доказанное невыполнение не порождает фиктивный Fragment или BS.

Для каждого прогона сохраняются вход, версии, ожидаемые и фактические решения, основание PASS/FAIL и ограничения. Повторный прогон использует тот же фиксированный вход; GC не добавляются в EB пользователя. При проверке механизма M6 действуют M6.9.3–M6.9.6, включая три успешных повторных прогона каждого обязательного GC на одной версии механизма. Повторяемость и соответствие экспертному эталону проверяются отдельно.

Проверка текста и ручной разбор траектории не считаются исполненным прогоном продукта. Синтетические ответы не доказывают длительность прохождения людьми и достижимость покрытия. GC и независимость их утверждения проверяются отдельно от документного QA.

M7.9.4 Эмпирический пилот

Пилот проводится на фактических прохождениях пользователей в заявленных ролях и условиях применения.

До начала определяются состав участников, проверяемые маршруты, собираемые показатели и критерии принятия решения. Объём пилота обосновывается задачами проверки; универсальное число участников в M7 не устанавливается.

Для базовой экспресс-оценки с настройками по умолчанию проверяется гипотеза: в пределах 60 минут учитываемого времени и календарного окна 72 часа можно получить основания для оценки всех целевых Skills четырёх компетенций с соблюдением требований M7.3. Прохождения с другими значениями параметров выделяются в отдельные условия проверки; их результаты не подтверждают часовой сценарий автоматически.

По фактическим прохождениям рассматриваются:

эффективные параметры и их источники, учитываемое время Sessions и Cycle, календарная длительность и соблюдение зафиксированного крайнего срока;

время основных сценариев, вопросов в ходе Case, оценочных уточнений и исключённого блокирующего ожидания;

доля Cycles, в которых выполнен весь план, с разделением непрерывных и возобновлённых прохождений;

выполнение требований по каждому Skill, все разрезы покрытия M7.3.2 и причины незакрытого покрытия;

доли четырёх исходов M6.7.4 по целевым Skills; частный Score не считается подтверждением полного покрытия;

частота и причины отсутствия возможности наблюдения и INSUFFICIENT_EVIDENCE;

какие уточнения и изменения маршрута помогли получить недостающие основания;

случаи нарушения самостоятельности или иных существенных условий оценки.

Обоснованный низкий уровень не считается неуспехом покрытия или дефектом сценария.

В анализ включаются также незавершённые и прерванные прохождения с указанием причин. Возобновлённые прохождения рассматриваются отдельно от непрерывных; проверяются суммарное учитываемое время Cycle, его календарная длительность и влияние прерываний на условия наблюдения.

M7.9.5 Интерпретация результатов проверки

Выводы пилота относятся к проверенным ролям, маршрутам, версиям Cases и условиям проведения. Их распространение на другие варианты требует обоснования.

Одинаковое плановое время разных маршрутов не подтверждает их сопоставимость. Проверяются возможности наблюдения, самостоятельность действий, фактическое покрытие и ограничения результата.

При систематических пробелах устанавливается их источник: конструкция Case, персонализация, последовательность ситуаций, недостаток времени, правила уточнений либо оценочная интерпретация.

Исправления направляются в соответствующий блок. Нельзя задним числом уменьшать требования к покрытию или достаточности, чтобы объявить пилот успешным.

Выбор других значений параметров до старта по M7.2.4 является настройкой программы или запуска и сам по себе не требует новой версии M7. Он фиксируется в плане и условиях проверки. Изменение методических значений по умолчанию, правил учёта времени, требований к покрытию или достаточности оформляется как методическое изменение по M0. Новый целевой состав оценки задаётся до старта; настройки времени не сокращают его задним числом.

До эмпирического подтверждения достижимость полного покрытия за 60 минут сохраняет статус гипотезы пилота.

M7.9.6 Результат QA и выпуск версии

Для каждой проверки фиксируются её предмет, использованные версии и условия, фактические основания, результат и выявленные ограничения.

Применяются отметки:

PASS — установленное требование проверено и выполнено;

FAIL — проверка выявила несоответствие;

NOT_RUN — проверка не проводилась.

NOT_RUN не считается подтверждением выполнения требования. После исправления несоответствия повторяется затронутая проверка; при изменении общих правил проверяются связанные сценарии.

Итог QA должен позволять определить:

какие положения согласованы;

какие свойства подтверждены прохождениями;

какие замечания препятствуют заявленному применению;

какие гипотезы и ограничения сохраняются.

Переход нормативного документа в FROZEN проводится по M0 после QA, проверки существенных зависимостей и утверждения владельцем.

Статус FROZEN фиксирует утверждённые правила. Эмпирическая проверенность конкретного сценария, его продолжительность и достигнутое покрытие подтверждаются отдельными результатами проверки.

В.4 Решения прошлой проработки и финальная формулировка

Прежние обсуждения количества Cases, конкретного минутного маршрута и вариантов форм служат входом для проектирования и пилота. Они не вводят в M7 универсальные пять Cases, фиксированные 50 минут, обязательные формы A–D или безусловную эквивалентность форм. Количество Cases определяется покрытием, допустимостью и временем; эквивалентность альтернатив подтверждается по M7.9. Параметры по умолчанию остаются 60 минут и 72 часа, с настройкой до старта по M7.2.4.

Ранее обсуждавшееся дополнение недостаточного покрытия разложено на разные ситуации. В продолжающейся Session допустима другая AS по M7.6.5. Additional Session разрешена только для незавершённого прохождения. После штатного завершения Session её Cycle закрыт при любом покрытии; расчёты можно закончить позже, новые ответы добавлять нельзя. Эти правила отражены в схемах Б.2–Б.4 и не переопределены backlog.

Итоговая граница M7: организовать один независимый срез с исходным планом, фиксированным контекстом и двумя параметрами времени; управлять допустимыми Cases, уточнениями и продолжением; сверить фактическое покрытие и закрыть Cycle с его ограничениями. M6 формирует оценочные основания и допустимые расчёты. M8 сохраняет и представляет один Results закрытого Cycle, включая частные исходы и отсутствие Skill Results.

M7 v1.3 утверждён FROZEN с внесёнными уточнениями и схемами. Новая модель оценки из backlog не требуется. Существенные зависимости M1/M8 сохраняются по А.3 и А.6; эмпирическая пригодность и готовность реализации подтверждаются отдельно.
