# Чек-лист ревью EVC

## Результат и область

- [ ] Diff реализует заявленные критерии приёмки и не меняет постороннее поведение.
- [ ] Изменения публичного API, данных, конфигурации и UI документированы.
- [ ] Рефакторинг отделён от изменения поведения либо его необходимость явно обоснована.
- [ ] Прочитанные источники и пробелы записаны; стоп-условия проверены, необходимые решения имеют человеческого владельца и основание.
- [ ] Управляющие документы не менялись попутно; для их изменения есть отдельная согласованная задача.

## Инварианты оценки

- [ ] Указаны применимые версии источников, PM/LU, контракты и владельцы данных; открытые решения не реализованы как утверждённые нормы.
- [ ] Различены целевая архитектура, версии M, наличие пакетов/задач и реализованное поведение; будущие M6–M8 не объявлены выполненными или дефектами автоматически.
- [ ] Обновлена связь «источник → правило → реализация → проверка».
- [ ] Соблюдены границы PM, разделение фактической оценки, интерпретации и отчёта; цели компании не меняют фактическую оценку.
- [ ] Промпты, справочники и предметные политики находятся в версионируемых артефактах, включая настройки сборщиков; новые скрытые defaults отсутствуют.
- [ ] Legacy-исключения не расширены; затронутый долг и критерии его закрытия отражены в реестре.
- [ ] Для переноса артефактов проверены сохранение содержания, потребители, полнота пакета и исполнение старого снимка после изменения текущих настроек.

- [ ] Опубликованные определения и пакеты промптов остаются неизменяемыми.
- [ ] Запущенные сессии используют сохранённые снимок и контрольную сумму.
- [ ] Черновик не может стать конфигурацией по умолчанию.
- [ ] Сценарий может исполнять только зарегистрированные компоненты и предикаты.

## Данные и безопасность

- [ ] Каждая новая операция проверяет авторизацию на сервере.
- [ ] Логи и ответы не содержат секретов или лишних персональных данных.
- [ ] Изменения схемы обратно совместимы либо имеют явные миграцию и откат.
- [ ] Тесты не могут подключиться к базе разработчика или production.
- [ ] Новые переменные окружения описаны во всех относящихся к ним `.env.*.example`.

## Надёжность и эксплуатация

- [ ] Где применимо, обработаны повторные попытки, идемпотентность, тайм-ауты и частичные сбои.
- [ ] Задачи очереди восстанавливаются после истечения lease и не дублируют активную работу.
- [ ] Эксплуатационные сбои наблюдаемы без раскрытия чувствительных данных.
- [ ] Изменение можно безопасно отключить или отменить.

## Проверка

- [ ] Каждая исправленная ошибка покрыта регрессионным тестом.
- [ ] Значимые модульные и интеграционные/HTTP-пути покрыты тестами.
- [ ] Локальный минимум [матрицы](verification-matrix.md) выполнен для всех типов изменения; неприменимость и пропуски обоснованы.
- [ ] При изменении поведения базы данных integration прошёл на изолированной test/pytest-БД, не просто пропущен runner.
- [ ] `git diff --check` проходит.
- [ ] Перед слиянием для актуального head/base успешны обязательные CI jobs `frontend` и `pytest`; локальные результаты не подменяют CI.

## Передача результата

- [ ] PR содержит ссылку на локальную задачу (пока WEEEK не используется) или тикет и точные шаги проверки.
- [ ] Риски, непроверенное поведение, шаги развёртывания и откат указаны явно.
- [ ] Скриншоты, примеры API или логи приложены, если они существенно помогают ревью.
- [ ] Полный отчёт оформлен по [рабочему циклу](agent-workflow.md#шаблон-отчёта), состояние следующего шага сохранено.
- [ ] Baseline не заявлен без всех доказательств [чек-листа утверждения](baseline-v1.md) для точного commit/tag.
