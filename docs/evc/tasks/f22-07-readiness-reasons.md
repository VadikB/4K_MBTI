# F22-07 — причины готовности выбранной оценки

## Результат и границы

Исправить ложную свёртку всех поздних причин в «роли участников». Готовность должна
считать только пользователей, назначенных в выбранный `assignment_ref`, включая
администратора, если его независимо пригласили как участника. Отдельно показываются
ожидание знакомства, проблема связки профиля/роли и ошибка серверной проверки.

Права администратора, ответы участника, схема БД, методология и подготовка M7 не
меняются. Администратор не получает возможности отвечать за участника.

Стоп-условия: нет. Публичные поля readiness расширяются совместимо; существующие
`status/message/ready/total` сохраняются. Миграция и новые права не требуются.

## Реализация

- Участники и активные подготовки выбираются через действительное персональное
  приглашение ровно выбранного `assignment_ref`, а не через все `member` организации.
- `late_readiness.reason` агрегируется в безопасные счётчики; технический текст
  исключения после `:` наружу не передаётся.
- UI использует серверный `action_view`: переход в список участников показывается
  только для исправимой там проблемы профиля/роли, но не для ожидания знакомства.

## Проверки

Требуются: адресные unit и browser-регрессии, полный `npm run test:backend`,
`node --test tests/frontend/*.test.mjs`, `npm run lint:js`, `npm run build:web`,
`git diff --check`. HTTP/integration проверяется обязательным CI; локальная
integration допустима только на изолированной БД с `test`/`pytest` в имени.

## Риски и откат

Конфиг, схема и данные не меняются. Риск — несовпадение старых фиктивных readiness
ответов; отсутствие `action_view` безопасно скрывает переход. Откат — revert PR.
