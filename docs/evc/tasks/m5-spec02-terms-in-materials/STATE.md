# SPEC.02. Пояснения терминов в материалах участника

Карточка исходного кандидата `f9259a1b`. Совмещённая версия описана в
[карточке интеграции](../p4k-m5-spec02-integration.md).

22 ноября 2026. Решение владельца продукта для новых ситуаций SPEC.02. Участник получает короткое пояснение там, где встречает необходимый рабочий термин. Если в документах видно, когда меняется статус результата, повторять определения во вводной P00 излишне.

## Основание

Паспорт SPEC.02 v0.6, поле 13, требует объяснить необходимые термины. M2 K1.I09 v1.1 задаёт точность и однозначность выражения смысла. Применимы M5 v1.1 §§4.2 и 6.3, Product Architecture 1.0 с Change 01, C-23/C-34, LU-03.2/03.3, и термины W020–W023 рабочей редакции глоссария от 30.09.2026. В прежнем пакете v2 продуктовый контракт дополнительно задавал место в P00. Аудит S42 проверяет перефразирование в самой вводной. Для принятого решения требуется другой контроль, в котором сведения о стадиях лежат только в документах.

## Реализация

Для создаваемых циклов выбран пакет инструкций v2.1 (версия 2.1.0), с контрактом содержания SPEC.02 версии 1.1.0. Генератор, Tester, Challenger и repair получают одно правило. Значение можно установить по P00 или стартовым M01–M06. Условие и инструкция по сохранению различия в закрытой карте K1.I09 связаны с конкретными доступными источниками. Пакеты v1 и v2 читаются из путей закреплённых в цикле версий.

## Локальная проверка

В контроле по кредитным материалам M01 задаёт условие зачёта, а M05 показывает запись до сверки и момент подтверждения. С заданными положительными вердиктами версия только с документами и версия с перефразированием во вводной допускаются с нулём исправлений. При согласованно адресованной претензии к противоречию в M05 первый допуск даёт FAIL, repair получает претензию, исправленная AS проходит. Тест сверяет также запросы ролей, поля карты, итоговую SHA и текст вводной в представлении участника.

Пройдены 44 адресных теста, 1 382 теста общего офлайн-набора, 240 HTTP-тестов и 13 выбранных интеграционных проверок на отдельной PostgreSQL. В число интеграционных входит переход SPEC.02 → SPEC.03. Наборы частично пересекаются. Живые модельные вызовы — 0. Для оценки точности смысловых вердиктов требуется сопоставление с независимым чтением методолога.
