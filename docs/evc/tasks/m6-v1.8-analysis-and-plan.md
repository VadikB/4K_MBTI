## Предлагаемое устройство M6

Сервис получает frozen C-45 и разрешённые нормативные материалы M2. Адаптер
разрешает ссылки на неизменяемые условия и предъявленный материал; не читает
активный профиль или актуальный prompt вместо сохранённой версии.

Содержательный механизм анализирует весь Dialogue, авторство и доступные условия,
выделяет Fragments/BS, обосновывает атрибуцию по функции/продукту/EP/Boundaries,
строит Simple/Composite Evidence, EB и сопоставление с дескрипторами/RF.
Можно начать с одного структурированного LLM-вызова на AS, сохранив отдельные
стадии в выходе; число вызовов является техническим решением, не нормой M6.
При превышении лимита контекста — явная ошибка либо отдельно проверенная стратегия
обработки, без молчаливого усечения раннего или противоречащего материала.

Детерминированные валидаторы проверяют targets, ссылки, авторство, AS/Turn,
совпадение quote со span, границу материала, полноту обязательных полей и режим.
Они не доказывают семантическую правильность IA: это проверяется экспертными GC.
LLM возвращает проверяемое обоснование результата, а не произвольный балл уверенности.
Итоговый уровень — наивысший дескриптор с обоснованными определяющими признаками;
ни минимум Evidence, ни штраф RF, ни автоматический приоритет позднего ответа не вводятся.

Interim сохраняет ревизию того же EB и неопределённость для PM-04, без IA.
Final допускается после закрытия, сохраняет один логический IA на пару или
отдельную причину отсутствия. Техническая ошибка остаётся ошибкой обработки.
Версия пересчёта не становится независимым наблюдением.

До среднего выполняется содержательный допуск: обоснованность IA, сопоставимость
нормативных версий и условий, самостоятельность, противоречия и требования M7.
Эти решения сохраняются с причинами; равный IndicatorID не заменяет допуск.
Отдельный детерминированный калькулятор выполняет M6.7:

1. Вклад Indicator — среднее допустимых IA разных AS одного Cycle.
2. ComponentScore — среднее допустимых вкладов обязательных Indicators с равным весом.
3. SkillScore — среднее доступных ComponentScores с равным весом, включая частные.
4. L0 участвует как 0; IE и отсутствующие значения исключаются из числового знаменателя,
   но сохраняются в знаменателе покрытия. Нет допустимых значений — нет Score.
5. Полнота определяется обязательным составом M2 и требованиями, без произвольного
   порога покрытия; покрытие сокращённого плана не означает полный конструкт.

Пример синтетической проверки веса: Component A с вкладами 3 и 1 имеет Score 2;
Component B с единственным допустимым вкладом 0 имеет Score 0;
SkillScore=(2+0)/2=1, а не (3+1+0)/3. Если в A отсутствует ещё один обязательный
Indicator, A и Skill остаются частными; недостающее значение не подставляется нулём.

## Артефакты, snapshots и совместимость

Предметные инструкции, правила атрибуции/интерпретации и параметры находятся в
версионируемых файлах; Python содержит типы, технические проверки и расчётные операции.
Пакет связывает каждый rule_id с разделом M6 и нормативными M2 refs. Новый draft
получает loader/validator, публикационный контракт и snapshot; лабораторный manifest
M5 не копируется как будто он уже разрешает официальную публикацию M6.
Снимок исполнения фиксирует M2/M6, prompt, schema, handler, provider/model/parameters,
AS/Dialogue boundary и все checksums. Замена текущего пакета не меняет старый прогон.
Смена механизма создаёт новый прослеживаемый запуск/редакцию, сохраняющий исходные IA.

Предлагается расширить БД отдельными M6 записями, не мигрировать shadow IA в M6:
из старого excerpt нельзя достоверно восстановить Fragments/BS/EB и принадлежность AS.
Таблицы/индексы/FK и совместимость API оформляются до реализации записи.
Задача cycle-session.md содержит историческое разрешение владельца на удаление старых
данных. Для этого плана удаление не требуется; существующая история не переписывается.
Связанный долг: ART-04 (оценивание/prompts) не закрывается целиком новым M6;
ART-05 касается соседнего интервьюера; ART-07 и интерпретация отчётов вне объёма.

## Проверки и критерии готовности

Для будущих backend/артефактных изменений: `git diff --check`, офлайн-проверки
формата/ссылок/checksum/сохранения содержания, затронутые тесты, `npm run test:backend`.
Для хранения, очереди, snapshots, прав и закрытия: дополнительно
`npm run test:backend:http` и `TEST_DATABASE_URL=… npm run test:backend:integration`
только на изолированной БД с test/pytest в имени; команда без настоящего URL
здесь описывает план, не выполненный прогон. Перед merge обязательны CI frontend/pytest.

GC suite охватывает каждый заявленный IndicatorID по L0–L3/IE и соседним уровням,
