# SLS05 — основания отчёта и сопоставимость условий

## Контекст и решение

- База: `main` @ `1adcf798545fcb342a7fe35f8bc3c112a281f0cf`.
- Источники: `P4K_Sales_05_Report.txt`, `P4K.DEV.PRINCIPLES` v1.0,
  M8 v1.2 через действующий Registry, C-67 и рабочий контракт M8 Report.
- Тип находки: дефект проверки оснований и неполная реализация доказательств
  сопоставимости разных Cycle.
- `composition_checksum` остаётся проверкой целостности конкретного Cycle. Для
  сравнения добавляется отдельная неизменяемая проекция семантического состава и
  условий прохождения; отсутствие этой проекции в старом отчёте означает
  `not_confirmed`.
- Описательное утверждение о наблюдении, объяснение и цитата допускаются только с
  непустыми основаниями того же навыка. Summary дословно ссылается на проверенное
  нецитатное утверждение. Контекст профиля не создаёт наблюдение.

## Границы

- Не меняются фактические Results, Score, четыре outcome и методологические нормы.
- Не выполняется автоматическая публикация prompt-пакета и не раскрываются prompts.
- Старые C-67 не перезаписываются и не получают выдуманные условия.
- Рекомендации и признаки прогресса не добавляются.

## Проверка и откат

- Unit: валидные/пустые/чужие основания, владение цитатой, summary, четыре outcome,
  60/120 минут, календарное окно, return policy, старый отчёт без evidence.
- Integration/HTTP и browser — по матрице и CI; provider smoke отмечается отдельно.
- Откат: revert PR. Исторические immutable записи не мигрируются.
