## Контракт выпуска

1. `python -m scripts.plan_specialist_program_release --pilot-battery`
   строит реестр и сверяет исходные контрольные суммы без записи в БД.
2. Тот же lifecycle принимает `--publish-admitted-catalog` с источником
   `--assessment-evidence`. Он сверяет девять контрольных сумм CaseVersion,
   три утверждённые области допуска, ссылку на человеческое ревью, точные версии
   сценария, правил, контракта генерации и пакета рецензентов. Результат —
   производная версия банка 0.7-pilot.1, уникальные CaseVersion с суффиксом
   `-pilot.1` и привязки 1.5.1. Номер каталога по умолчанию 1.3.
   Статус исходников и изолированный каталог 0.7-qa остаются прежними.
3. Создать отдельную конфигурацию с новым каталогом через lifecycle конфигураций.
   Издатель `python -m scripts.publish_assessment_program` принимает новый
   `--pilot-plan-package` после согласования точного плана на этих источниках.
   В принятом payload `release_program` связывает версию, конфигурацию, каталог
   и `source_refs_json`. Исторический `program` остаётся основанием для кода,
   имени, типа назначения и режима. Снимок включает все девять CaseVersion,
   их контрольные суммы и QA-основания, существующие цели и утверждённое время.
   M7 определяет порядок среди применимых кейсов с сохранением принятых целей.
4. Штатное подключение программы применяет новую версию к будущим назначениям.
   Откат выбора — подключение прежней опубликованной версии тем же механизмом.
   Уже закреплённые Cycle продолжают по сохранённым снимкам. Миграции схемы нет.

## Доказательства и границы

Сохранённый обычный Cycle 04: `specialist_pilot@1.2`, `specialist-pilot@1.0`,
промпты v3, `CASE.SPEC.02 v0.6`. M5 вернул INCOMPLETE, карточка не показана.
Архивный `PILOT_PLAN_PREPARATION_SCOPE_MISMATCH` включает операцию со
`status=failed`. Новый результат указывает имена несовпавших полей,
интеграционный контроль M7 использует успешную подготовку.

В офлайн-повторе неизменённых тел SPEC.07 восстановлено 6 строк Tester,
а SPEC.09 — 8 строк адресации и K4.I16 с сокращённым SHA в теле ответа.
Подмена запроса и поздний ответ отклоняются. Отдельный контроль структуры
отклоняет и архивный repair SPEC.07 с массивом строк. У SPEC.04 I06 исходная
ссылка в `События` ведёт в отсутствующее поле, фактическое поле лежит в
`RuntimeBindings`. F03/F04 в SPEC.02 v0.6 локализуют содержательное FAIL
Challenger без изменения сохранённого результата 04.

Архивные 18 вызовов к рецензентам для трёх невалидных кандидатов заняли
222,4 с. Контроль v5 на тех же начальных ответах проверяет ноль вызовов
рецензентов к структурно невалидной AS. Эти числа не измеряют задержку TEST.

Для допуска реального нового назначения требуются подтверждённые
содержательные результаты на точных версиях. Приложенные технические
прогоны 04 и пустая форма методолога эту запись не содержат.
