# M6-A Анализ постановки и план первого PR

02.10.2026. Статус: техническое предложение по запросу «Проведи анализ, предложи план».
Это анализ постановки, не исполнение всех поручений внутри приложенного TXT.
Код, БД, SourceSet, статусы источников и публикация не изменяются.

## Результат анализа

M6 — самостоятельный дополнительный модуль PM-05 внутри приложения, подключаемый
к PM-04 через C-45. Владение прохождением не переносится в M6. Отдельный сетевой
сервис или универсальная библиотека агентов для первого результата не нужны.

Первый реализационный PR — M6-A: сохранённый C-45 → проверенный frozen вход →
Fragment/BS → Evidence/EB → сохранение и восстановление версии разбора одной AS.
В него не входят IA, оценочная неопределённость C-54, Confidence, агрегация, M7
планировщик, C-46/C-56/C-67 и Results/Report. Служебный статус обработки не является C-54.
Даже для handoff в режиме final этот PR строит доказательную цепочку, а не итоговую оценку.

Этот план уточняет последовательность [предыдущего анализа](m6-v1.8-analysis-and-plan.md):
агрегация больше не предлагается первым исполняемым ядром, а IA исключён из первого
вертикального среза. Остальные описанные там нормы M6 и ограничения сохраняются.

## Предлагаемый технический паспорт входа

1. M6 принимает `handoff_id` сохранённого C-45, не произвольный клиентский Dialogue.
   На сервере проверяются авторизация, schema, checksum, AS, режим и граница материала.
   Неподдерживаемая версия отклоняется до внешнего вызова.
2. Текущие cycle_ref/session_ref — DB ID в строках. Адаптер читает только соответствующие
   записи по PK/FK, проверяет принадлежность и ref checksum, сохраняет публичные UUID
   в нормализованном входе. Второй Cycle не создаётся; человек/дата не используются для поиска.
3. Предлагаемый Dialogue ID — стабильный namespaced ID от AS при действующей связи
   один Dialogue на AS. Это техническое решение требует фиксации в контракте;
   идентификатор не создаётся заново при каждом handoff.
4. Material revision адресует boundary_sequence вместе с hash канонического состава
   Turns/events и предъявленного материала. Hash и boundary сохраняются одновременно;
   канонизация использует действующий контракт `m5_case_runtime.canonical_bytes`.
5. Вводная/роль/условия разрешаются из AS snapshot, материалы — из frozen execution
   payload с проверкой checksum и событиями доступности. Скрытый материал остаётся
   описанием сценария, но не приписывается знаниям пользователя. Момент доступности
   начального предъявления также должен быть восстановим.
6. Resolver M2 получает точные цели AS и полный критерий: функцию/продукт, уровни,
   EP/RF/Boundaries, Component/Skill. Проверяются per-target version и версия пакета:
   `m2-competencies-4k/1.1` нельзя молча трактовать как одинаковую версию всех паспортов.
7. В содержательный AI payload идёт разрешённая проекция контекста, а не raw
   profile_snapshot. Права/контакты не смешиваются с предметными условиями.
8. Существующий C-45 v1 не переписывается. Предлагается версионированный PM-05 input
   с адаптером v1; недостающие общие поля следующего C-45 согласовать с владельцем PM-04.
   Неразрешимый обязательный материал означает ошибку, а не реконструкцию по текущему Case.
9. Interim допускается только по разрешённой открытой границе; final — после закрытия
   общим runtime. PM-05 не переопределяет terminated в closed самостоятельно.

Полный C-54 резервируется для задачи 4 очереди: AS/Indicator/M2/EB revision,
обработанная граница, подтверждённые основания, неопределённость и её влияние,
либо финальный IA/причина отсутствия. В M6-A наружу возвращается только processing
status и ref сохранённого разбора; это не оценочный ответ C-54.

## Минимальная модель хранения и AI

Предлагаются отдельные записи request, attempt, analysis revision и bundle identity/revision.
Fragment/BS/Evidence могут храниться в валидированном неизменяемом JSON одной analysis
revision с адресуемыми ID; отдельная таблица на каждое понятие пока не обязательна.
EB имеет стабильную идентичность AS×Indicator; принятую ревизию нельзя перезаписать.
Связи между AS, request и bundle защищаются FK/unique и проверкой принадлежности.
Следующая задача добавляет IA, не меняя смысл существующих Evidence/EB.

Request фиксирует режим, handoff/material hash, mechanism/input snapshot/hash и idempotency
key. Тот же ключ с другим payload даёт конфликт. Дедупликация принятого эффекта также
проверяет AS+режим+material hash+mechanism hash, чтобы новый транспортный ключ не удвоил
тот же результат. Attempt — отдельная внешняя попытка; ошибка допускает повтор в рамках
request, не создаёт EB-результат или оценочный исход. Изменённый вход/механизм создаёт
новую обработку с историей, а не независимое наблюдение пользователя.

Существующий `execute_frozen_ai_json` полезен транспортом и trace, но читает prompt
из текущего `prompts/<name>/v1`. Смена файла сейчас вызывает mismatch; это защита от
подмены, но не независимое исполнение старого снимка. Для M6 предлагается минимально
выделить/адаптировать технический вызов для prompt из проверенного immutable snapshot,
сохранив существующий gateway и проверку отправленной конфигурации. M5 потребители
требуют регрессии, если общий helper меняется. Универсальный агентный framework не нужен.

Предлагаемый пакет `assessment_definitions/prompts/m6_evidence/v1/` содержит prompt,
manifest и необходимые нормативные ссылки; поддерживаемая схема/статусы и loader
сначала описываются в задаче 1. Существующий файловый контур сохраняется, однако
M5 laboratory-only manifest не объявляется допуском официального M6 автоматически.
Нормативные инструкции не встраиваются в Python. Снимок фиксирует текст, источники,
schema/handler, provider/model/parameters; секреты в снимок не входят.

## Карточка первого реализационного PR

Название: M6-A — доказательная цепочка одной AS из сохранённого C-45.
Предполагаемые новые пути: `Api/m6_contracts.py`, `Api/m6_input_resolver.py`,
`Api/m6_evidence_service.py`, `Api/m6_repository.py`, пакет prompt и
`tests/unit/test_m6_evidence.py`, `tests/integration/test_m6_evidence_db.py`,
`tests/e2e/test_m6_evidence_http.py`. Изменяемые точки: `Api/routes.py`, schema setup
в `Api/database.py`, технический AI helper только в необходимой части.
Названия предварительные; текущие M5 таблицы и shadow не переименовываются.

Вход: авторизованный запрос на обработку существующего handoff и выбранный закреплённый
механизм. Выход: request ID/status, analysis revision ref и разрешённая доказательная
цепочка. Точка вызова: отдельное действие существующего административного QA-контура,
которое вызывает тот же PM-05 service, что впоследствии основной runtime.
Новый Prompt Lab не нужен. Controlled adapter доступен только тестам; runtime использует
реальный AI adapter, а статус QA не превращается в пользовательский допуск.

Миграция: добавление таблиц и индексов M6; без TRUNCATE, массового backfill и выдачи
старых shadow-результатов за M6. Перед записью — согласованный schema/rollback план.
LLM вызывается без удержания транзакции; короткие транзакции фиксируют request/claim
и затем атомарный принятый эффект. Для recovery используются lease/повторы с проверкой
идемпотентности; существующая очередь переиспользуется только после адресной проверки
её привязок к legacy session, без предположения о готовой совместимости.

Приёмка: T-A1–T-A7 из TXT — ссылки/schema/checksum; точные spans и авторство;
пустой EB; повтор/сбой/конфликт; неизменяемый replay; технические ошибки; PostgreSQL
read-back и права HTTP. T-A8 — отдельный синтетический smoke реального provider,
с точной конфигурацией и фактическим статусом. Пропущенный smoke — NOT_RUN.
Семантическая правильность цепочки проверяется на независимо утверждённых ожиданиях;
успешная JSON-валидация её не доказывает.

## Решения, проверки и передача

Принято пользователем в разговоре: M6 — дополнительный самостоятельный модуль.
Остальные конкретные схемы выше — предложения, не присвоенное агентом человеческое
утверждение. Общая повторная актуализация M1 и разрешение «начинать изучение M6» не нужны.
Перед реализацией требуется принять ограничение M6-A и контракт расширения хранения/
артефакта. Назначение одного владельца Evidence/EB согласуется с общей основой.

Стоп-условия текущего анализа: изменения смысла/публичного API/схемы/данных/передачи/
деплоя нет; новый контур только предложен; откат документа определён; область соблюдена.
Для будущей реализации неполученные решения по схеме и артефакту блокируют только
зависимую запись/loader. Пробелы источников и runtime ограничены выше, не являются
общим запретом проектирования. Управляющие документы не изменялись.
