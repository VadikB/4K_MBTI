Решение: адресная сервисная процедура «подготовить кандидата → опубликовать» с обязательной причиной, ссылкой на установленную ошибку, ожидаемым report_id, типом источника и idempotency key. Проверка кандидата следует существующему M8 descriptive validator и M6/C-56 provenance. Публикация в транзакции с блокировкой Cycle создаёт новую неизменяемую C-67, запись аудита и переключает указатель. Owner/admin получают только публичную проекцию разницы с теми же правами, что REPORT-02. Экран до резюме показывает дату, причину и только изменённые поля. Сервисная подготовка обращается к действующему M8 semantic validator для содержательного текста. Недоступность или отклонение блокирует только публикацию этого кандидата; в тестах подставляется детерминированный gateway. Дополнительный runtime prompt или встроенная норма не вводятся.

Проверки: unit, HTTP, изолированная PostgreSQL с `pytest` в имени БД, browser 1440/390, сборка, lint, `git diff --check`, CI точного head. Fixtures синтетические, LLM и письма не вызываются.
