# M7 · Применимость и покрытие v0.6

Для опубликованной версии программы условие допуска задаётся закреплённой политикой маршрута. У кандидата `specialist_pilot@2.1` порог — **39 уникальных IndicatorID**, обязательны все 39 идентификаторов опубликованного замысла. Полная матрица M2 содержит 61 цель. Замеры ниже показывают запланированные возможности по паспортам банка `0.9`, до действий участника и расчётов M6.

| Сценарий | Пересчитанный порядок | Цели | Решение по требованиям программы |
| --- | --- | ---: | --- |
| Обычный профиль подходит для .02 | .02 → .03 → .04 → .07 → .05 → .01 → .06 → .08 | 39 | Маршрут удовлетворяет условию охвата. |
| .02 и .09 исключены по профилю | .03 → .04 → .07 → .05 → .01 → .06 → .08 | 30 | Подготовка останавливается. Недоступны `K1.I06`, `K1.I09`, `K4.I03`, `K4.I05`, `K4.I12`, `K4.I13`, `K4.I14`, `K4.I16`, `K4.I17`. |
| .02 исключён, .09 подходит по профилю | .03 → .04 → .07 → .05 → .09 → .06 → .01 → .08 | 32 | Подготовка останавливается. .09 возвращает `K4.I12` и `K4.I16`. Недоступны `K1.I06`, `K1.I09`, `K4.I03`, `K4.I05`, `K4.I13`, `K4.I14`, `K4.I17`. |

Три маршрута пересчитаны кодом M7 по целям и времени из полного банка. В проверке подставлены управляемые исходы применимости, отдельно от прогона генерации на рабочем провайдере. Серверный код остановки — `PILOT_PLAN_PROGRAM_COVERAGE_UNAVAILABLE`. Ответ участнику `ASSESSMENT_PROGRAM_COVERAGE_UNAVAILABLE` показывает доступное и требуемое число целей. Внутренняя квитанция содержит список недоступных обязательных целей, версии и причины исключения. Пониженный порог допускается только по отдельной закреплённой политике программы. В регрессии проверены минимальное число и обязательные идентификаторы.

До генерации кандидат ссылается на закреплённые ответы о работе, решениях и ограничениях. Рабочий провайдер классифицирует каждое условие, а сервер проверяет дословную выдержку и допустимое поле источника и выводит итог из критериев. Явное противоречие даёт статус `incompatible`. Нехватка предметных сведений даёт `clarification_required`, даже когда заполнено поле о рабочих задачах. Полное подтверждение даёт `applicable`. При нехватке данных экран остановки задаёт один предметный вопрос, если ответ может восстановить обещанный охват. Текущий W02 фиксирует подтверждённые ответы и не имеет действия для дополнения закреплённого профиля из экрана подготовки. Решение и выдержки доступны серверной проверке, а участнику показываются итог, причина или вопрос. PM-03 сверяет квитанцию с выбранным источником и профилем перед генерацией.

Сохранение закреплённых источников старых Cycle проверено отдельно. В изолированной PostgreSQL существующий запущенный Cycle дал то же состояние до публикации программы 2.0, после подключения программы и при повторном штатном запуске публикации. Исходный SHA планировщика для 2.0 проверен по `4b1154e5b8f6277bc19faaf34638d6ae0b59adbb`. Штатная публикация 2.0 воспроизвела обе ожидаемые проекции маршрута.
