# Выбор версии RoleProfile пользователем

## Результат

Авторизованный пользователь может получить доступные ему опубликованные
RoleProfiles 1.1 и выбрать конкретную версию. Выбор хранится отдельно от
legacy `users.role_id`.

## Область

- Включено: `users.selected_role_profile_version_id`, HTTP-контракт чтения и
  выбора, проверка членства в организации, интеграционный и HTTP-тесты.
- Не входит: изменение формы профиля, публикация ролей, использование выбранной
  роли при подборе кейсов, удаление legacy-ролей и данных.

## Контекст и решение

- M3 допускает дополнительные RoleProfiles для конкретной организации;
  выборка не должна ограничиваться шестью BaseRoles.
- `GET /users/role-profiles/available` возвращает опубликованные BaseRoles и
  только версии активных организаций, участником которых является пользователь.
- `PUT /users/role-profiles/selection` принимает `version_id` и не меняет
  опубликованное определение, профиль пользователя или существующие сессии.
- `POST /users/admin/organizations/{organization_id}/role-profiles/drafts`
  позволяет администратору своей организации создать дополнительный черновик.
  Опубликовать его этим endpoint нельзя.
- M3 не задаёт применимость кейсов к роли и покрытие Indicators. Текущий подбор
  зависит от `role_skills` и `case_registry_roles`; он не переносится в 1.1
  без правил M5/M7.

## Критерии приёмки

- [x] Оба endpoint требуют действующую пользовательскую сессию.
- [x] Нельзя выбрать draft, retired или роль чужой организации.
- [x] Дополнительная опубликованная роль появляется только у участников своей организации.
- [x] Администратор не может создать черновик роли в чужой организации.
- [x] Выбор не перезаписывает `users.role_id` и не меняет старые сессии.
- [x] При отсутствии иного выбора список не ломается.

## Проверка и откат

- HTTP-контракт проверяется через FastAPI `TestClient`.
- Запись и ограничения доступа проверяются на изолированной PostgreSQL.
- Откат: убрать endpoint, сервисный выбор и nullable колонку. Если значения
  колонки уже заполнены, предварительно сохранить их в резервной копии.
