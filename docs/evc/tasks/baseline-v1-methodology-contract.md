# Контракт методологии baseline 1

## Результат

Пользователь видит три роли методологии 1.0 при заполнении профиля, а роли и
уровни входят в неизменяемый снимок исполнения оценки.

## Область

- Включено: роли и уровни методологии 1.0, их валидация, совместимая проекция
  ролей в существующий справочник `roles`, тесты контракта.
- Не входит: методология 1.1, пять новых ролей, импорт отсутствующих навыков,
  кейсов и профилей промптов, изменение алгоритмов оценивания.

## Контекст

- Значимые точки входа: `Api/assessment_configuration.py`, `Api/agent.py`,
  `Api/database.py`.
- Архитектура: `docs/architecture/assessment-runtime.md`.
- Существующие тесты: `tests/unit/test_assessment_configuration.py`,
  `tests/integration/test_assessment_authoring_workflow_db.py`.

## Ограничения и риски

- Совместимость: числовой `role_id` сохраняется для действующего API и связей БД.
- Данные и миграции: опубликованная версия в БД не изменяется; для старой версии
  1 используется детерминированное дополнение снимка контрактом legacy 1.0.
- Безопасность и персональные данные: изменение не читает пользовательские данные.
- Внешние сервисы/LLM: вызовы отсутствуют.
- Эксплуатация: роли материализуются идемпотентно при инициализации схемы.

## Критерии приёмки

- [ ] Методология 1.0 содержит ровно три роли и уровни `L1`, `L2`, `L3`.
- [ ] Дублирующиеся или неполные роли/уровни отклоняются валидатором.
- [ ] Чистая БД получает три роли из контракта методологии.
- [ ] Snapshot legacy-сессии содержит роли и уровни даже после обновления старой БД.
- [ ] Существующие публичные поля `role_options[].id/code/name/description` сохранены.

## План проверки

- Модульные тесты: структура и нормализация контракта.
- Интеграция/HTTP: инициализация legacy-конфигурации и загрузка snapshot.
- Ручная проверка/test-среда: открыть профиль оценки и увидеть три роли.
- Наблюдаемость: техническая регрессия `data_roles` должна пройти.

## Откат

Откатить коммит приложения. Добавленные строки справочника ролей совместимы со
старым кодом и могут быть оставлены; удалять их при наличии ссылок пользователей
нельзя.

## Передача результата агентом

- Принятые решения: заполняется контракт legacy 1.0 без изменения опубликованной
  записи; реляционный справочник остаётся совместимой проекцией.
- Известные пробелы: полный запуск требует отдельного канонического пакета
  skills/cases/prompts.
