# UX-F01 — защита новой сессии от запоздалого 401

Дата: 06.10.2026. Статус: **технически готово; браузерная приёмка ожидает
изолированный стенд**. Выполнен только UX-F01. UX-F02 и UX-02 не запускались.

## Результат

Запросы frontend теперь получают поколение сессии в момент отправки. Ответ
обрабатывается только пока это поколение остаётся текущим. Поэтому поздний 401
старой сессии не запускает recovery новой сессии, а поздний успешный ответ не
возвращает данные для записи в состояние нового аккаунта. Несколько 401 текущего
поколения по-прежнему объединяются в один recovery.

Смена сессии после успешного входа и явного выхода публикуется через
`BroadcastChannel` без user ID, cookie или токенов. Другая вкладка инвалидирует
свои начатые запросы и локально очищает прежнего владельца. Recovery по 401 больше
не вызывает server logout: отозвать shared-cookie сессию может только явный выход.

## Техническое решение

`web/js/api.js` хранит монотонное поколение сессии и `WeakMap` поколений
`Response`. Установленный один раз fetch-adapter фиксирует поколение до сетевого
ожидания. `readApiResponse` отклоняет устаревший 401 и устаревший 2xx через
`StaleApiResponseError`; текущие ответы сохраняют прежний контракт.

Recovery хранит поколение, поэтому незавершённый recovery A не подавляет новый
recovery актуального поколения B. Перед ленивым reset чата поколение проверяется
повторно: завершение старого dynamic import не очищает уже вошедшего пользователя.
Успешный login повышает поколение и уведомляет вкладки; boot/restore повышают его
только локально, чтобы открытие вкладки само по себе не сбрасывало соседнюю.

## Риски, откат и передача

Публичный backend/API и cookie semantics не менялись. Канал передаёт только тип
события, без идентификаторов и секретов. Старые ответы, которые обходят
`readApiResponse`, не получают этот gate; затронутый auth/protected flow использует
единый reader, а двухвкладочная регрессия остаётся обязательной на стенде.

Откат — revert локального commit UX-F01 и повторная штатная сборка `web/dist`;
миграций и изменений данных нет. Для окончательной приёмки передать изолированный
`STAND_ADMIN_URL`, выполнить добавленный browser test и затем полный обязательный
CI. После этого отчёта остановиться; UX-F02 и UX-02 не запускать.
