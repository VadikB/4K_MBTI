# CONTRIBUTING-MERGE-AUTH-01 — следующий PATCH при поручении на merge

Дата: 17.11.2026. Отдельная явно согласованная задача изменения управляющего
документа; принимается отдельным PR от продуктового POSTW02-04.

Основание — прямые сообщения владельца в текущем чате: «сливай на main», затем
«обновляй contributing» после остановки на повторном согласовании PATCH и предложения
считать необходимый PATCH частью порученного merge. Идентификаторы сообщений
недоступны. Вложения задачи описывают требования продукта, а не полномочия публикации.

## Результат и границы

В CONTRIBUTING явно задано: допуск на merge текущего результата включает необходимые
push/PR, следующий PATCH от свежего main, Ready, обязательный CI, squash merge и
штатный deploy на test. Тип MINOR/MAJOR и конкретный номер, если задан владельцем,
не выбираются вместо его решения. Более узкие прямые ограничения сохраняются.
Без допуска на merge обычная локальная работа и draft PR версию не поднимают.

branch_push=true, pr=true, merge=true, deploy=test автоматически после merge;
version_bump=false для этого документального PR, artifact_publish=false.
Внутри продуктового merge этапа разрешён следующий PATCH, что фиксируется отдельно
в карточке продуктовой задачи. Pilot/production, реальные LLM/письма, данные и
публикация предметных сущностей не входят в эту задачу.

Обязательные CI/review/release gate/актуальная база сохранены. Скрипты, workflows,
ruleset, runtime и методология не меняются. Исторические подтверждения не переписаны;
новое решение добавлено в реестр отдельной строкой.

## Основания и проверки

Прочитаны AGENTS.md, README.md, CONTRIBUTING.md, docs/evc/agent-workflow.md
(полномочия этапа и отдельные задачи/PR), verification-matrix.md,
decision-register.md, scripts/prepare_ready_release.py и check_release_version.py.
Флагам сохраняется отдельный учёт; одно поручение может разрешать необходимые
операции этапа согласно существующему рабочему циклу.

Локальный минимум: проверка diff, локальных ссылок и существования описанных команд,
содержательное review на противоречия. Перед merge — обязательные frontend, pytest
и full-verification на точном head. Результаты CI и merge фиксируются во внешней
передаче после фактического выполнения, а не объявляются заранее.

Откат: revert отдельного squash commit этого PR. POSTW02-04 проходит отдельный
release preflight и обязательные проверки после объединения со свежим main.
