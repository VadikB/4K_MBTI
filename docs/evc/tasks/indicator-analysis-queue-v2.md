# Подключение индикаторной оценки v2 к очереди анализа

## Результат

Сессия с замороженной методологией schema v2 исполняет четыре индикаторных оценщика из своего снимка и сохраняет результаты v2, не обращаясь к изменяемой текущей методологии.

## Область

- Включено: диспетчеризация по schema version, проверка frozen AgentDefinition, сбор материалов, LLM-вызов и сохранение Indicator results.
- Не входит: агрегация индикаторов в отчёт, включение kill switch на контурах, удаление данных и артефактов 1.0.

## Контекст

- Точки входа: `Api/assessment_analysis_queue.py`, `Api/assessment_indicator_material_repository.py`.
- Контракты: evaluator input/output v2, неизменяемый execution snapshot.

## Ограничения и риски

- Совместимость: schema v1 продолжает исполняться прежней веткой.
- Данные: v2 пишет только в `session_indicator_assessments` и `session_case_indicator_evidence`.
- Безопасность: проверяются checksum, версия, executor и границы ссылок Evidence.
- LLM: требуется `ASSESSMENT_UNIVERSAL_LLM_ENABLED=true`; fallback запрещён.

## Критерии приёмки

- [x] schema v2 не вызывает legacy evaluator.
- [x] Агент и нормативный материал читаются из снимка сессии.
- [x] Перед сетевым вызовом транзакция с загруженными материалами фиксируется обновлением progress.
- [x] Сбой официальной v2-оценки переводит job в штатный retry/failure flow.

## План проверки

- Модульные тесты: маршрутизация v1/v2, kill switch, frozen agent validation, сохранение результата.
- Интеграция: изолированная PostgreSQL через `TEST_DATABASE_URL`.
- Реальный LLM: не входит в стандартные тесты.

## Откат

Выключить `ASSESSMENT_UNIVERSAL_LLM_ENABLED`; новые v2 job завершатся контролируемой ошибкой, v1 останется работоспособной. Сохранённые v2 результаты не удаляются.
