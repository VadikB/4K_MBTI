# UX-FIX20-02 — изоляция несохранённого ввода управления

## Основание и границы

- Пакет владельца: `P4K_UX_Fixes_2026-10-20`, задача `UX-FIX20-02`.
- База реализации: squash-коммит UX-FIX20-01 `d17d1c4288503e0d9b771adc0192af40f36fa5c7`.
- Прочитаны: `README.md`, `CONTRIBUTING.md`, `docs/evc/agent-workflow.md`,
  `docs/evc/verification-matrix.md`, `docs/evc/artifact-recipe.md`,
  `docs/architecture/product-4k/1.0/context.md`, `docs/architecture/product-4k/registry.md`,
  Change 01, manifest набора источников, ADR-002 и карта traceability.
- Методология, API и схема БД не меняются. Черновики остаются только в памяти вкладки;
  публикация, приглашения и загрузка анкеты навигацией не запускаются.

## Решение

- Поля сохраняются по устойчивым `name` и ключу `user_id → organization_id → assessment_ref → form`.
- Общие данные организации, участники и assessment-scoped формы разделены.
- Переключение трёх подразделов и возврат из личного маршрута восстанавливают только
  разрешённую область текущей сессии.
- `clearAssessmentContext` очищает черновики, previews, revisions и выбранные области.
  Ответы старого `identityEpoch` не применяются.
- Исчезнувшая из серверного ответа организация удаляется из вкладочного состояния.
- `File` не восстанавливается по имени: после перерисовки требуется реальный повторный выбор.

## Проверка и откат

- Browser-регрессии покрывают переходы, участника, получателей, две подготовки,
  `A → logout → B` и поздний preview A.
- Полный фактический набор команд и PASS/FAIL фиксируется в PR.
- Откат: revert PR; миграция и восстановление данных не требуются.
