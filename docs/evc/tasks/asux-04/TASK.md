## Решение

PM-03/LU-03.2–03.3 готовит и допускает AS согласно C-34. После закрытия AS
штатный обработчик ставит команду в существующую очередь с ключом от закрытой
AS. Повтор после потери квитанции адресуется по исходному ключу. Разрешённый
повтор технической ошибки использует тот же ключ выбора маршрута и отдельную
квитанцию попытки. Окончательный отказ сохраняет публичную причину из #253.

PM-04/LU-04.2 и LU-04.6 читает готовность из сохранённого допуска и
предъявляет AS отдельной командой `POST /assessment/m7/cycles/{cycle_id}/present-next`.
Команда содержит ID допущенной AS и ожидаемую редакцию плана. Сервер проверяет
владельца, организацию и назначение, открытый сбор, оба времени и редакцию
маршрута. Повтор для той же активной AS возвращает сохранённое предъявление.
До клика работает пауза между ситуациями. При истечении срока закрывается
указанный Cycle. Последняя позиция закрывает сбор после сохранения ответов.

## Совместимость и откат

Используются существующие строки очереди, снимки AS, решения маршрута и
интервалы M7. Уже предъявленные AS читаются в сохранённом статусе. Для старых
отказов без детальной причины предусмотрен безопасный общий текст.
Изменение не требует миграции. Перед полным откатом нужно дать участникам
открыть уже допущенные AS и дождаться обработки очереди между ситуациями.
На переходный период обработчик `present-next` должен оставаться доступным
для записей `admitted` с пустым `presented_at`. После сверки выполняется revert
продуктового коммита с пересборкой frontend.

## Проверки

Сценарии 04.1–04.5, проверенный SHA и результаты обязательного CI фиксируются
в разделе «Проверка» PR. Используются изолированный PostgreSQL, реальные
HTTP-маршруты, синтетический gateway и Chromium. Для визуальной сверки
применяется вложенный HTML с тремя сценами на 1440 и 390 px.
