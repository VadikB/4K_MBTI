# Версионируемое хранение RoleProfile для методологии 4К 1.1

## Результат

Базовые и дополнительные организационные RoleProfiles хранятся отдельными
версиями. Опубликованная версия неизменяема; конкретная версия и её содержимое
могут быть зафиксированы в снимке сессии 1.1.

## Область

- Включено: таблицы версий, импорт шести BaseRoles как draft, создание
  организационного draft с происхождением, выборка доступных участнику
  опубликованных ролей, фиксация версии в снимке сессии.
- Не входит: UI создания и публикация ролей, переключение legacy выбора,
  подбор кейсов по М3, удаление старых данных, публикация конфигурации 1.1.

## Контекст и ограничения

- Источники: draft-пакет `assessment_definitions/role_profiles/competencies_4k/1.1`.
- Существующий runtime подбирает кейсы через `user.role_id`, `role_skills` и
  `case_registry_roles`; переключение этого пути выполняется отдельным шагом.
- Шесть BaseRoles не являются закрытым enum: опубликованный RoleProfile с
  `scope=organization` виден только участникам своей активной организации. Он может ссылаться на
  опубликованный BaseRole или быть сформирован без такого основания.
- Привязка к сессии разрешена только для опубликованной роли и снимка
  методологии 1.1. Снимок содержит полное определение и checksum.
- Опубликованные методология 1.0 и её роль-ссылки не изменяются этим шагом.

## Критерии приёмки

- [x] Повторный импорт одного пакета возвращает те же версии без перезаписи.
- [x] Изменённый опубликованный RoleProfile отклоняется на уровне БД.
- [x] Организационная роль не показывается участнику другой организации.
- [x] Версия роли и её содержимое фиксируются в execution snapshot с checksum.
- [x] Старые сессии и роли не мигрируют автоматически.

## Проверка и откат

- Интеграционный тест использует только изолированную базу с `test`/`pytest` в имени.
- Перед PR: `npm run lint:js`, `npm run build:web`, `npm run test:backend`,
  `git diff --check`.
- До заполнения таблиц откат состоит в удалении новых таблиц, колонки сессии и
  сервиса. После публикации версий удаление требует резервной копии и отдельной
  миграции.
