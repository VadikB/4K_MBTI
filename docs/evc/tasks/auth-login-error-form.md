# Отказ при входе сохраняет форму и сообщение

## Результат и область

При отказе проверки пароля или одноразового токена интерфейс сохраняет форму
учётных данных и показывает ответ сервера. Восстановление просроченной сессии
по 401 защищённых API продолжает работать. Изменение не затрагивает пароли,
cookie, базу и правила авторизации.

## Контекст и решение

Пользователь сообщил о возврате к email после ввода сохранённого пароля на test
2.1.27. `readApiResponse` запускал общий сброс состояния на любой 401, включая
ответ password-login. Причина конкретного отказа пользователя пока не наблюдалась.
Архитектура: `docs/adr/001-assessment-platform-architecture.md` и
`docs/architecture/assessment-runtime.md`. Тикет не указан.

Решение: публичный обработчик ответа получает совместимый необязательный параметр
`recoverUnauthorized`, по умолчанию true. Проверка токена и пароля передаёт false;
исключение со статусом и текстом сервера сохраняется.

## Критерии приёмки и план

1. Регрессионный frontend-тест: неверный пароль не вызывает восстановление
   сессии и сохраняет текст ошибки; существующие тесты защищённых API проходят.
2. lint, build, backend и diff-check; HTTP smoke для контрактов.
3. После штатного CI/deploy-test пользователь повторяет вход самостоятельно:
   введённые данные не читаются агентом. Ошибка остаётся видна в форме.

## Ограничения и откат

Секреты и персональные данные не используются для диагностики. Реальная попытка
входа требует действия пользователя. Миграций и новых переменных нет.
Откат — предыдущая версия приложения штатным процессом, без изменения данных.
