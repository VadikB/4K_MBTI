# TGBOT-01: сервисная связь участника Telegram-бота с пользователем 4К

## Результат

Telegram-бот по Bearer-токену идемпотентно получает внутренний `agent4k_user_id`
по нормализованному email. Если пользователь отсутствует, создаётся минимальная
строка `users` без пароля, web-сессии, профиля, роли и членства в организации.

## Область

- Включено: `POST /integration/v1/participants/resolve`, сервисная авторизация,
  поиск/создание пользователя, конфигурация и unit/HTTP-контрактные тесты.
- Не входит: подтверждение владения email, Telegram ID в 4К, организация,
  PersonalizedProfile, Assessment Cycle, Case, Results и изменение бота.

## Контекст

- Основание: решения владельца от 06.11.2026 — допустить email студента и сначала
  реализовать его как технический мост к существующей модели 4К.
- Base SHA: `e9639edef400e2c36425f0d1c3ca98b646fdb0c2`.
- Архитектурный адрес: техническая identity/admission-граница перед PM-02; PM-03–07
  и предметные артефакты не меняются.
- Владелец `users`: 4К; потребитель внутреннего ID: Telegram-бот.

## Источники и решения

- Прочитаны `README.md`, `CONTRIBUTING.md`, EVC workflow/matrix/artifact recipe,
  Product 4K context/registry, Change 01 + manifest, ADR-002, traceability и
  действующие `Api/auth_service.py`, `Api/config.py`, `Api/database.py`, routes/tests.
- Новый пользователь не считается подтвердившим email. Endpoint не создаёт
  `user_identities` и не обходит штатную magic-link-верификацию.
- Существующий пользователь не изменяется; переданное имя используется только
  при создании минимальной строки.
- `TG_BOT_INTEGRATION_TOKEN` — отдельный секрет не короче 32 символов; пустое или
  короткое значение закрывает endpoint.
  Токен и email не выводятся в application logs и ответ.
- Публичный API расширяется аддитивно; схема БД не меняется.

- Следующий шаг: после приёмки — клиент endpoint и сохранение ID в Telegram-боте.

## Ограничения и риски

- Совместимость: endpoint новый, существующие auth-сценарии не меняются.
- Данные: создаётся минимальная строка `users`; откат кода не удаляет пользователя.
- Безопасность: один ротируемый сервисный токен; TLS обязателен на внешнем контуре.
- Персональные данные: email используется в запросе и БД, но не возвращается.

## Критерии приёмки

- [x] Пустой или короткий конфигурационный токен закрывает endpoint.
- [x] Отсутствующий/неверный Bearer-токен получает 401.
- [x] Email нормализуется штатной функцией 4К.
- [x] Повторный запрос возвращает существующий ID и не меняет профиль.
- [x] Новый пользователь не получает identity, роль, профиль, организацию или сессию.
- [x] Ответ не содержит email или Telegram ID.

## Откат

Удалить маршрут из приложения и очистить `TG_BOT_INTEGRATION_TOKEN`. Созданные строки
не удалять автоматически: они могут быть подтверждены или использованы независимо.
