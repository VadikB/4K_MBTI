# Совместимость frontend-модулей при deploy

## Результат

Открытая до deploy вкладка может после обновления динамически загрузить модуль
предыдущей frontend-сборки и не получает ошибку `Failed to fetch dynamically
imported module`.

## Область

- Включено: test deploy, сохранение предыдущих content-addressed файлов
  `web/dist` и их очистка по сроку хранения.
- Не входит: изменение экранов, API, методологии, БД и пользовательских данных.

## Контекст

Entry point `main.js` загружается без кеширования, но уже открытая вкладка может
держать его предыдущую версию в памяти. Старый entry point продолжает ссылаться
на hashed chunk, который прежний deploy удалял.

## Критерии приёмки

- [x] Новый `main.js` не заменяется файлом предыдущей сборки.
- [x] Отсутствующие hashed chunks предыдущей сборки сохраняются.
- [x] Файлы старше 14 дней удаляются.
- [ ] CI и deploy-test проходят.
- [ ] Старый и новый URL модулей доступны после deploy.

## Проверка

- Unit-тест retention-скрипта.
- `sh -n` для обоих deploy-скриптов.
- Обязательные frontend/backend проверки проекта.
- HTTP-проверка старого и нового hashed URL после deploy.

## Откат

Отменить commit. Изменение не затрагивает БД; сохранённые старые chunks можно
удалить следующим штатным deploy.
