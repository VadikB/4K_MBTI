# Файловые AgentDefinition для методологии 1.1

## Результат

Четыре оценщика компетенций методологии 1.1 представлены версионированными файловыми AgentDefinition, используют общий протокол индикаторной оценки и проверяются до публикации.

## Область

- Включено: общий Markdown-протокол, четыре AgentDefinition, executor v2, контракты v2, контрольные суммы в manifest, проверка совместимости публикации.
- Не входит: публикация сущностей в БД, переключение production-конфигурации, удаление методологии 1.0, запуск LLM из очереди.

## Контекст

- Значимые точки входа: `Api/assessment_agent_definitions.py`, `Api/assessment_authoring_service.py`, `scripts/build_methodology_1_1_package.py`.
- Существующие контракты: `competency_evaluation_input` v2 и `competency_evaluation_output` v2.

## Ограничения и риски

- Совместимость: проверки schema v1 сохранены; schema v2 не требует ролей.
- Данные и миграции: изменение схемы БД отсутствует.
- Безопасность и персональные данные: протокол запрещает домыслы и разрешает только Evidence из снимка исполнения.
- Внешние сервисы/LLM: реальные вызовы не выполняются.

## Критерии приёмки

- [x] Каждый из K1–K4 ссылается на отдельный AgentDefinition и executor v2.
- [x] Инструкции вынесены в единый Markdown-файл и разворачиваются при загрузке.
- [x] Manifest покрывает SHA-256 всех файлов агентов.
- [x] Публикационная проверка требует universal runtime и контракты/executor v2.

## План проверки

- Модульные тесты: загрузка файлов, валидация агентов, методологии и bundle, manifest.
- Интеграция/HTTP: не требуется до реализации публикации файлов в БД.
- Наблюдаемость: без изменений.

## Откат

Удалить каталог `agents`, ссылки `agent_definition` из draft-пакета и регистрацию executor v2. Опубликованные версии не изменяются.
