F02: удалять человека и аккаунт из текущего списка

Команда «Удалить человека» теперь запускает существующее полное удаление аккаунта
и зависимостей через preview/fingerprint и идемпотентную квитанцию. Она доступна
из текущих списков; участник с правами администратора удаляется вместе с обеими
функциями. «Снять права» остаётся отдельным действием.

Администратор организации может удалить только своего допустимого участника,
после серверной проверки и блокировки всей области данных. Защищены текущий
аккаунт, последний администратор, configured primary/verified alias и чужие
данные; закрыт обход защиты configured человека через organization purge.
Успешная серверная квитанция сохраняет смысл при сбое localStorage; потерянный
ответ после commit восстанавливается по прежнему operation_id. Авторизация
сериализована с purge, старые токены не переживают удаление/повторное добавление.

Удалены пользовательские списки исключённых/отвязанных и восстановление.
Прежний DELETE members возвращает410 без изменений. Существующие inactive
memberships автоматически не мигрируются: [адресный план](LEGACY-TRANSITION.md).
Схема receipt получает nullable numeric actor_user_id без FK на удаляемого
человека; внешний ledger остаётся обезличенным, формат не меняется. Старые
receipt без actor доступны для replay только суперадминистратору.

Задача: [TASK.md](TASK.md). Проверки, точный code SHA и ограничения:
[CHECKS.md](CHECKS.md). Состояние: [STATE.md](STATE.md).

Риск совместимости: прежние клиенты исключения должны обновиться вместе с UI.
Удаление необратимо. Откат = revert кода для новых команд; удалённые данные не
восстанавливаются. Backup restore по-прежнему требует replay внешнего ledger.
Массовая миграция, предметная публикация, почта, платный LLM и пользовательские
данные в этом изменении не используются. Owner visual PENDING.
