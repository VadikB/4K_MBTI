F02 — Удаление человека и его аккаунта
Версия постановки 1.0 / 11.11.2026. Это задание на последующее исполнение; сейчас код не изменён.
Тип: новое явно заданное поведение вместо прежнего exclude/retain. Существующий дефект квитанции R01 включён в эту функцию.

ТРЕБУЕМЫЙ РЕЗУЛЬТАТ
«Удалить человека» после подтверждённого успеха означает, что его аккаунта и доступа больше нет. Не должно оставаться исключённого или отвязанного аккаунта для восстановления, списка исключённых, кнопки «Вернуть» или требования предварительно удалить организацию.

«Снять права администратора» — отдельное действие. Оно не называется удалением человека.

ВОССТАНОВЛЕННОЕ ОСНОВАНИЕ
Решение владельца от 11.11, пункты 4–5, имеет приоритет над прежними COM D01/SUP01–06 и FIX02 F01/F02. Api/routes.py:5124–5179, 5281–5418; scripts/purge_test_organization.py; web/js/api.js:262–381; UI organizations.js.

ЧТО УЖЕ ПРОВЕРЕНО НА 748be43 / 2.0.97
DELETE members устанавливает is_participant = false. DELETE admins снимает права, но не удаляет аккаунт. Отдельное физическое удаление доступно суперадминистратору через списки excluded/detached. Поэтому старые тесты подтверждали сохранение человека, а не его удаление.

Если сервер вернул успешную квитанцию с кодом 200, а затем очистка локального хранилища завершилась ошибкой, UI ложно сообщает, что запрос на удаление не отправлен. Серверный purge также не проверяет, является ли удаляемая цель другим configured superadmin. Скрытие такой цели в списках не обеспечивает защиту.

ЧТО СДЕЛАТЬ
Переиспользовать действующий механизм физического удаления и его план зависимостей. Не создавать второй механизм сохранения удалённого аккаунта. Дать прямой вход в удаление из текущего списка.

Суперадминистратор удаляет допустимую цель. Администратор организации может удалить только допустимого участника своей организации после серверной проверки всей области удаления. Нельзя просто открыть глобальный purge любому администратору организации.

Если человек одновременно администратор и участник, действие «Удалить человека» удаляет аккаунт вместе с обеими функциями. «Снять права» остаётся отдельным действием F23.

Убрать из UI, обработчиков и API пользовательский сценарий исключения с последующим восстановлением, а также обходные советы по его использованию. Технический флаг, необходимый для сочетания ролей, сам по себе не даёт права сохранять удалённого человека.

Существующие записи с is_participant = false не удалять массово автоматически. Выяснить их происхождение и подготовить адресный план перехода, не создавая нового интерфейса исключений.

Сервер должен проверять защищённую цель и полномочия действующего пользователя. Для аккаунтов, указанных в конфигурации, учесть источник, который способен создать их заново. Не заменять удаление записью email в новом blacklist. Не менять управляющие документы ради теста. Обезличенная техническая квитанция операции не должна позволять восстановить аккаунт.
