# Адресный переход прежних записей участия

Основание: F02 1.0 от 11.11.2026. Этот план не выполняет миграцию существующих
пользовательских данных и не вводит интерфейс исключённых аккаунтов.

`ensure_organization_membership_participation_column` в `Api/database.py`
добавляет `is_participant BOOLEAN NOT NULL DEFAULT TRUE`: backfill сам не создаёт
значение `FALSE`. Прежний `DELETE /admin/organizations/{id}/members` записывал
`FALSE`, сохраняя аккаунт, membership, историю и admin authority. Повторное
добавление участника записывало `TRUE`. Это поведение прямо описано в
`p4k-remarks-combined-2026-11-10/{TASK,STATE}.md`; PR207 и FIX02 продолжили его.
В доступной shallow-копии истории есть `8442ae1` и `748be43`; более ранний commit
введения флага по локальной Git-истории не установлен. Рабочие БД не читались.

1. На этапе отдельно разрешённого перехода владелец контура формирует закрытый
   адресный реестр записей `is_participant=FALSE`, сопоставляя membership с
   `organization_membership_action_audit`, действующими admin rights и
   конфигурационными источниками. Персональные данные не входят в Git или отчёт.
2. Подтверждённые прежние исключения обычных участников и admin+participant не
   трактуются как уже выполненное удаление. Для каждого аккаунта владелец отдельно
   подтверждает физическое удаление либо сохранение аккаунта для действующей роли.
   Отсутствие/неоднозначность audit сохраняется как неизвестное происхождение.
3. Подтверждённый аккаунт удаляется существующим account purge: свежий dependency
   preview, проверка всей области, защищённых/configured целей и last-admin,
   fingerprint, idempotent operation id, внешний ledger при необходимости,
   отрицательная независимая проверка PostgreSQL. Нового email blacklist нет.
4. Если `FALSE` нужен для действующего администратора без участия, техническое
   состояние сохраняется. Наличие флага не означает разрешение удержать аккаунт
   после команды «Удалить человека». Общий backfill `TRUE`, bulk purge и скрытое
   восстановление участия не допускаются этим планом.
5. Сохраняются обезличенные количества решений и квитанции удаления. Откат кода
   не восстанавливает удалённые аккаунты; восстановление общей резервной копии
   требует штатной сверки внешнего deletion ledger и replay до запуска workers.

Исполнение этого плана на существующих данных, изменение конфигурации и выпуск
на постоянный контур остаются отдельными этапами владельца. Новый F02 меняет
будущую команду удаления и не запускает этот переход автоматически.
