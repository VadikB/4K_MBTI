# Базовые роли М3 для методологии 4К 1.1

## Результат

Шесть нормативных BaseRoles М3 доступны как детерминированный draft-пакет с
четырьмя полями описания и 17 полями карточки для каждой роли.

## Область

- Включено: извлечение из переданного DOCX, проверка структуры, пакет JSON,
  контрольные суммы источников и тесты.
- Не входит в этот независимо проверяемый результат: публикация ролей, изменение
  выбора роли пользователем, запись в БД, удаление legacy-данных и серверный деплой.

## Контекст

- Источники: `M3.BaseRoles_v1.0_FROZEN.docx`, `M3.RoleProfile_v1.0_FROZEN.docx`.
  Оба относятся к предметной методологии 4К 1.1 независимо от версии в имени.
- Архитектура: `docs/adr/001-assessment-platform-architecture.md` и
  `docs/architecture/assessment-runtime.md`.
- Пользователь разрешил отказаться от трёх старых ролей и удалить исторические
  профили и результаты сессий, которые на них ссылаются. Такое удаление требует
  отдельного шага миграции с инвентаризацией ссылок и проверкой на изолированной БД.

## Ограничения и риски

- Пакет содержит только базовые роли; `RoleSkillTargetProfile`, UserContext,
  OrganizationContext и оценочные уровни в него не входят.
- Опубликованная методология 1.0 и уже сохранённые снимки этим шагом не меняются.
- Исходные DOCX не копируются в Git; manifest содержит их имена и SHA-256.
- Системные коды ролей введены технически и не являются идентификаторами M3.

## Критерии приёмки

- [x] Содержатся ровно пять профессиональных BaseRoles и роль «Студент».
- [x] У каждой роли заполнены все 21 нормативное поле.
- [x] Пакет имеет статус `draft` и версию методологии `1.1`.
- [x] Повторная сборка из тех же источников даёт те же байты и checksum.

## План проверки

- Модульные тесты полноты и manifest.
- Повторная сборка во временный каталог и сравнение файлов.
- Стандартные проверки репозитория перед передачей PR.

## Откат

Удалить новый пакет, конвертер, тесты и эту документацию. Данные БД и runtime
данным шагом не затрагиваются.

## Следующий шаг

После локальной проверки выполнить отдельную миграцию runtime: версионируемые
RoleProfiles, ссылки в снимке сессии и удаление старых кодов из работающих путей.
Перед удалением данных проверить все внешние ключи и зависимости на изолированной
БД, зафиксировать число затронутых строк и предусмотреть откат из резервной копии.
