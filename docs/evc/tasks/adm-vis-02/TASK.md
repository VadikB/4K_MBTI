## Расхождение и изменение

На исходной сборке сотрудник с `preparation_failed` и планом 0 из 8 имел общий заголовок, «AS плана», строку об ответственном и две кнопки. Сбой обработки направлял на проверку подготовки из-за наблюдения с `kind=report`. При ширине 1440 px центры групп первой строки сбоя расходились на 15 px. В кандидате центры совпадают. При 390 и 320 px состояние занимает полную ширину под именем и действиями. Сверены размеры `14/20` для имени и действия, `13/18` для статуса и `13/19` для пояснения. Плашка сбоя использует `#ffe5e0`.

| Правило | Реализация и проверка |
| --- | --- |
| Этап первой ситуации появляется при подтверждённом наблюдении | `preparation_observation.py` возвращает `stage_code` из наблюдения. `organizations.js` показывает короткий текст при `preparation_failed`. Синтетика покрывает известный этап и сбой без записи этапа. |
| Сбой следующей ситуации, обработка и устаревшее чтение различимы | Наблюдение `kind=next` привязано к Cycle. Пауза берётся из его состояния, прогресс из `assessment_stages[ref].progress`. В фикстуре план на 8 ситуаций и каталог из 2 кейсов. `kind=report` открывает отдельное пояснение обработки. |
| Проверка читает конкретное назначение | `wiring.js` открывает ту же карточку, что и имя участника. GET обновляет проекцию. Карточка сверяет идентичность сессии, организацию, участника, выбранную оценку и `assignment_id`. При потере ответа остаются последние сведения. При новом поколении карточка запрашивает повторное открытие. Прежняя квитанция приглашения читается в карточке по своей оценке. |
| Отмена при сбое доступна из карточки до старта | Проекция `can_cancel` учитывает привязанные Cycle и неоднозначную историческую связь. Подтверждение выполняет штатный POST точного `assignment_id`. Сервер повторно проверяет состояние под блокировкой. При `409` интерфейс обновляет список. При потере ответа UI читает результат той же отмены. |
| Маршруты ADM-UI-01 и ADM-UI-03 доступны | Браузерные сценарии проверяют меню приглашения, назначение, отчёт, пояснение, фильтр и раздел обращения, включая Tab и Escape. |

## Воспроизведение

Из корня кандидата установите зависимости по `README.md` и `tests/browser/README.md`. Укажите выделенный локальный PostgreSQL 16 в `STAND_ADMIN_URL`. Каждый тест со стендом создаёт собственную `product4k_pytest_*` и удаляет её после прогона. В `TEST_DATABASE_URL` укажите отдельную БД с `pytest` в имени.

```sh
npm run lint:js
npm run build:web
node --test tests/frontend/*.test.mjs
npm run test:backend
npm run test:backend:http
.venv/bin/python -m pytest -q --run-integration tests/integration/test_path_start_assignment_lineage_db.py tests/integration/test_adm_layout_31_cancellation_db.py
npm run test:browser -- tests/browser/adm-vis-02.spec.mjs tests/browser/adm-ui-01.spec.mjs tests/browser/adm-ui-03-reentry.spec.mjs tests/browser/admin-appeals.spec.mjs tests/browser/preparation-status.spec.mjs
npm run test:browser -- tests/browser/auth-r03.spec.mjs --grep 'ADM-STATUS-01|ADM-UI-01|PROGRAM01 R0[5678]|PATH-START ST-R[14]|PATH-START viewport'
git diff --check
```

Для пошагового просмотра запустите `npm run test:browser -- tests/browser/adm-vis-02.spec.mjs --debug`. В открытой тестом синтетической организации выберите «Участники оценки».

| Сценарий | Как открыть |
| --- | --- |
| Сбой до старта | Строка «Сбой до старта» → «Проверить состояние». Карточка показывает подтверждённый этап, номер случая и допустимую отмену. |
| Сбой без этапа | Строка «Сбой без сведений об этапе» → имя или «Проверить состояние». Причина и первая ситуация появляются только при подтверждённых фактах. |
| Сбой следующей ситуации | Строка «Сбой подготовки» → «Проверить состояние» → «Скопировать номер». Карточка показывает паузу и 2 из 8 ситуаций. |
| Подготовка и устаревшие сведения | Строки «Подготовка идёт» и «Устаревшее состояние подготовки» → «Проверить состояние». |
| Ошибка обработки | Строка «Сбой обработки результата» → «Подробнее об обработке». |
| Приглашение, отчёт и обращения | «Письмо отправлено» → «⋯». «Полный результат» → «Открыть отчёт». В сценарии `admin-appeals.spec.mjs` нажмите «С обращениями», затем отметку в строке. |
| Потеря ответа, смена контекста и `409` | Именованные шаги `adm-vis-02.spec.mjs` останавливают или теряют ответы и меняют синтетические данные в действующем HTTP-контуре. Сверьте статус карточки, состояние списка и квитанцию отмены. |

Локальный эталон открывается из распакованного архива командой `python3 -m http.server 8765 --bind 127.0.0.1 --directory reference`. Страницы `screens/index.html?scene=people`, `?scene=exceptions`, `?scene=incident`, `?scene=preparation`, `?scene=progress` доступны на порту 8765.
