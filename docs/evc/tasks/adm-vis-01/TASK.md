# ADM-VIS-01 · Общая оболочка администратора организации

## Задача

Обновить общую оболочку вкладок «Участники оценки», «Данные организации» и «Анкета» для администратора организации. Проверить три ширины в Chromium, управление аккаунтом с клавиатуры, прямой вход в отчёты с возвратом к выбранной организации, вкладке и оценке, а также действующие маршруты «Моя оценка» и управления платформой.

Основание — прямое поручение «Запусти задание» и критерии из `P4K_ADM_VIS_01_Shell.zip`. Рабочая база `b5d4217d889e6f78550b265d47d0ce5352198e25` (актуальный `origin/main`, 2.1.64). База для воспроизведения замечаний `2abc3b75b530e60fedbd67abc8d4cef47fc525ea` (2.1.63). Ветка `codex/adm-vis-01-shell`.

## Источники и решения

- Эталон редакции 3, публикация `4d8b03f05f6c4c4dd5dcd4643af502db8ee97e91`. Проверены все 13 SHA-256 из `reference/SOURCE_IDENTITY.json`, включая Onest. Сцены `people`, `data` и `questionnaire` открыты по локальному HTTP на 1440, 390 и 320 CSS px.
- [ADM-UI-01](../adm-ui-01/TASK.md) определяет вход в реестр и восстановление контекста управления. [ADM-UI-02](../adm-ui-02/TASK.md) сохраняет прямой вход в реестр и раскрытие готовности на вкладке данных. Отдельной карточки ADM-VIS-04 в архиве, исходном репозитории и прилегающем комплекте архитектуры нет. Для этой вкладки сохраняется действующий вариант ADM-UI-02 и используется общий каскад оболочки.
- Применяются [рабочий цикл](../../agent-workflow.md), [матрица](../../verification-matrix.md), [проверка ревью](../../review-checklist.md), [Git-процесс](../../../../CONTRIBUTING.md) и решение SYN-CONTOUR-OWNERSHIP из [реестра](../../decision-register.md). По [архитектурному контексту](../../../architecture/product-4k/1.0/context.md) предметные определения, контракты PM, права и жизненный цикл данных находятся за границами изменений оболочки.
- Для EVC-стоп-условий отсутствуют изменения источников предметных значений, схемы, данных, прав и внешних контрактов. Локальная сборка и синтетическая приёмка входят в поручение. Полномочия этапа ограничены локальной передачей на ревью. `branch_push=false`, `pr=false`, `version_bump=false`, `merge=false`, `deploy=false`, `artifact_publish=false`.

## План

1. Снять стили и геометрию эталона и исходной сборки на одноразовом стенде.
2. Сверить шапку, вкладки, фон, шкалу Onest и существующий общий подвал. Обновить меню аккаунта и контекст вкладок в пределах обычного администратора.
3. Повторить браузерные измерения, пройти регрессии кабинета, маршрутов, отчётов и анкеты. Выполнить lint, frontend-тесты и воспроизводимую сборку.
4. Зафиксировать один коммит и передать SHA, команды и результаты ревью. Откат выполняется возвратом коммита с исходниками и сборкой.

## Как открыть сценарии

| Сценарий | Действия на локальном синтетическом стенде |
| --- | --- |
| Три вкладки | Откройте `/?screen=admin-organizations` как администратор организации с подключённой программой. Переключите «Участники оценки», «Данные организации», «Анкета» на 1440, 390 и 320 CSS px. |
| Меню аккаунта | Проверьте обычное, длинное и пустое ФИО с помощью `measure-product.cjs`. Откройте меню клавишей Enter, перейдите Tab к «Выйти» и нажмите Escape. Фокус возвращается к имени. При пустом ФИО отображается email. |
| Реестр отчётов | На каждой вкладке нажмите «Отчёты организации», сверьте организацию и программу, затем нажмите «К управлению». Сравните `organizationId`, `view` и `assessmentRef` до и после перехода. |
| Собственная оценка | Нажмите «Моя оценка» в шапке. Для синтетического администратора без назначения откроется экран ожидания. «Управление» вернёт в кабинет. |
| Управление платформой | Войдите как синтетический суперадминистратор, откройте `/?screen=admin-organizations`, перейдите в «Проблемы» и вернитесь в «Организации». |
| Эталон | Запустите `python3 -m http.server 8765 --bind 127.0.0.1 --directory reference` из распакованного задания. Откройте оглавление по `http://127.0.0.1:8765/`, затем сцены `people`, `data` и `questionnaire` через вкладки. |

## Проверки

- `git diff --check`, `npm run lint:js`, две сборки `npm run build:web` с одинаковыми SHA-256 всех 49 выходных файлов и `node --test tests/frontend/*.test.mjs` (473 PASS).
- `npm run test:browser -- tests/browser/adm-ui-01.spec.mjs tests/browser/adm28-real.spec.mjs tests/browser/adm-program-positive.spec.mjs tests/browser/auth-r03.spec.mjs tests/browser/adm-program-guards.spec.mjs tests/browser/adm-ui-03-reentry.spec.mjs tests/browser/questionnaire-it-inputs.spec.mjs tests/browser/questionnaire-draft-guards.spec.mjs tests/browser/program-connection-feedback.spec.mjs` (223 PASS, 2 проверки ожидали прежние подпись и границу).
- `npm run test:browser -- tests/browser/auth-r03.spec.mjs --grep 'keeps one bulk panel|resolves palette tokens'` (2 PASS после обновления ожиданий, продуктовые файлы идентичны первому прогону). Один тест AC18 опубликованного контура штатно пропущен в локальном запуске.
- Скрипты `measure.cjs`, `measure-product.cjs` и `compare.cjs` из каталога `verification` пакета дали 18 пар визуальных замеров, 27 состояний кандидата и 5 маршрутов. Данные и результаты находятся рядом со скриптами. Chromium запускался на изолированных стендах с синтетическими аккаунтами, отключённым внешним транспортом и локальным PostgreSQL.
- GitHub CI и опубликованный контур имеют статус `NOT_RUN` для локальной передачи. Серверная реализация, методологические пакеты и схемы данных находятся вне области ADM-VIS-01.

Для повторения замеров установите зависимости приложения согласно README и [инструкции браузерных тестов](../../../../tests/browser/README.md). Из корня проверяемого checkout запустите следующие команды, подставляя абсолютный путь к каталогу `verification`. Команду замера `product-before.json` выполните из отдельного checkout базы `2abc3b75`. Остальные команды выполните из checkout кандидата. Используйте общий каталог результатов и тот же выделенный локальный PostgreSQL.

```sh
node "$ADM_VIS_VERIFICATION/measure.cjs" "$ADM_VIS_RESULTS/reference-layout.json"
ADM_VIS_SINGLE_ORG=1 node "$ADM_VIS_VERIFICATION/measure-product.cjs" "$ADM_VIS_RESULTS/product-before.json"
ADM_VIS_SINGLE_ORG=1 node "$ADM_VIS_VERIFICATION/measure-product.cjs" "$ADM_VIS_RESULTS/product-after.json" --verify
node "$ADM_VIS_VERIFICATION/compare.cjs" "$ADM_VIS_RESULTS/reference-layout.json" "$ADM_VIS_RESULTS/product-before.json" "$ADM_VIS_RESULTS/product-after.json" "$ADM_VIS_RESULTS/comparison.json"
```

Укажите в `ADM_VIS_RESULTS` отдельный каталог для повторных измерений. Перед командами `measure-product.cjs` экспортируйте `STAND_ADMIN_URL` для отдельного локального PostgreSQL. В архиве эталона значение `product_base=dcd876f23036d0750b516e9eccf60f54daaae224` описывает происхождение прототипа. Сравнение продукта выполнено от 2.1.63, реализация подготовлена поверх проверенного `origin/main` 2.1.64.

## Передача и откат

Локальное ревью получает Git bundle ветки, SHA-256 пакета, исходные браузерные замеры и сводку проверок. В checkout с доступным базовым коммитом можно проверить и импортировать ветку командами `git bundle verify <абсолютный путь к ADM-VIS-01.bundle>` и `git fetch <абсолютный путь к ADM-VIS-01.bundle> refs/heads/codex/adm-vis-01-shell:refs/heads/codex/adm-vis-01-shell`. Откат после применения выполняется `git revert <SHA коммита ADM-VIS-01>` вместе с выходными файлами сборки.
