# Нормативный контракт М3 для методологии 4К 1.1

## Результат

Полное текстовое содержание двух FROZEN-источников М3 доступно в проекте в
читаемом Markdown. Структура RoleProfile, девять проверок ролевой валидности,
пять инвариантов BaseRole и четыре способа формирования дополнительно выражены
в детерминированном JSON-контракте.

## Область

- Включено: полные текстовые представления двух DOCX, структурированный
  `role_profile_contract.json`, обновлённый manifest и проверки.
- Не входит: изменение работающего выбора роли, подбор кейсов, публикация ролей,
  миграция старых данных, Git и серверный деплой.

## Контекст

- Источники: `M3.BaseRoles_v1.0_FROZEN.docx` и
  `M3.RoleProfile_v1.0_FROZEN.docx` из локального каталога пользователя. Оба
  относятся к предметной методологии 4К 1.1 независимо от версии в имени.
- Архитектура: `docs/adr/001-assessment-platform-architecture.md`,
  `docs/architecture/assessment-runtime.md`.
- Шесть карточек BaseRoles уже были извлечены в `base_roles.json`.

## Ограничения и риски

- Исходные DOCX не копируются в Git; manifest хранит их имена и SHA-256.
- Состояние `draft` относится к интеграционному пакету проекта и не меняет
  FROZEN-статус исходных документов.
- Word-переносы внутри ячеек сохраняются как строки JSON и `<br>` в Markdown;
  это важно для перечней задач, полномочий и сценариев.
- Markdown является точной текстовой транскрипцией, а не заменой исходного DOCX
  для визуальной проверки оформления.

## Критерии приёмки

- [x] В `role_profile_source.md` присутствуют M3.1–M3.9 и Appendix A.
- [x] Все непустые абзацы и ячейки обоих DOCX присутствуют в транскрипциях:
  BaseRoles — 14 абзацев и 276 ячеек; RoleProfile — 156 абзацев и 108 ячеек.
- [x] JSON-контракт содержит 4 + 17 полей с техническими ключами, 9 проверок,
  5 инвариантов и 4 способа формирования.
- [x] Повторная сборка даёт идентичные байты всех артефактов и manifest.
- [x] Контрольные суммы всех файлов включены в manifest.

## Проверка и откат

- Модульные тесты валидатора и manifest.
- Независимая сверка текста DOCX через `python-docx`.
- Повторная сборка во временный каталог и побайтовое сравнение.
- Перед передачей PR: `npm run lint:js`, `npm run build:web`,
  `npm run test:backend`, `git diff --check`.
- Откатить изменение конвертера, новые текстовые и JSON-артефакты, manifest,
  тесты и эту документацию. Данные БД этим шагом не меняются.
