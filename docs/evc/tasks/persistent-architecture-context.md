# Постоянный архитектурный контекст и реестр артефактов

## Результат

Согласованные принципы доступны из AGENTS.md; будущая задача обязана обозначить
источники, архитектурные границы и место хранения предметных артефактов.

## Область

Включено: правила, локальное резюме архитектуры 1.0, Registry, шаблон задачи,
чек-лист и первичный реестр долга. Не входит: перенос prompts, изменение runtime,
публикация методологии, миграции, CI-ограничения и деплой.

## Контекст

Основание: согласованный пользователем план от 2026-09-29. Тикет не предоставлен.
Источники: Product Architecture 1.0 (§18–21), ADR-001, assessment-runtime.md.
Архитектурный адрес: сквозное управление всеми PM; runtime-контракты не меняются.
Прослеживаемость принципов приведена в `docs/architecture/product-4k/1.0/context.md`.
Открытые решения сохранены в Registry, их разрешение в этот этап не входит.

## Ограничения и риски

Только Markdown. API, данные, схема, конфигурация, права и внешняя передача данных
не меняются. Документация не создаёт технического запрета: CI остаётся отдельным долгом.

## Критерии приёмки

- [x] AGENTS.md содержит правила и маршруты к архитектуре и долгу.
- [x] Статус REVIEW источника и открытые вопросы сохранены.
- [x] Предметные артефакты отделены от допустимой технической логики.
- [x] Реестр содержит места, владельцев, очередь и критерии закрытия.
- [x] Шаблон и ревью требуют источники, traceability и проверки артефактов.

## План проверки

Проверка локальных Markdown-ссылок и итогового diff по review-checklist.
Обязательные команды перед передачей: lint:js, build:web, test:backend, diff --check.
Интеграция не требуется: поведение БД не меняется. Реальные LLM не вызываются.

## Откат

Отменить только документальные изменения этого этапа. Снимки и данные не затронуты.
