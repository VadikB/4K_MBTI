## Решение и трассировка

- Выбранная подготовка оценки используется формами, readiness и приглашениями через
  один assessment-scoped ключ; DOM-порядок полей больше не определяет назначение.
- Сервер формирует `participant_preview`, допустимые классы получателей и diff с
  последней подтверждённой редакцией. В проекцию не входят технические идентификаторы,
  checksum, idempotency metadata и закрытые поля анкеты.
- Подтверждение применяет возвращённую сервером редакцию немедленно, отдельно от
  редактируемого черновика. Поздний ответ другой сессии отсекается `identityEpoch`.
- Изменение данных, файла или получателей помечает preview устаревшим и блокирует
  confirm до повторного серверного preview.
- Confirm идемпотентен для уже подтверждённой редакции. Advisory lock сериализует
  публикацию по `organization_id + assignment_ref`; более старый draft не может
  перезаписать новую подтверждённую редакцию.
- Технические коды validation/confirm преобразуются в понятные сообщения интерфейса.

## Проверка и откат

- Browser-регрессия проверяет participant-текст, diff, stale preview и немедленное
  отображение подтверждённой редакции; frontend-контракт проверяет единый источник
  выбранной оценки для приглашений.
- PostgreSQL integration-регрессия проверяет безопасную проекцию, diff,
  идемпотентность и конфликт старой редакции. Без `TEST_DATABASE_URL` локально имеет
  статус `SKIP`; обязательный CI должен выполнить её в изолированной test-БД.
- Фактические команды и статусы полного набора фиксируются в PR.
- Откат: revert PR. Новых таблиц, колонок и преобразований данных нет.
