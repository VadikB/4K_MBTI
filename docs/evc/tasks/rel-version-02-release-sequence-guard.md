# REL-VERSION-02 — защита последовательности версий

## Результат и область

Подготовка кандидата использует актуальный `origin/main`, отклоняет рабочую ветку
на устаревшей базе, а CI допускает только непосредственный PATCH/MINOR/MAJOR-преемник
версии базы. Push в `main` повторяет ту же проверку до deploy.

Включено: release scripts, unit-регрессии, CI deploy gate, `README.md` и
`CONTRIBUTING.md`. Не входят: изменение версии текущего приложения, продуктовый
runtime, схема БД, предметные артефакты и перенос старой UX-ветки.

## Контекст и источники

- Основание: решение владельца от 2026-11-03 сначала исправить release-процесс,
  затем перенести UX-изменения на свежую ветку.
- База: `origin/main@2a823f6100806808e3ee0249c90fcc021903e92c`, версия `2.0.52`.
- Диагноз: `codex/ux-ui02-spacing-radar-status-colors` создана 2026-10-19 от
  `6dd48e0`, до принятого перехода `2.1.37 → 2.0.1` в `03c39df`; удалённый merge
  не обновил её базу. Deploy версию не увеличивает и разворачивает точный SHA.
- Прочитано: `README.md`, `CONTRIBUTING.md`, `AGENTS.md`, рабочий цикл, матрица
  проверок, рецепт артефактов, шаблон задачи, review checklist,
  `REL-VERSION-01`, `REL-PREFLIGHT-01`, release scripts, CI/deploy и тесты.
- Предметные версии M/PM/LU, данные и snapshots неприменимы: меняется только
  инфраструктура выпуска. Публичный API `/users/version` не меняется.
- Стоп-условия: нет. Изменение управляющих документов выделено в отдельную,
  явно подтверждённую владельцем задачу.

## Действия выпуска

- `branch_push=true`: после локальных проверок.
- `pr=true`: после push.
- `merge=false`: отдельное подтверждение после CI/review.
- `deploy=false`: следует только из отдельно подтверждённого merge.
- `version_bump=false`: изменение процесса не назначает новую версию.
- `artifact_publish=false`: предметные артефакты не затронуты.

## Риски и откат

Guard намеренно требует обновлять долгоживущие ветки перед назначением версии.
Это может добавить rebase, но предотвращает неверный кандидат. Данные и миграции
не затронуты. Откат — revert этого PR; deploy продолжит использовать прежний
проверенный commit, версия приложения не изменяется этой задачей.
