## Основания и границы

- `START.md`, обе редакции Паспорта Case v1.2 (§§2, 5–7), Методология M5 v1.2
  (§§6.3–6.9), запись публикации от 21 ноября, M0 и рабочий глоссарий из комплекта.
  Манифест батареи указывает v1.2 WORKING, редакцию 2. Связанный и присланный DOCX
  маркированы FROZEN / CURRENT=NO. Таблицы 22 полей совпали. Раздел 6 и таблица
  межмодульных зависимостей различаются в описании уже проведённых сверок и
  статуса зависимостей. Это фиксируется в происхождении. Подключение использует
  исходную схему паспорта и точные байты батареи. Фактическая регистрация в
  центральных M0 Registry/Manifest и допуск к оценке людей требуют отдельных решений.
- [Change 01, И-3](../../../architecture/product-4k/1.0/updates/2026-10-01/README.md)
  и [ADR-002](../../../adr/002-cycle-as-dialogue-contracts.md) связывают источники
  M2/M3 и цели паспорта с PM-03, C-23/C-34 и передачей в PM-04. Действующий
  [реестр](../../../architecture/product-4k/registry.md) сохраняет применимость
  ранее закреплённых источников. В этой карточке проверяются входные данные и
  закрепление зависимостей. Подготовка AS, испытание сценариев и рецензирование
  нового банка относятся к 02/03.
- В предметных данных сохранены все 22 поля, включая исходные текстовые формулировки
  и места ссылок. Для выбора индексируются роль, CaseType, время, цели,
  последовательность старта, материалы и правила. Ссылки сохраняют исходную
  подпись и разрешаются в JSON Pointer. Для SPEC.02 и SPEC.07 `E02_SUBMISSION`
  указывает на 17.4. Одноимённые версии Case в разных пакетах различаются
  ссылкой и checksum пакета. Старые выборки без каталога исключают диагностический
  банк.
- Батарея v0.3 остаётся WORKING / CURRENT=NO. Новый продуктовый каталог возможен
  только с `usage_scope=qa` и конкретной организацией. Рабочие Case сохраняют
  WORKING, синтетические записи допуска не создаются. Диагностическая
  конфигурация отдельная и не может стать конфигурацией по умолчанию.

```sh
.venv/bin/python scripts/build_m5_passport_bank.py --battery-v0.3 \
  assessment_definitions/cases/competencies_4k/functional-personalization/0.7/sources
.venv/bin/python scripts/plan_specialist_program_release.py --diagnostic-battery
```

Для первой команды также подходит оригинальный ZIP батареи. Его Excel-файлы
проверяются по SHA-256 при чтении ZIP. Источники и сборка сверяются после повторного запуска.

Для изолированной БД скрипт планирования с `--diagnostic-battery --apply-import
--usage-scope qa --organization-id … --published-by … --decision-basis … --catalog-version 0.7-qa`
использует штатные импорт, привязку правил и публикацию QA. Диагностический каталог
привязывается к отдельной публикуемой конфигурации через `catalog_version_id`.
На её синтетическом профиле функция `create_cycle_session_for_case` с
`usage_scope="qa", diagnostic=True` и точными `case_id, case_version` сохраняет
Case, каталог и контрольные суммы зависимостей в новом Cycle. Для чтения
файлового пакета можно передать каталог `0.7` явно в `load_bank_case`.
Подготовка с новым паспортом и старт диагностической Session блокируются кодом
`M5_BATTERY_PREPARATION_NOT_ENABLED`.

Откат для новых тестов — выбрать прежнюю конфигурацию при создании профиля.
Уже созданные циклы читают закреплённые снимки и версии. Обновление строк
существующего каталога, миграции и удаление сохранённых данных не требуются.
