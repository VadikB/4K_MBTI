# Публикация M2 v1.1 для M4/M5 QA на test

## Результат

Superadmin может из Prompt Lab опубликовать проверенный файловый пакет M2 v1.1,
его четыре AgentDefinition и отдельную конфигурацию `4k_m5_qa_v1_1`. Конфигурация
доступна M4/M5 на test и не меняет default обычного assessment.

## Область

- Включено: проверка manifest/checksum, штатный authoring lifecycle, audit log,
  идемпотентность, серверная авторизация, non-default QA-конфигурация и UI-команда.
- Не входит: изменение содержания M2, публикация нового Scenario, включение
  universal evaluator в обычном assessment, смена default и production deploy.

## Контекст

- Основание: команда владельца «публикуй м2 и м3» от 2026-10-01; M3 v1.1 уже
  опубликован на test отдельным управляемым маршрутом.
- Точки входа: `POST /users/admin/m5-lab/publish-m2-qa-configuration`, Prompt Lab.
- Источники: `AGENTS.md`, `README.md`, `CONTRIBUTING.md`, рабочий цикл, матрица
  проверок, рецепт артефактов, M1 v1.4 и пакет
  `assessment_definitions/methodologies/competencies_4k/1.1`.
- Контракты: schema v2 M2, четыре AgentDefinition contract v2, действующие
  `assessment_*_versions`, `assessment_configurations` и audit log.
- Архитектурный адрес: M2 предоставляет нормативные Indicator/уровни и evaluator
  refs; M4 сохраняет профиль; M5 использует точные M2 refs. Сборка сессии M7
  этим изменением не реализуется.
- Прослеживаемость: M2 manifest и source checksums → schema/validator → authoring
  versions и configuration snapshot → unit/integration/HTTP → ручной read-back test.
- Предметный артефакт не изменяется: `methodology.json` остаётся draft-пакетом в
  Git; DB publication создаёт неизменяемую опубликованную версию с checksum.

## Источники и решения

- Применимы M2 package 1.1, M3 package 1.1 и M5 QA runtime текущего `main`.
- Владелец подтвердил human review и публикацию M2/M3 для test. Область решения
  ограничена test и QA-конфигурацией; default не меняется.
- Стоп-условий нет: содержание не корректируется, миграции и перезаписи
  опубликованных записей нет, пользовательский assessment не переключается.
- Требуется решение владельца: нет для реализации; merge выполняется после
  обязательного CI и подтверждения действия в GitHub.

## План и состояние

- Завершено: разведка, реализация loader/publication endpoint/UI, unit и HTTP.
- Активный шаг: CI и DB integration на изолированной PostgreSQL CI.
- Следующий шаг: merge/deploy test, вызов публикации и read-back M2/M4/M5.
- Ветка: `codex/m2-qa-configuration-publication`.

## Ограничения и риски

- Совместимость: только новая non-default configuration; старые snapshots и default
  остаются неизменными.
- Данные: операция добавляет expand-only `assessment_methodology_publications` и
  новые immutable version/configuration/audit records;
  повтор точного запроса возвращает те же ID, расхождение отклоняется.
- Безопасность: endpoint требует server-side superadmin; PII и секреты не читаются.
- LLM: реальные вызовы не выполняются. AgentDefinition только публикуются.
- Эксплуатация: публикация выполняется одной транзакцией; отсутствие Scenario,
  prompts или точных agent artifacts отменяет всю операцию.

## Критерии приёмки

- [x] Loader проверяет manifest, controlled artifacts, transformation PASS и M2 schema.
- [x] Методология и четыре AgentDefinition проходят штатный lifecycle с audit.
- [x] Конфигурация опубликована с `is_default=false`; повтор идемпотентен.
- [x] Endpoint закрыт server-side superadmin-проверкой.
- [x] Новое предметное содержание не встроено в Python/JS.
- [ ] CI integration подтверждает транзакцию и DB read-back.
- [ ] На test получены реальные methodology/configuration IDs и M4/M5 продолжает работу.

## План проверки

- Unit/backend: `npm run test:backend`.
- HTTP: `npm run test:backend:http`.
- Frontend: `npm run lint:js`, `npm run build:web`, проверка tracked `web/dist`.
- Integration: обязательный CI PostgreSQL; локально URL изолированной DB отсутствует.
- Test: нажать публикацию M2, зафиксировать IDs/checksum, создать M4 QA-профиль,
  создать M5 AS и перечитать сохранённый trace.

## Откат

Откатить application commit. Новая конфигурация не является default и не влияет
на обычный assessment. Опубликованные версии не удалять и не изменять: они остаются
аудиторским следом; дальнейшее использование прекращается отсутствием вызова по коду.
