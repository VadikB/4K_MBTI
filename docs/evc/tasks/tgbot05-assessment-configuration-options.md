# TGBOT-05: список опубликованных конфигураций для бота

## Результат и граница

`GET /integration/v1/assessment-configurations` возвращает под отдельным
`TG_BOT_INTEGRATION_TOKEN` только опубликованные `AssessmentConfiguration`, чьи
версии методологии и сценария также опубликованы. Ответ содержит `id`, `ref`,
`code`, `name`, `methodology_ref`, `reference_checksum` и `is_default`.

Это новый интерфейс чтения. Конфигурации, методология, Case Catalog, правила
оценки и административные endpoints не изменяются. Список не означает допуск
AssessmentProgram или готовность Cycle; это проверяет действующий admission.

## Источники и решение

- Base commit: `6645859935d099b352e3cf2f57fc23237c70efde` ветки `main`.
- Новый read-only route реализован независимо от draft Student Channel API.
- Change 01 `1.0/01` WORKING, task SourceSet `2026-10-01`, ADR-002 и TGBOT-02/04:
  4К владеет опубликованной конфигурацией, бот хранит точную ссылку в snapshot.
- Решение владельца 20.11.2026: бот показывает список доступных конфигураций;
  спецификации 4К не меняются, локальные период, число кейсов и получатели
  остаются настройками проекта в боте.

`reference_checksum` — SHA-256 канонического JSON из `id`, `code`, точных ID
версий методологии, сценария и каталога, а также `prompt_bundle_checksum`.
Он фиксирует ссылку на опубликованный комплект; это не checksum всего содержимого
методологии или каталога. При изменении этих компонентов отпечаток меняется.

## Проверка и выпуск

- HTTP: без настроенного token → 503, без Bearer → 401; с token → только поля ответа;
  пустой список → `[]`.
- Unit: SQL фильтрует published конфигурацию и версии; отпечаток детерминирован.
- PostgreSQL integration, общий Telegram путь и CI — отдельная проверка кандидата.
- Student Channel API остаётся отдельным
  `development_only` контуром до предусмотренного архитектурным контрактом допуска.

## Откат

Удалить read-only route и сервис. Схема БД и опубликованные артефакты не меняются.
