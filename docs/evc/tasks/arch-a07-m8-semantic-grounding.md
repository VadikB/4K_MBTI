# ARCH-A07 — смысловая подтверждённость описания M8

## Результат и область

Для новых Cycle пакет `m8_descriptive_report/1.2.0` добавляет независимый второй
LLM-вызов: он проверяет каждый claim и каждый элемент summary против сохранённых
фактов M8 и разрешённых границ интерпретации. Результат публикуется как `ready` только
когда все элементы получили решение `supported`. Противоречие, недостаточность данных,
ложная причинность, перенос в другой контекст и неподтверждённое обобщение переводят
описание в `failed`; неподтверждённый текст не попадает в API/UI/PDF.

Включено: новый draft-пакет prompt/schema/validator, строгая проверка полного покрытия
решения валидатора, сохранение результата семантической проверки и тестовый gateway.
Не входит: изменение IndicatorIDs, оценок, агрегации, методологических норм M8,
исторических пакетов и уже сохранённых Cycle; реальная provider-приёмка и решение
методолога остаются отдельными воротами.

## Риски и откат

Два последовательных provider-вызова повышают latency/cost и делают описание
fail-closed при недоступности валидатора. Фактический M8 Results при этом сохраняется,
а клиент получает честное состояние недоступности описания. Откат — вернуть default
dependency новых Cycle на `/v1` и код релиза; опубликованный `/v2` не изменять и не
удалять, исторические snapshots не переписывать.
