# Контракт оценивания индикаторов версии 2

## Результат

Приложение имеет типизированный, но ещё не подключённый к production runtime
контракт оценивания Indicators и отдельное идемпотентное хранение результатов и
case-level evidence. Legacy evaluator contract v1 продолжает работать без изменений.

## Область

- Включено: input/output models v2, `L0–L3`, состояния `observed`,
  `insufficient_evidence`, `not_assessed`, проверка ссылок, новые таблицы и repository.
- Не входит: material loader v2, LLM prompt, runtime routing, агрегация Skill и
  Competency, отчёты, связь authoring-кейсов с Indicators и включение 1.1.

## Контекст и ограничения

- Источник структуры: draft-пакет `assessment_definitions/methodologies/competencies_4k/1.1`.
- Новые результаты идентифицируются каноническими строковыми ID M2.
- `observed` требует уровень `L0–L3`; два состояния без оценки требуют `level_code=null`.
- Сохранение принимает только ссылки на Indicators и session cases из входного контракта.
- Новые таблицы не изменяют и не заполняют legacy `session_skill_assessments`.

## Критерии приёмки

- [x] Contract v1 и его тесты остаются без изменений поведения.
- [x] Contract v2 выражает полную иерархию до Indicator и дескрипторы `L0–L3`.
- [x] `L0` нельзя выдать без наблюдаемого evidence state.
- [x] Недостаток evidence и отсутствие охвата хранятся раздельно.
- [x] Repository отклоняет чужие Indicator и case references до записи.
- [ ] Повторное сохранение обновляет тот же результат без дублей — интеграционный
  тест добавлен, локальный запуск ожидает изолированную `TEST_DATABASE_URL`.

## Откат

Откатить новые модели, repository и создание таблиц. Новые таблицы можно оставить
пустыми: runtime v1 их не читает. Удаление заполненных таблиц требует отдельного
решения о сохранности данных.
