## Миграция, совместимость, восстановление

Expand: добавляются `scope_key`, `assignment_ref`, `assignment_id`, `questionnaire_revision_id`, поля claim и отдельная таблица ответов. Старые сообщения, статусы и время сохраняются; `resolved` остаётся читаемым как «Обработано ранее». Старое уникальное ограничение снимается по определению из `pg_constraint` (его имя сокращается PostgreSQL), создаётся уникальность по `scope_key`. Повтор expand проверен.

После снятия старого уникального ограничения прежняя версия API с `ON CONFLICT(user_id,organization_id,message)` не может принимать новые обращения. Поэтому выпуск требует остановить старые writers до применения expand и развернуть новый API до возобновления записи. Откат **только кода** на 2.1.39 несовместим; восстановление — вернуть проверенную новую версию или выпустить совместимый hotfix записи, сохранив расширенную схему и все обращения. Down migration и удаление записей запрещены. Владелец должен явно допустить этот порядок перед merge/deploy. До этого PR остаётся draft.
