  остальные токены только по v9. Первичный полный текст ТЗ Кати в этих вложениях
  отсутствует. Это **открытая проверка происхождения токена**, а не разрешение
  автоматически перекрасить общие W02/ADMIN токены.
- Footer text: v10 `rgba(100,116,139,.6)`, продукт `#68777C`. То же ограничение:
  исходник/UI_BASELINE описывает цель, но его наличие само по себе не заменяет
  проверку первичного ТЗ для прочих цветов. Фон#F7F7F7, напротив, задан прямо,
  поэтому старая зелёная поверхность подвала — подтверждённое A18.
- Дополнительные fallback-шрифты в font-family не считаются дефектом: реальный Onest
  загрузился, бинарный файл совпадает. Цвет #B3EBEF относится к сообщению пользователя;
  для самого кабинета нет элемента, на котором следовало бы специально его вводить.

## Почему предыдущая проверка это пропустила

Предыдущая реализация проверялась по краткому описанию композиции и нескольким
свойствам собственного рендера: фон, radius, наличие блоков, N/M, overflow и действия.
`VISUAL_REVIEW.html` сравнивал старый и новый продукт, **не эталон и продукт**.
Новый frontend test проверял только чистую функцию N/M; полноценного структурного
renderer-теста для компактной истории, метаданных состояний и типографики не было.
Palette test проверял текст объявлений и не проверял итоговую специфичность hover.
Поэтому функциональные PASS не доказывали визуального соответствия.

Предыдущее утверждение «точный исходник недоступен через Sites tools» было неверным:
поддерживаемый source workflow позволяет открыть репозиторий без публикации. Теперь
он использован, SHA и исходники сверены. Фразы старого CHECKS о завершённой реализации
и соответствии композиции **отозваны этим аудитом**. Исторические логи сохранены.
