## Дефекты и риски (не исправлялись)

1. **Blocker:** обычный вход создаёт legacy-профили. Для `new@acme.test` после входов: `active_profile_id=3`, `user_role_profiles=3`, `m5_cycles=0`, `m8_results=0`. Вход не должен инициировать такую предметную работу.
2. **Major:** логотип Lidum фактически не подключён и не загружается.
3. **Major:** canonical пользовательский M4 отсутствует; продолжить блок 2 как настоящее новое знакомство невозможно.
4. **Risk:** при `Europe/Moscow` у процесса приложения и UTC у PostgreSQL только что созданная ссылка считалась просроченной. В UTC-конфигурации сценарий проходит. Нужно закрепить единый timezone-контракт.
5. **Minor:** после успешного password reset кнопка визуально остаётся с подписью «Сохранить новый пароль» из-за завершения предыдущего submit, хотя режим уже переключён. Повторный вход через чистый экран работает.

## Короткое ручное повторение

1. Открыть `/?invite=<одноразовый invitation token>`; убедиться, что показана правильная организация.
2. Ввести предварительно добавленный email, открыть письмо в локальном mail-catcher, перейти по ссылке, задать пароль.
3. Проверить нейтральный экран «Следующий этап готовится», отсутствие оценки и таймера; снять desktop/mobile кадры.
4. Выйти; проверить неверный и правильный пароль. Запросить reset, открыть письмо, сменить пароль, войти заново.
5. Повторно открыть использованные ссылки; отдельно просрочить токен только в одноразовой БД и проверить отказ.
6. Повторить с email того же домена вне membership и с пользователем другой организации.
7. Заблокировать browser request на `/users/auth/email/request-link`, обновить страницу и сверить число писем/токенов до и после.
8. После входа запросить counts `user_role_profiles`, `user_sessions`, `m5_cycles`, `m8_results` для участника.
