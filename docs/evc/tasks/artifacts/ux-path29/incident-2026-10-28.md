## Что сохранено, а что отсутствует

Read-only проекция текущего состояния для каждой найденной операции:

- acquaintance status `answers_confirmed`, факт подтверждения и факт согласия есть;
- в текущем scope одна immutable confirmation, bound profile у неё отсутствует;
- выбранная RoleProfile отсутствует, персонализированных профилей нет.

Это текущие boolean/count факты, не исторический snapshot на момент отказа.
Историческое отсутствие допустимой роли отдельно подтверждено точной ветвью стека.
Фактический текст сохранённых ответов не читался; вывод об их содержательной полноте
или корректности не делается. Удаление ответов этим исследованием не установлено.

## Причина и границы вывода

Для всех найденных отказов причина подтверждена: подготовка вызвана без готовой
роли/M4. Код знакомства допускает сохранение confirmation без M4 и связывает её
только при глобальной единственности конфигурации и наличии выбранной роли
(`Api/acquaintance.py::_bind_confirmed_answers`). API административного назначения
на этой базе не содержит явных role/config refs. Это разрыв подготовки источников,
а не доказанный provider failure.

Нельзя доказать, какой именно UUID изображён на 8.jpg: на изображении он не указан.
Найдены отказы в указанное владельцем окно с одной и той же причиной.
P0 не закрыт: требуется scoped назначение источников, восстановление из сохранённых
ответов, регрессия и положительный сквозной путь. Real-provider smoke NOT_RUN;
диагностические SELECT не запускали новые операции и не делали LLM-вызовов.
