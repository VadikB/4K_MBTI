# F22 — единый интеграционный PR

## Результат и область

Собрать исправления F22-01–F22-07 и контракт стабильных browser fixtures в один
проверяемый release-кандидат PR #93. Включены только уже поставленные и отдельно
проверенные исправления из PR #94–100; новая предметная норма, миграции и изменение
публичных прав не вводятся.

Обычное правило «один PR — один независимо принимаемый результат» сознательно
заменено решением владельца от 2026-10-22: «делай один PR». Исключение относится
только к этому интеграционному выпуску. Merge в `main`, закрытие исходных PR и удаление
их веток не входят в автоматическое решение агента до зелёного CI объединённого head.

## Критерии приёмки и проверки

- Все F22-регрессии одновременно проходят на одном head.
- Полные backend и frontend unit-наборы, JS lint и production build проходят.
- Browser-сценарии проходят без косвенного выбора fixture через indicators.
- PostgreSQL integration проходит на одноразовой БД с `test`/`pytest` в имени.
- `git diff --check` чист; временные зависимости не входят в Git.
- Обязательные CI `frontend` и `pytest` зелёные на актуальном head PR #93.

Фактический локальный результат на объединённом дереве:

- `npm run test:backend` — PASS, 491;
- `node --test tests/frontend/*.test.mjs` — PASS, 72;
- `npx playwright test tests/browser/auth-r03.spec.mjs --workers=1` — PASS, 48;
- полный PostgreSQL 16 integration с раздельными `TEST_DATABASE_URL` и
  `STAND_ADMIN_URL` — PASS, 144;
- `npm run lint:js`, `npm run build:web`, `git diff --check` — PASS.

Первый integration-запуск ошибочно передал test database как maintenance URL и
закономерно получил пять отказов защитного `admin_params`. После исправления параметров
полный набор прошёл. Отдельно исправлено устаревшее ожидание F22-05: при переходе от
доступа участник+администратор к умолчанию «только участник» preview обязан включать
`result_recipients` в список изменений. Одноразовый контейнер и тестовые данные удалены.

## Риски и откат

Главный риск — взаимодействие исправлений в общей форме администратора. Он закрывается
полным unit/browser/integration прогоном на объединённом дереве. Данные и схема БД не
меняются. Откат до merge — вернуть PR #93 на `8d7959e`; после merge — revert одного
интеграционного PR. Исходные ветки PR #94–100 сохраняются до подтверждения результата.
