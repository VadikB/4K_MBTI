# P4K-FIRST-START-ONBOARDING-01 — первый старт оценки

## Результат

Участник с готовым планом и подтверждённым финальным шагом знакомства может
открыть первую AS подготовленного Cycle при недоступном сохранении знакомства.
При неполном подтверждении финальный шаг сохраняется до команды старта.

## Область и основание

- Запуск 18.11.2026 по прямому поручению пользователя в Codex. Приложенный
  `P4K_First_Start_Fix_v1.0.md` задаёт требования и заканчивает этап локальной передачей.
- База `b5cd92b7d492f31efe3b01ee22699bb34f55248d`, приложение 2.1.32.
  Ветка `codex/p4k-first-start-onboarding-01`. В доступных ветках и открытых PR
  подходящего кандидата не найдено. Проба `c4323f1` относится к 2.1.30.
- Изменяемая точка — `advance()` входа в PM-04,
  [onboarding.js](../../../../web/js/screens/onboarding.js). Источник отметки
  знакомства — ответ API для текущего участника. Готовый план и `mandatory_complete`
  не подтверждают сохранённый финальный шаг. Существующий `readinessIndex()`
  рассчитывает шаг по анкете участника. Поля API и сохранённые записи совместимы.
- Штатный запуск через `startAssessmentInterview({ preparedCycleId })` использует
  допущенный план, идентификацию текущего владельца и экрана, ключ идемпотентности
  и сверку по runtime после неизвестного исхода. Граница — та же первая AS и
  ноль оценочных ответов. Подготовка PM-03, вопросы допуска M5, последующие AS,
  таймер, API, схемы и предметные артефакты вне этапа.

## Проверки

| Критерий | Синтетическое воспроизведение и ожидаемый результат |
| --- | --- |
| AC-1 | Прервать PUT в браузерном маршруте при подтверждённом финальном шаге. На базе ошибка и 0 POST. На кандидате 0 PUT, 1 POST для подготовленного Cycle и видна та же первая AS. |
| AC-2 | `in_progress` на финальном шаге и `completed` на другом шаге требуют 1 PUT с финальным шагом до 1 POST. При обрыве обязательного PUT нет POST и работает штатная повторная проверка. |
| AC-3 | Принятый POST с неполным 201 и первым чтением 503. Повторное чтение и reload открывают ту же первую AS. Один POST, ноль оценочных ответов. |

[Матрица EVC](../../verification-matrix.md) для изменения поведения JS и карточки.
Проверяются frontend tests, `npm run lint:js`, `npm run build:web`, стабильность
`web/dist`, адресный Chromium
[remain05-first-start.spec.mjs](../../../../tests/browser/remain05-first-start.spec.mjs)
с `--workers=1 --retries=0` и `git diff --check` для передаваемого диапазона.
Протокол сверяет число, порядок и payload фактических браузерных команд.

## Полномочия, передача и откат

Codex работает в отдельной локальной копии. Удалённые операции ограничены
чтением GitHub и установкой зависимостей по lockfile. В тесте собственный
localhost и браузерные подстановки, без рабочей БД, провайдеров и почты.
Состояние этапа в [STATE.md](STATE.md). Пакет передачи содержит bundle от
точного base, SHA кандидата и проверенного HEAD, diff и результаты по AC.

`branch_push=false`, `pr=false`, `merge=false`, `deploy=false`,
`version_bump=false`, `artifact_publish=false`. Назначение выпуска и CI перед
слиянием относятся к отдельному поручению владельца.

Откат выполняется отменой коммита правки и его сборки. Действующие записи
знакомства, Cycle и AS при откате не редактируются.
