# Задание 5. Адресный повтор промежуточного M6 Evidence

## Цель и область

Продолжить обработку принятого ответа из существующего C-45 на той же границе. В ветке выполняются техническое исправление обратной связи валидатора, адресная команда для оператора хоста и проверки на синтетическом назначении опубликованной программы 2.0. Работа с общим TEST ограничена диагностическим чтением. Разрешён локальный коммит. Публикация ветки, PR, изменение номера версии, merge, deploy и запуск повтора на общем TEST требуют отдельного поручения.

## Источники и решения

- База совпадает с TEST 2.1.85, SHA `026576a0f9c97fab3299a0517f4ba19f8397aed4`. В существующих локальных и удалённых ветках и открытых PR продолжения этого исправления при поиске не найдено.
- Диагностика задания 5 и синтетическое воспроизведение дали две проверки в одной попытке. Первая зафиксировала `fragments.0.end / greater_than`, вторая дала `M6_FRAGMENT_SPAN`. Точная подпричина второго отказа в старой диагностике отсутствует.
- [Change 01](../../architecture/product-4k/1.0/updates/2026-10-01/README.md), [Registry](../../architecture/product-4k/registry.md), [ADR-002](../../adr/002-cycle-as-dialogue-contracts.md) и [M6-A](../../architecture/m6-a-contracts.md) связывают PM-04 и PM-05 через сохранённый промежуточный C-45 с границей материала. Результат M6 допускается действующим валидатором, затем штатные M6 Assessment и M7 обрабатывают C-54.
- `STATE.md`, подразделы R05–R07, закрепляет короткие транзакции до и после шлюза, повтор по устойчивой идентичности и сохранение исходного механизма. Техническая подсказка использует точную единственную цитату из хода участника. Строгая проверка и пакет `m6_evidence/1.0.1` сохраняются.

## Реализация и проверка

Ветка `codex/task5-m6-interim-retry`. Сначала проверить валидатор и существующий захват, затем выполнить целевой интеграционный сценарий на PostgreSQL и наборы проекта по матрице. Команда доступна из доверенной оболочки оператора. Без `--apply` открывает транзакцию чтения. Ключ эффекта — request UUID и ожидаемый номер завершившейся отказом попытки. Аудит сохраняется в trace новой попытки. После фиксации захвата транзакция закрывается до вызова шлюза.

Откат возвращает commit приложения. Старые и новые попытки, исходный C-45 и принятые ревизии сохраняются. Миграции и публикация новой версии предметного пакета не нужны.

## Команда оператора

Запуск из корня установки приложения с этой ревизией под действующей учётной записью оператора хоста. Подставить подтверждённые идентификаторы и номер завершившейся отказом попытки.

```bash
.venv/bin/python -m scripts.retry_m6_interim_evidence \
  --expected-origin https://test.4k-assistant.ru \
  --assignment-id "$assignment_id" --cycle-id "$cycle_id" \
  --situation-id "$situation_id" --handoff-id "$handoff_id" \
  --request-id "$request_id" --failed-attempt "$failed_attempt"
```

Предварительная проверка возвращает `eligible=true` для доступного повтора. С `--apply` команда захватывает одну попытку и передаёт исходный C-45 штатному шлюзу M6. `started=false` при повторе команды означает, что новая попытка этой командой не запущена. Обычный воркер продолжает C-54 и M7 после `request_status=succeeded`. При `failed` команда с `--apply` возвращает exit 1. При отказе адресных проверок или ошибке исполнения возвращает exit 2 и технический код.
