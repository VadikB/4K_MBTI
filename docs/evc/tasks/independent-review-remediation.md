Повтор подтверждения одинаковых источников/сведений использует прежний M4;
изменение профессиональных сведений или имени создаёт новую UserContext/M4-версию.
Блокирующие конфликты не снимаются автоматически. При выборе профиля для нового
Cycle проверяется последняя версия, а не любой старый ready. Уже начатый Cycle
сохраняет собственный snapshot. Ни одна историческая запись не переписывается.

Совместимость API: AgentProfileConfirmRequest дополнен optional personalized_profile;
новый UI передаёт все три version/configuration ID явно. Старые клиенты сохраняют
анкету прежним контрактом, но не получают автоматического ready M4; старт runtime
по-прежнему проверяет M4. Поля history/latest_session_id/average_score_percent
сохраняют legacy-данные, legacy_assessments_total показывает их число. Счётчики
total_assessments/completed_assessments теперь считают Cycle с индивидуальным
Report, как dashboard.reports_total; версии Report не увеличивают число оценок.
cycle_reports содержит текущую версию и полный список сохранённых версий.

Форма требует опубликованных входов; отсутствие организации, M3 или конфигурации
не заменяется встроенными значениями. Подготовка этих входов ответственным
администратором предшествует участию. Создание организации/новая onboarding-система
не входят в эту задачу. Legacy role_id пока сохраняется для совместимости анкеты;
оценочный runtime использует только явно выбранный M3. Долг ART-03/ART-06/ART-07
