## Связь с существующим предметным долгом

ART-01 (перенос M5 prompt) не ставится повторно: `m5_generation_lab.generate`
использует input_snapshot['prompt']['text']; отдельные тесты сохранённых снимков
есть. В этом аудите эти тесты не запускались, поэтому новый PASS ART-01 не заявлен.
BC-03 развивает ART-05, BC-07 связан с ART-06, BC-09 — с ART-07.
BC-01/04 и словарь BC-05 — дополнительные кандидаты долга: наличие имени legacy
не разрешает содержательные определения в Python. Реестр долга и управляющие
документы сейчас не переписывались: устаревшие требования «сохранить legacy»
должны быть адресно сняты при подготовке соответствующих задач.

## Очередь отдельных PR

1. **PR-A: полный bundle без достраивания** — BC-01/02, один результат:
   новый запуск принимает только полную опубликованную конфигурацию; нет скрытых
   чтений active prompts и UPDATE опубликованного bundle. Подготовить пакет и
   критерий отказа перед удалением ветвей. Это рекомендуемый следующий шаг.
2. **PR-B: prompt интервью из snapshot** — BC-03 / ART-05; зависит от полного
   набора prompts и их потребителей. Содержимое переносится с источником, новые
   методологические правила не придумываются.
3. **PR-C: явная установка пакета** — BC-04; зависит от пригодного полного пакета
   и согласованного плана данных. Проверка чистой test-БД обязательна.
4. **PR-D: прямой M3/M4 ввод лаборатории** — BC-05; замена действующего UI-сценария,
   затем удаление миграционного endpoint и alias-словаря.
5. **PR-E: env-контракт** — BC-08; независимая небольшая задача с подготовкой
   конфигурации выпуска. **PR-F: граница gateway** — BC-07, после PR-B.
6. **PR-G и далее: оценивание и Results** — BC-06/09 вместе с соответствующими
   задачами M6–M8, но отдельными принимаемыми результатами. Не поддерживать два
   пути только ради старой версии; не удалять единственный действующий до готовности
   целевого. Подробные алгоритмы требуют адресных источников.

Нет основания начинать с массового переименования таблиц, удаления всего legacy
или переписывания монолитов. Приоритет — скрытые источники предметных значений и
изменяемые входы, затем упрощение маршрутов с проверенными потребителями.
