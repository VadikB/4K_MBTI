# Рабочий цикл агента и проверяемые правила EVC

## Результат и область

Агент использует явный цикл, проверяемые стоп-условия, единый отчёт и существующие
процедуры работы с артефактами. Локальные проверки выбираются по типу изменения;
обязательный CI перед слиянием сохраняется.

Включено: AGENTS.md, agent-workflow.md, verification-matrix.md, artifact-recipe.md,
CONTRIBUTING.md, шаблоны задачи/PR, review-checklist.md и уточнение Registry. Не входит: runtime,
методологические правила, миграции, новый валидатор, изменение CI или присвоение baseline.
Подробный migration-playbook отложен в отдельную задачу.

## Принятые решения

- Один шаг — проверяемая часть плана, не обязательно ответ, коммит или PR.
- Подтверждение нужно для неразрешённого решения владельца, не для каждого плана.
- Обязательные источники и проверки фиксируются; отсутствие проверки не считается успехом.
- Для docs локально проверяются diff, ссылки и согласованность. Полный CI сохраняется.
- Управляющие документы меняются только отдельной явно согласованной задачей.
- Делегирование не включается автоматически; человеческая приёмка не заменяется самооценкой агента.
- Дополнительное указание владельца: версии всех M будут корректироваться; задачи
  M6–M8 ещё не внесены в проект. Различать целевую архитектуру, пакеты, задачи и runtime;
  не фиксировать существующие пакеты как окончательную методологию.

## План

1. Описать рабочий цикл, матрицу и рецепт на основе существующих контрактов.
2. Сократить AGENTS.md и согласовать шаблоны/CONTRIBUTING.md.
3. Проверить ссылки, реальные команды, непротиворечивость; оформить отдельный PR.

## Критерии приёмки

- Есть протокол вопроса/ожидания и бинарные стоп-условия с учётом ранее данного допуска.
- Различены роли владельца и агента, шаг/ответ/коммит/PR и локальный/CI-контроль.
- Заданы правила конфликтов, отсутствующих источников и передачи состояния.
- Рецепт не обещает отсутствующую команду или методологический допуск по checksum.
- Шаблоны требуют результаты, причины пропусков, риски, откат и блокеры.
- В управляющих документах нет одновременно старого и нового локального порога проверок.

## Проверка, риски и откат

Локально: `git diff --check`, проверка Markdown-ссылок и путей команд, review
согласованности. CI — действующий полный workflow. Для содержательных команд
рецепта достаточно проверить реализацию/существующие тесты; повторные runtime-тесты
из-за изменения Markdown не требуются. Схема, env, права и деплой не меняются.
Откат — revert только этого документального изменения. Не ослаблять критерии baseline.

## Риски: конфиг / схема / деплой / безопасность / откат

Конфиг и схема не меняются. Деплой не выполняется; выпуск — существующим PR/CI-путём.
Права и передача данных не меняются. Основной риск — различное толкование документов:
оно снижено единой матрицей и ссылками вместо дублирующихся требований.
Откат — revert этого отдельного коммита, без отката ART-01 и изменения данных.
