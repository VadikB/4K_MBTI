# ADM-UI-01 · Кабинет, участники и карточка

## Результат и границы

Штатный кабинет администратора организации показывает выбранную оценку, список
участников с адресными действиями и карточку с историей и сведениями о сбое.
Реестр отчётов открывается для выбранной организации и программы. Возврат
восстанавливает контекст «Управления». Действующая оболочка суперадминистратора,
операторский запуск подготовки и обработка обращений ведутся в своих контурах.

## План и приёмка

1. Собрать шапку, вкладки, контекст и колонки. Проверить 1440, 390 и 320 px,
   Tab, Escape, клик вне меню и возврат фокуса.
2. Пройти состояния приглашения, назначения, подготовки и результата. Использовать
   синтетических участников, существующие команды, изолированный PostgreSQL.
   Проверить отдельный переход к предпросмотру удаления и чтение старой квитанции.
3. Сверить идентификатор Report и права для одного Cycle в строке и реестре.
   Проверить возврат к исходным организации, оценке и разделу.
4. Собрать `web/dist`, пройти JS lint, frontend и адресные browser/HTTP проверки
   по [матрице](../../verification-matrix.md). Результаты, способ воспроизведения
   и SHA кандидата указать в одном PR.

## Как открыть проверенные состояния

На нужном SHA выполните штатную сборку и запустите тест на выделенном локальном
PostgreSQL 16. Подставьте адрес своего изолированного кластера.

```sh
npm ci
npm run build:web
npm run lint:js
node --test tests/frontend/*.test.mjs
STAND_ADMIN_URL=postgresql://pytest@127.0.0.1:55961/postgres npm run test:browser -- tests/browser/adm-ui-01.spec.mjs tests/browser/path-admin-contract.spec.mjs
```

Сценарий открывает «Управление» по настоящей сессии браузера, показывает
синтетические состояния на фактической проекции HTTP и удаляет только свою БД.
Параметр Playwright `--headed` позволяет наблюдать сценарий в браузере.

| Сцена эталона | Путь в проверке |
| --- | --- |
| `people` | Кабинет админа, «Участники оценки». Проверить шапку, вкладки, панель оценки, добавление и CSV на 1440, 390 и 320 px. |
| `menu-sent` | Строка «Письмо отправлено», «⋯». Два пункта, Tab, Escape, клик вне меню и подтверждение отзыва. |
| `card` | Нажать имя той же строки. Раскрыть историю, открыть предпросмотр удаления, закрыть карточку. Проверить возврат фокуса на имя. |
| `invitations` | В строке без письма доступно «Пригласить». У «Отправка не подтверждена» проверить прежнюю операцию с теми же организацией, оценкой и адресатом. |
| `preparation` | В строке «Подготовка идёт» проверить состояние. Операторский запуск покрывается существующими тестами подготовки. |
| `assignment` | Из строки «Участник для назначения» выбрать разрешённую роль и подтвердить. Проверить ID участника и роли в команде. Пакетное назначение покрывает `path-admin-contract.spec.mjs`. |
| `progress` | Открыть полный, ограниченный и безбалльный результат из строки и реестра. Сверить Report ID, Cycle и доступ customer. Для недоступной публикации вход скрыт. Проверить возврат после обновления страницы. |
| `exceptions` | Прочитать старую квитанцию или состояние подготовки. Отдельный сценарий в `auth-r03.spec.mjs` проверяет сбой без публичного номера. |
| `incident` | Карточка «Сбой подготовки». Сверить номер, последний подтверждённый этап и копирование. Проверка делает GET. |

Статусы приёмки, точный SHA и результаты проверок указываются в PR.
