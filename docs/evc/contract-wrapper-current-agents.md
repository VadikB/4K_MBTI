# Краткое описание задачи EVC: контрактная оболочка текущих агентов

## Результат и область

Runtime анализа вызывает четыре существующих оценщика компетенций 4K через одну
явную версионированную входную/выходную границу, сохраняя методологию, scoring,
хранение и отчёты. Включены модели входа оркестрации и нормализованного выхода,
построитель только по снимку сессии, legacy-адаптер для `evaluate_session`, wiring
очереди и регрессионные тесты. Не входят новая методология, таблицы определений
агентов, перенос legacy SQL/сохранения, агрегация, отчёты, промпты, рубрики и scoring.

## Контекст и ограничения

Точки входа: `Api/assessment_analysis_queue.py`, `Api/communication_agent.py`,
`Api/assessment_runtime.py`; текущая форма результата — `SkillEvaluation`.
Классы оценщиков, методология v1, записи базы и чтение отчётов остаются совместимыми.
Схема не меняется. Идентификаторы и результаты нельзя логировать вместе с диалогом
или персональными данными. Новых сетевых и SQL-вызовов нет.

## Критерии приёмки

- [x] Каждый оценщик получает валидированный вход из зафиксированного снимка.
- [x] Агенты работают через общий адаптер без изменения `evaluate_session`.
- [x] Legacy-результаты нормализуются и валидируются до завершения этапа.
- [x] Повторы и завершение очереди не изменены.
- [x] Методология и схема хранения не изменены.

## Проверка, откат и передача

Покрыты построение контракта, нормализация, отклонение неверного результата и
очередь; использованы существующие интеграционные тесты. Откат удаляет wiring и
модуль адаптера без отката данных. Выполнены целевые и полные backend-тесты,
JS lint, web build, компиляция Python и проверка diff. Вход ещё не был
самодостаточным пакетом evidence; следующий шаг — snapshot-aware построитель входа.
