# Краткое описание задачи EVC: репозиторий результатов оценщика

## Результат и область

Оценщики компетенций вычисляют валидированные результаты без записи в базу;
оркестрация сохраняет их через единый репозиторий, не меняя строки и отчёты.
Включены контракт анализа кейса, чистый расчёт, UPSERT в
`session_case_skill_analysis` и `session_skill_assessments`, очередь,
совместимый фасад `evaluate_session` и регрессионные тесты. Не входят миграции,
изменение методологии/scoring, общий редизайн транзакций и версии агентов.

## Ограничения и критерии приёмки

- Сохранённые столбцы, значения, JSON-форматы и conflict keys остаются прежними.
- Evidence не логируется и не раскрывается в результате этапа; LLM не меняется.
- Повторные попытки безопасны благодаря прежним UPSERT conflict keys.
- [x] Контрактный расчёт не выполняет запись в базу.
- [x] Обе коллекции валидируются до сохранения.
- [x] Репозиторий использует прежние conflict keys и JSON-форматы.
- [x] Очередь сохраняет только успешно валидированный результат.
- [x] Legacy `evaluate_session` создаёт и сохраняет прежнюю форму результата.

## Проверка, откат и передача

Покрыты чистая граница расчёта, SQL/параметры, отклонение неверного результата,
очередь и legacy-фасад. Пройдено 11 интеграционных PostgreSQL-тестов, целевые и
полные модульные тесты, компиляция Python, JS lint, web build и проверка пробелов.
Откат возвращает UPSERT внутрь оценщиков без миграции данных. Транзакция остаётся
на прежнем соединении задания. Следующий шаг — убрать fallback активного промпта
для сессий со снимком.
