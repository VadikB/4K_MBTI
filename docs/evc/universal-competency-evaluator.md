# Краткое описание задачи EVC: универсальный оценщик компетенций

## Результат и область

`AgentDefinition` компетенции может выбрать `runtime.mode: universal_llm`;
runtime передаёт самодостаточный зафиксированный вход единому LLM-исполнителю и
возвращает существующий валидированный выходной контракт. Включены выключенный по
умолчанию kill switch, строгая runtime-конфигурация, Markdown-промпт, ограниченные
повторы, JSON/identity/reference-валидация, точная маршрутизация, fake-LLM тесты и
отдельный минимальный тест реального LLM. Не входят изменение production-default,
новая методология, shadow-хранение, автоматический legacy fallback и реальные данные.

## Ограничения и критерии приёмки

- `legacy_adapter` сохраняет поведение; Markdown — данные, не код; секреты только в окружении.
- Реальные вызовы помечены `llm`, ограничены и исключены из стандартных тестов.
- После ошибки тип оценщика не меняется молча.
- [x] Legacy-определения исполняются без изменений.
- [x] Universal-исполнение запрещено при выключенном kill switch.
- [x] Используются только зафиксированный Markdown и самодостаточный вход.
- [x] Неверные JSON, identity или source references не сохраняются.
- [x] Повторы, temperature, timeout и output tokens ограничены.
- [x] Автоматического legacy fallback нет.
- [x] Путь покрыт модульными и изолированными PostgreSQL-тестами.

## Проверка, откат и передача

Проверены routing, kill switch, промпт, parsing, повторы и ссылки; реальный тест
содержит один синтетический навык/кейс и не более двух вызовов. Откат:
`ASSESSMENT_UNIVERSAL_LLM_ENABLED=false` и определения на `legacy_adapter`.
Пройдено 108 backend-, 3 HTTP-, 13 интеграционных и 1 ограниченный LLM-тест,
JS lint, web build, компиляция и diff. Максимум — две попытки и 4096 output tokens,
`fallback=fail`. Для нового кода компетенции ещё нужен общий репозиторий материалов.
