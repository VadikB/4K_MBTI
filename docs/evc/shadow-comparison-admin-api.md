# Административный API сравнения shadow-оценок

## Результат и область

Суперадминистратор читает агрегированную статистику official-versus-shadow без
payload оценки и идентификаторов сессий. Включены read-only запрос репозитория,
типизированный HTTP-ответ, endpoint только для superadmin и тесты. Не входят UI,
пакетный запуск, изменение методологии, экспорт сырых данных, детализация по
пользователю/сессии и изменение feature flag.

## Ограничения и критерии приёмки

- API аддитивен, схема не меняется, внешние сервисы/LLM не вызываются.
- Ответ исключает ID сессии, ошибки, evidence, rationale, выдержки и текст пользователя.
- Выполняются одна общая и одна групповая агрегации по таблице shadow-запусков.
- [x] Без сессии возвращается 401, не-superadmin получает 403.
- [x] Superadmin получает итоги и группы по компетенции и версиям official/shadow-агентов.
- [x] Процент согласованности рассчитывается по агрегированным числам совпавших и сравнённых навыков.
- [x] Ответ не содержит payload оценки или идентификатор сессии.

## Проверка, откат и передача

Проверены процент, пустой результат, SQL-агрегация в изолированной pytest-базе,
аутентификация и авторизация endpoint. Откат — удалить route, response schemas и
метод репозитория; сохранённые данные не меняются. Принят доступ только superadmin.
Проверки lint, web build, backend, HTTP, интеграция и diff прошли. Пагинация не
нужна из-за конечного числа комбинаций версий. Следующий шаг — контролируемый shadow-пакет.
