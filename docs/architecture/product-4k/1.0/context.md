## Карта ответственности

| Модуль | Ответственность |
| --- | --- |
| PM-01 Construct | Нормативный конструкт M2, его определения и иерархия |
| PM-02 Role & Context | Роли M3, контексты M4 и PersonalizedProfile |
| PM-03 Assessment Design | Инструменты M5, Case и подготовка AS |
| PM-04 Assessment Session Runtime | Исполнение AS, Dialogue, состояния и маршрут по применимым M5/M7 |
| PM-05 Evidence & Assessment | Evidence и фактические оценочные результаты по применимому M6 |
| PM-06 Results & Interpretation | Интерпретация фактов и сопоставление с целями по применимому M8 |
| PM-07 Reporting | Представление утверждённого содержания результата получателям |

Это целевые ответственности, не утверждение о завершённом разделении кода.
PM не обязан быть сервисом, LU — классом или агентом. Каталог LU и контрактов
источника нельзя автоматически считать полностью реализованным. Термин Component
в целевом предметном описании сохраняется за компонентом навыка; существующие
API/идентификаторы component registry не переименовываются этой задачей.

## Работа с версиями и открытыми решениями

Различайте версии методологии, архитектуры и реализации. Статусы архитектурного
комплекта WORKING/REVIEW/FROZEN и указатель CURRENT не заменяют существующий
runtime-жизненный цикл draft/ready_for_review/published/retired.

Применяйте существующие [ADR-001](../../../adr/001-assessment-platform-architecture.md)
и [runtime-контракт](../../assessment-runtime.md) для совместимости опубликованных
конфигураций. Например, историческое решение о четырёх evaluator-компонентах
не означает запрет других будущих AI-реализаций; их ввод требует отдельного решения.
При существенном противоречии источников фиксируйте его до зависимой реализации.

Открытые методологические вопросы перечислены в Registry. Работа, не зависящая
от них, может продолжаться. Эксперимент не становится утверждённой нормой.
