# Реестр архитектурных источников Product 4K

Обновлено: 2026-10-01. Этот реестр фиксирует применимость известных источников;
выбор комплекта текущей задачи задан Change 01; полнота локальных оригиналов
отмечена отдельно в task manifest.

Историческое уточнение владельца проекта 2026-09-29: версии всех этапов M ещё будут
корректироваться; задачи M6–M8 пока не внесены в проект. Упоминание этих этапов
в архитектуре описывает целевую ответственность, а не принятый объём реализации.
Наличие legacy-оценивания, shadow или отчётов не доказывает реализацию M6–M8.
Для текущей задачи применять выбранный ниже комплект без повторного запроса
актуальности M1; текущие runtime-пакеты не объявлять соответствующими ему автоматически. Правило неизменяемости уже опубликованной
версии сохраняется: корректировка оформляется новой версией.

## История первоначального включения M1 от 01.10.2026

Пользователь согласовал включение M1 v1.4 как зафиксированного источника и отдельный
аудит; публикация Sources → Registry → CURRENT → Manifest по M0 не выполнялась.
Этот локальный реестр не равен публикационному Registry M0 и не переключает CURRENT.
Заявленные в M1 статусы M5 v1.1, M6 v1.8, M7 v1.3 FROZEN и M8 v1.2 REVIEW не проверены
по отдельным исходникам. M1-14-01–04 закрыты в документе на уровне документного QA;
это не автоматическое закрытие OPEN-01/02 проекта или доказательство реализации.
На момент первоначального включения M8 был указан как REVIEW. Это историческое
состояние, заменённое для текущей задачи выбранным комплектом Change 01 ниже.

[Предварительный аудит](../../evc/m1-v1.4-gap-audit.md) различает подтверждённые
расхождения контрактов, существующие механизмы и пока не поставленную работу M6–M8.

## Действующий вход задачи по Change 01

Выбраны M0 v1.0, M1 v1.4, M2 K1/K3 v1.1 и K2/K4 v1.0, M3/M4 v1.0,
M5 v1.1, M6 v1.8, M7 v1.3, M8 v1.2 FROZEN; архитектурная поправка WORKING.
Подтверждение комплекта не доказывает наличие каждого файла, публикацию или runtime.
Точные доступные файлы/хеши и отсутствующие M0/M6/M7/M8 — в task manifest.
Исторические REVIEW в неизменяемых оригиналах сохраняются; не повторять общий
запрос актуальности M1/M4. Конкретный конфликт нормы предъявлять адресно.

M6–M8 теперь имеют [постановки первого эшелона](../../evc/tasks/change01-first-echelon.md),
а не реализованные модули. [Карта реализации](../../evc/change01-traceability.md)
требует доказательства правило → контракт/данные → код → проверка. Новые Cases
не блокируют технические контракты/fixtures; содержательная приёмка ждёт их QA/GC.
