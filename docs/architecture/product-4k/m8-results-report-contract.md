# M8 Results и базовый Report v1

Статус: `draft QA`, M8 v1.2 остаётся FROZEN, CURRENT не изменён. Контракт
реализует PM-06/PM-07 для одного закрытого Cycle и не вводит Recommendations,
Skill Level, CompetencyScore, Group или Longitudinal Report.

## Вход и идентичность

Producer принимает только Cycle в состоянии `calculated`, согласованные C-46/C-56
одного Cycle и точную revision расчёта. Проверяются ссылки расчёта, Cycle и
`composition_checksum`. Ошибка входа останавливает выпуск; отсутствие расчёта не
становится `no_result`.

На Cycle существует один логический Results. Каждая принятая revision расчёта
создаёт неизменяемую Results revision. Повтор одного idempotency key с тем же входом
возвращает прежнюю revision, с другим входом даёт `IDEMPOTENCY_CONFLICT`.

## Results и C-67

Results сохраняет точные C-46/C-56 refs, состав, профиль и роль, план и полный M2,
Sessions/AS, время, четыре исхода Skills, точные дроби Scores, полноту, пять
покрытий, Confidence, Reliability, ограничения и происхождение. Skills группируются
по Competency; поле Competency score всегда `null`.

C-67 — неизменяемая versioned projection выбранной Results revision. Представления
`assessee`, `customer`, `methodology_qa` различаются раскрытием, сохраняя одинаковые
факты и существенные ограничения. Шаблон `m8_basic_report/1.0.0` проверяется по
checksum и связан с M8 v1.2. `recommendations` всегда пуст.

TargetProfile сохраняется в Report отдельно от Results. Нет требования —
`NO_TARGET_REQUIREMENT`; нет результата — `NO_SKILL_RESULT`; при Target Level и
отсутствии нормативного фактического Skill Level — `NOT_COMPARABLE` с причиной
`NORMATIVE_SKILL_LEVEL_NOT_AVAILABLE`. Score не преобразуется в Level или Gap.

## Выдача и права

Admin API создаёт Results/C-67 и читает/экспортирует разрешённые представления.
Владелец Cycle читает только свой latest Results и `assessee` C-67; сервер повторно
проверяет владельца для прямой PDF-ссылки. Экран и PDF читают один сохранённый C-67.
PDF сохраняет revision, точные дроби, ноль, отсутствие значения, покрытия,
Reliability и ограничения; для кириллицы требуется Unicode font.

Создание остается явной авторизованной операцией. Автоматическое событие после
закрытия Cycle, retry worker и переход из основного прохождения относятся к Task 10.

## Хранение и восстановление

`m8_results` задаёт логическую идентичность; `m8_result_revisions` и `m8_reports`
неизменяемы trigger-ограничением; request keys хранят hash входа. Откат отключает
новые M8 routes/UI consumer. История C-46/C-56/Results/C-67 не удаляется и не
переписывается.

## Расширение Task 11: Recommendations

Report v1.1 добавляет Recommendations по M8.6–M8.6.1, не меняя фактический Results.
Пакет `m8_recommendations/1.0.0` детерминированно формирует три типа предложения
по существующему Skill Result и точной IA revision. Сохранённый C-67 содержит
версию контракта, механизм и checksum шаблона, минимизированный input и его checksum,
сформированный текст, статус и причину сбоя.

Контекст берётся только из allowlist содержательных полей PersonalizedProfile,
сохранённого в Results для данного Cycle. Текущие источники профиля, ФИО и контакты
не читаются. При `no_result` формируется пояснение недостатка оснований без вывода
о дефиците. `NOT_COMPARABLE` сохраняется. Экран и PDF показывают одну сохранённую
revision. Для текущего продуктового пути REPORT_01 произвольная
owner-регенерация удалена; повторная подготовка допускается только через
зафиксированную техническую ошибку и служебный M10 recovery.
[Реализация и проверки](../../evc/tasks/m8-task11-recommendations.md).

## REPORT-07: допуск сравнения двух сохранённых C-67

Проекция `m8-report-comparison/1.1.0` обратно совместима по существующим полям,
добавляет сохранённое имя программы в ссылки на оба Report. Применяется M8 v1.2
§7.3 к двум разным закрытым Cycle одного владельца. Таблица
проверяется **для каждого навыка/показателя**, по сохранённым C-67/Results, без
повторного M6 и без объединения Evidence. Отсутствующее обязательное поле означает
`not_confirmed`; равенство двух `null` не подтверждает сопоставимость.

| Основание | Проверяемый снимок | Допуск разности |
| --- | --- | --- |
| Смысл и версия Skill | `skills[].skill_id/code/name/description`, `provenance.sources` и сохранённый состав `presentation.required_indicator_ids` | Подтверждён тот же смысл и версия; одно название/число недостаточно. Иная версия без утверждённого mapping показывается раздельно. |
| Правила расчёта | `provenance.algorithm`, `provenance.sources`, `score`/`outcome` | Подтверждены одинаковые применённые правила M6 и числовой Score; `no_result` не ноль. |
| Обязательный и включённый состав | `presentation.required_indicator_ids` и `included_indicator_ids` каждого Skill | Оба набора сохранены и совпадают. Полный/частичный не смешиваются; два частичных допустимы только при одинаковом подтверждённом составе и условиях. |
| Достаточность/самостоятельность | Сохранённый `outcome`, `score`, `presentation` и ограничения | Оба результата допущены M6 как числовые; неполный Cycle сам по себе не запрещает полный показатель. Неизвестное основание — раздельное представление. |
| Роль и существенный контекст | Содержательные снимки `role_ref`, `profile_ref`; технические `id` исключаются из сравнения | При разном содержании или неполном снимке — раздельно с причиной. Совпадение одного технического ID не достаточно. `target_profile` для фактического Score не используется. |
| Время, возврат, известные ограничения | `provenance.comparison_evidence.assessment_conditions`, сохранённые `time`/`collection` и ограничения | Эффективные budget/window и checksum правила возврата подтверждены и совпадают; известное отличие условий или отсутствие обязательного подтверждения исключает разность. Даты различны и показываются как периоды, а не как равные условия. |

Разность есть арифметика двух уже опубликованных Scores, не процент роста, ступень
Skill Level или доказательство развития. Если условие не подтверждено, оба значения
остаются видимыми с адресной причиной. Техническая revision не является новым
прохождением. PDF использует тот же payload и пару `report_id`.
